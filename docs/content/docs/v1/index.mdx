A bad folder structure slows you down. You spend effort remembering where the related pieces live, and time hunting for them.

## The Problem: Layer-Based Architecture

Most Roblox projects split their code twice:

1. **By environment:** `server`, `client` and `shared` folders at the root.
2. **By type:** inside those, a folder per technical role, like `Controllers`, `Services` or `Utils`.

That looks tidy at first, but it doesn't scale. The folders keep growing, and related files end up far apart. To change the **Inventory** system, you dig through three big trees just to collect its pieces.

	**The cost:** context switching. Working on one feature means wading

</Callout>

## The Solution: Feature-Based Architecture

Keep all the code for one feature (client, server and shared) together in a single folder.

Rogen reads your folders and file names and sends every file to the Roblox service where it belongs. Your repository stays organized by feature, and Studio still gets every script in the right place.
