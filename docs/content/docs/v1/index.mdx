A bad folder structure slows you down. You spend your time remembering where the related pieces live, and then hunting for them.

## The Problem: Layer-Based Architecture

Most Roblox projects split their code twice:

1. **By environment:** `server`, `client` and `shared` folders at the root.
2. **By type:** inside those, a folder per technical role, like `Controllers`, `Services` or `Utils`.

It looks tidy at first, but it doesn't scale. The folders keep growing and related files drift further apart, until changing the **Inventory** system means digging through three big trees just to collect its pieces.

</Callout>

## The Solution: Feature-Based Architecture

Keep all the code for one feature (client, server and shared) together in a single folder, and let Rogen sort out the rest. It reads your folder and file names and sends every file to the Roblox service where it belongs.
