# Environments

You often write code that you do not want in your final game, such as unit tests, mock data, or development tools. Rogen filters files based on active environments.

## Using Environment Tags

You tell Rogen which environments are active via your `.rogen.json` file or the CLI. You then add environment tags to your file or folder names.

For example, appending `.dev` or `.spec` to a file:

- `InventoryService.spec.luau`
- `MathUtils.dev.luau`

When Rogen builds your tree, it checks your environment rules:

1. If a file or folder contains an **inactive** environment tag, Rogen drops it from the build.
2. If a file contains an **active** environment tag, Rogen keeps the file and strips the tag from the final script name.

This ensures your final `.project.json` remains clean and your live game stays optimized.

<Callout type="info">
	You configure active environments inside your `rogen.json` file using the
	`env` array under your specific mode (like `luau` or `ts`). See the
	**Configuration** section for details.
</Callout>
