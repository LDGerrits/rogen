title: Config
description: The keys Rogen adds to a Rojo project file.
---

A config, `default.rogen.json`, is a Rojo project file with three more keys. Rogen writes it, with your routed files added to the `tree`, to `default.project.json`. Edit the `.rogen.json`: `rogen write` overwrites the project file. Rojo's own keys work as [Rojo documents them](https://rojo.space/docs/v7/project-format/).

| Key | Default | What it does |
|---|---|---|
| `routes` | none | [Route keys](/docs/v2/core-concepts/routing) and their targets. |
| `sourcePaths` | `["src"]` | The folders Rogen reads. A later folder's file replaces an earlier one's at the same path. |
| `compiledPath` | none | Where a compiler such as roblox-ts or Darklua writes your code, for Rojo to sync from. |

A route key is letters and digits, starting with a letter, or `*` for the [fallback route](/docs/v2/core-concepts/routing#files-outside-every-route).

## Targets

A target starts with a service, such as `"ServerScriptService"`, and may add folders, such as `"ReplicatedStorage/Shared"`. Write `StarterPlayer/StarterPlayerScripts` in full, because Rogen doesn't know a service's children.

A second config, `X.rogen.json`, writes `X.project.json` and needs its own `name`.
