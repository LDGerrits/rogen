```bash
rogen [command] [name…] [options]
```

The first word is always the command, and a bare `rogen` runs `build`. Whatever follows is a config name, so `rogen build lobby` builds `lobby.rogen.json`. `rogen lobby` is an error, not a shortcut, and Rogen will suggest `rogen build lobby`.

## Commands

### `build [name…]`

Writes the project file for each named config, and is the default command. You can build several configs at once, as long as no two write the same file. `--all` builds every config in the folder.

`build` also lists any `*.rogen.json` you didn't ask for, which helps in a Darklua setup where it's easy to forget one of the two configs.

### `watch [name…]`

Builds, then rebuilds whenever files or configs change. Only names matter, so editing inside a script never triggers a rebuild.

A config reloads when it, its `extends` chain or its template changes, and CLI overrides carry over. If you save an invalid config, `watch` prints the error and keeps using the last valid version, so a broken `prod.rogen.json` doesn't hold up `default.rogen.json`.

```
┌  rogen watch · default, lobby
│
◇  12:04:31 · 2 files changed
│  ✔ default.project.json · wrote
│  ■ lobby.project.json · not written
│  ■ /repo/lobby.project.json - error: …
│
◇  12:05:02 · default.rogen.json changed · reloaded
│  ✔ default.project.json · unchanged
```

It's safe to run `build` while `watch` is running. Press Ctrl+C to stop.

### `where [path…]`

Shows where each file lands in the game and why, without writing anything:

```
$ rogen where src/Net src/Combat/Server/Hit.luau
src/Net/Http.luau -> ReplicatedStorage/Shared/Net/Http · route * (fallback)
src/Net/Http.mock.luau -> pruned · variant mock is off (suffix)
src/Net/Remotes@server.luau -> ServerScriptService/Net/Remotes · route Server (suffix)
src/Net/Types.lua -> replaced by src/Net/Types.luau
src/Combat/Server/Hit.luau -> ServerScriptService/Combat/Hit · route Server (folder)
```

A directory stands for the files inside it, and no path at all means every file in the tree. Since Rogen only reads names, the path doesn't have to exist yet, so you can check a file before you create it.

A placed file shows its instance path, the governing route, how it matched (`folder`, `marker`, `suffix` or `fallback`) and any active variants. Otherwise the line says why it isn't placed: `pruned`, `replaced by` another file, `displaced` by a template node, `mounted` by a template `$path`, `unrouted`, `excluded` (with the glob), or `outside the root dirs`.

`where` also works backwards. An argument that starts with a service is read as an instance, and you can paste an error line straight in:

```
$ rogen where "ServerScriptService.Combat.Hit:12: attempt to index nil"
src/Combat/Server/Hit.luau -> ServerScriptService/Combat/Hit · route Server (folder)
```

Unlike other commands, `where` takes paths, not config names. It reads the default config unless you pass `-c` or `--all`, and accepts `--variant`, `--no-variant` and `--json`.

### `init [name]`

Writes a starting `<name>.rogen.json` (or `default.rogen.json`). It detects the language, Darklua and your package manager, and writes what it found into the config. This is the only time Rogen detects anything; builds just do what the config says.

In a terminal it asks a few questions, and Enter gives you the default each time. With an existing `default.rogen.json`, it offers to add a place, a config that extends default, or a separate config. Without a terminal, or with `--json`, it takes the defaults, so `rogen init lobby` adds a place in `places/lobby`.

`init` never overwrites a file. If a hand-written project file is in the way, it's copied to `template.project.json` first. When it's done, `init` prints what to run next.

### `list [name…]`

Lists every config in the folder with its root directories, sync directory, project file and active variants. It's the quickest answer to "what can this repo build?". With `--json`, each config is printed fully resolved, which is handy for following an `extends` chain.

### `help [command]` and `version`

Print usage and the installed version.

## Options

An override changes a config value for one run. Anything you want every time belongs in the file. `where` and `list` only take `--all`, `-c`, `--variant` and `--no-variant`.

| Flag | Effect |
|---|---|
| `--all` | Every `*.rogen.json` in the folder. Can't be combined with names or `-c`. |
| `-c, --config <path>` | A config file by path. Repeatable. |
| `-o, --out-file <path>` | Overrides `outFile`. |
| `-s, --sync-dir <path>` | Overrides `syncDir`. |
| `--template <path>` | Overrides `template`. |
| `--variant <name>` | Turns a variant on. Repeatable. |
| `--no-variant <name>` | Turns a variant off. Repeatable. |
| `--json` | Prints one JSON document for `build`, `where`, `list` and `init`. |
| `-h, --help` | Prints help. |
| `-v, --version` | Prints the version. |
| `--verbose` | Prints debug output. |
| `-q, --quiet` | Prints errors only, plus anything you explicitly asked for. |
| `--no-input` | Never asks questions, and prints plain lines. |

`-o`, `-s` and `--template` change a single config, so you can't use them when building several. A variant flag applies to every config that declares the variant, and is only an error if none do.

## JSON output

`--json` prints exactly one JSON document on stdout, even when the command fails or the command line itself is wrong. The exit code is unchanged. File paths are absolute and use the OS separator; instance paths and globs always use `/`.

Diagnostics look like this. Match on `code`, since the wording of `message` can change. `line` and `column` are omitted when the problem is a whole file.

```json
{
	"file": "/repo/default.rogen.json",
	"line": 3,
	"column": 2,
	"severity": "error",
	"code": "config.unknownField",
	"message": "unknown field \"outDir\"."
}
```

If a command fails before it has anything else to report, you get `{ "diagnostics": [...] }`, or `{ "error": "..." }` for anything that isn't a diagnostic.

### `build --json`

```json
{
	"configs": [
		{
			"file": "/repo/default.rogen.json",
			"outFile": "/repo/default.project.json",
			"outcome": "wrote",
			"diagnostics": []
		}
	],
	"notBuilding": ["/repo/lobby.rogen.json"]
}
```

`outcome` is `wrote`, `unchanged` or `notWritten`. If any config fails, nothing is written. `notBuilding` lists the configs you didn't ask for.

### `where --json`

An array with one entry per config and path, each with `config`, `status` and `source`, plus:

| `status` | Fields |
|---|---|
| `placed` | `instancePath` (an array of names), `route`, `routeMatch`, `variants` |
| `pruned` | `variants`, the dormant ones |
| `replaced` | `by`, the file that took its instance path |
| `displaced` | `node`, the template node's path |
| `mounted` | `node`, the template node whose `$path` mounts it |
| `excluded` | `pattern`, the glob that matched |
| `unrouted`, `outside`, `ignored`, `missing`, `empty`, `skipped` | none |
| `noFile` | `instance` instead of `source`: no file places an instance you asked about |

`routeMatch` is `folder`, `marker`, `suffix` or `fallback`. Each `variants` entry looks like `{ "variant": "mock", "form": "suffix" }`.

### `init --json`

```json
{
	"files": ["/repo/lobby.rogen.json", "/repo/tsconfig.lobby.json"],
	"notes": [],
	"nextSteps": {
		"setup": ["Add \"include\": [\"src\"] to tsconfig.json, so its own build leaves out the place folders."],
		"run": ["rbxtsc -w -p tsconfig.lobby.json --rojo lobby.project.json", "rogen watch lobby", "rojo serve lobby.project.json"],
		"darklua": [],
		"edits": ["Declare variants under \"variants\" in lobby.rogen.json to swap in files like Analytics.mock.ts."]
	}
}
```

`files` lists what was written, in order, and `notes` what `init` said along the way. In `nextSteps`, `setup` holds one-time edits, `run` the long-running commands (one terminal each), `darklua` the processing commands, and `edits` suggested changes to the new files. If a write fails, you get `{ "files": [...], "error": "..." }`.

### `list --json`

An object keyed by each config's absolute path. Every value has `extends` (nearest parent first) and `diagnostics`. Configs that resolved also have `name`, `rootDirs`, `commonRoot`, `routes`, `variants`, `exclude`, `template`, `syncDir` and `outFile`, with `null` for anything unset. If any config has errors, the exit code is 1.

## Output

In a terminal, Rogen draws a framed layout. In CI, pipes and redirects, or with `--no-input`, `TERM=dumb` or a truthy `CI` variable, it prints plain lines and never asks questions. Use `--no-input` when a tool runs Rogen in a pseudo-terminal.

Diagnostics use the familiar `file:line:col - severity: message` shape, so editors and CI can parse them. A failed command exits with 1.
