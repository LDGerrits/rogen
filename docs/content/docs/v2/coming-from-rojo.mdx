---
title: Coming from Rojo
description: Move a Rojo project to Rogen, then sort it by feature
---

Use Rogen when you want each feature's server, client and shared code in one folder. If your folders already match Roblox's services and you don't mind writing the tree by hand, Rojo alone does the job. Rogen runs Rojo underneath, so Rojo's keys and flags keep their meaning.

## Run `rogen init`

In the folder that holds `default.project.json`, run `rogen init`. It moves no files, and writes your project file as `default.rogen.json`. For the project that `rojo init` makes:

```json title="default.rogen.json"
{
	"name": "my-game",
	"sourcePaths": ["src"],
	"routes": {
		"Shared": "ReplicatedStorage/Shared",
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"*": "ReplicatedStorage/Shared"
	},
	"tree": {
		"$className": "DataModel",
		"ReplicatedStorage": {},
		"ServerScriptService": {
			"Server": { "$path": "src/server" }
		},
		"StarterPlayer": {
			"StarterPlayerScripts": {
				"Client": { "$path": "src/client" }
			}
		}
	}
}
```

`src/shared` becomes a route, and every file lands where Rojo put it, so your requires still work.

From now on, edit `default.rogen.json`. `rogen write` replaces `default.project.json`, so stop tracking it: add `*.project.json` to `.gitignore` and run `git rm --cached default.project.json`.

## Sort by Feature

Then move code into [feature folders](/docs/v2/core-concepts/routing/folders):

```bash
git mv src/server/Services/InventoryService.luau src/Inventory/Server/
git mv src/client/Controllers/InventoryController.luau src/Inventory/Client/
git mv src/shared/Types/InventoryTypes.luau src/Inventory/Shared/
```

Moving a file changes its path in the game, so update the requires that reach it. `rogen where` on a module prints its require. Old folders and feature folders work side by side, so you can move one feature at a time.
