---
title: Coming from Rojo
description: Move a Rojo project to Rogen
---

This guide is being rewritten for Rogen 2. Until it's back, run `rogen init` in your Rojo project: it lifts your `default.project.json` into a `default.rogen.json` and keeps your tree. Its source path is the closest folder that holds every folder of code the project file mounts: `code` for `code/server` and `code/client`. Each of those folders becomes a route. Folders that the project file mounts from the top of the project, such as `server/` and `shared/`, stay mounted in the tree, and `init` says so. If code is outside the source path and the tree, `init` warns with [`init.codeOutsideSourcePaths`](/docs/v2/diagnostics#init-codeoutsidesourcepaths). From then on, `rogen write` writes `default.project.json` from `default.rogen.json`, so make your changes in `default.rogen.json`. If the project file mounts a folder that Darklua writes, such as `build`, and `.darklua.json` is beside it, `default.rogen.json` reads your source and a `dist.rogen.json` reads that folder as its `compiledPath`. Serve it with `rogen serve dist`.
