---
title: Coming from Rojo
description: Move a Rojo project to Rogen, then sort it by feature
---

Use Rogen when you want each feature's server, client and shared code in one folder. If your folders already match Roblox's services and you don't mind writing the tree by hand, Rojo alone does the job. Rogen runs Rojo underneath, so Rojo's keys and flags keep their meaning.

## Run `rogen init`

In the folder that holds `default.project.json`, run `rogen init`. It moves no files. It lifts the project file into `default.rogen.json` and keeps your tree. For the project that `rojo init` makes, it writes:

```json title="default.rogen.json"
{
	"name": "my-game",
	"sourcePaths": ["src"],
	"routes": {
		"Shared": "ReplicatedStorage/Shared",
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"*": "ReplicatedStorage/Shared"
	},
	"tree": {
		"$className": "DataModel",
		"ReplicatedStorage": {},
		"ServerScriptService": {
			"Server": { "$path": "src/server" }
		},
		"StarterPlayer": {
			"StarterPlayerScripts": {
				"Client": { "$path": "src/client" }
			}
		}
	}
}
```

The rest of the tree, such as `Workspace` and `Lighting`, stays as it was. `src/shared` becomes the `Shared` route. `src/server` and `src/client` hold an init script, which Rojo reads as the folder's own instance and a route can't, so they stay `$path` mounts. A mounted folder without one becomes a route to its node instead, such as `"Server": "ServerScriptService/Server"`.

Every file lands where Rojo put it, so your requires still work. A file in `src` that no node mounted stays out of the game: `init` lists it, or its folder, under `globIgnorePaths`. From now on, `rogen write` replaces `default.project.json`, so make your changes in `default.rogen.json`. Stop tracking the project file: add `*.project.json` to `.gitignore` if `init` didn't (it does when it creates the `.gitignore`), then, if git tracks it, run `git rm --cached default.project.json`.

## Sort by Feature

Next, move the code into [feature folders](/docs/v2/core-concepts/routing/folders), one feature at a time:

```bash
git mv src/server/Services/InventoryService.luau src/Inventory/Server/
git mv src/client/Controllers/InventoryController.luau src/Inventory/Client/
git mv src/shared/Types/InventoryTypes.luau src/Inventory/Shared/
```

Moving a file changes its instance path. Rogen doesn't check requires, so update the ones that reach the feature. `rogen where` on a module prints the require that reaches it. Old folders and feature folders build side by side, so the game works between moves.
