---
title: Diagnostics
description: Every error and warning Rogen reports, why it fires and how to fix it.
---

Every diagnostic has a stable code, such as `route.strayAt`. The terminal prints it as `file:line:col - severity: message (code)`, and `--json` adds a `url` pointing at its section on this page and, for some warnings, the `fixes` that resolve it. `rogen help <code>` prints a code's section from the version you have installed, offline.

An error stops every config in the run from being written. A warning never does, but it always names something to fix.

## Config

### `config.unreadable` [#config-unreadable]

Error. The config file isn't there, or is there but Rogen couldn't read it from disk. A missing file says where Rogen looked, and an unreadable one says why.

```
rogen.json - error: the config does not exist (looked for rogen.json). (config.unreadable)
rogen.json - error: the config could not be read: permission denied. (config.unreadable)
```

Fix the path or the file's permissions, or check that it's a file and not a folder. See [Configuration](/docs/v2/configuration).

### `config.invalidSyntax` [#config-invalidsyntax]

Error. The config isn't valid JSONC. Comments and trailing commas are fine, but brackets and quotes have to match.

```
rogen.json:4:1 - error: invalid JSONC: expected '}'. (config.invalidSyntax)
```

Fix the syntax at the line and column shown. See [Configuration](/docs/v2/configuration).

### `config.notAnObject` [#config-notanobject]

Error. The config holds a JSON value that isn't an object, such as an array or a string.

```
rogen.json:1:1 - error: a config must be a JSON object. (config.notAnObject)
```

Wrap the fields in `{ }`. See [Configuration](/docs/v2/configuration#fields).

### `config.wrongType` [#config-wrongtype]

Error. A field holds the wrong kind of value, such as a string where `sourcePaths` needs an array.

```
rogen.json:2:14 - error: "sourcePaths": expected an array, found a string. (config.wrongType)
```

Give the field the type the message names. `null` is never a value in a `rogen.json`, and it removes nothing: leave the key out, or in a project, ignore the folder a mount points at with `globIgnorePaths`. A node of the `tree` must be an object, so `"DevPackages": null` there gets the same error. See [Configuration](/docs/v2/configuration#fields).

### `config.unknownField` [#config-unknownfield]

Warning. The config has a key that is neither one of Rojo's nor one of Rogen's, often a typo or a key from Rogen 1. Rogen passes it through to the project file it writes, and Rojo refuses a project file with a key it doesn't know, so the file fails to load there.

```
rogen.json:4:2 - warning: "exlude" is not a Rojo key and not Rogen's: it is passed through, and Rojo will reject the written file by this name. Did you mean "exclude"? (config.unknownField)
```

A field of a sync rule that a rule does not have gets the same warning, since Rojo ignores it and the rule then reads differently from what was meant. Rename the key to the one suggested, or remove it. A config with v1 keys also gets [`legacy.config`](#legacy-config). See [Configuration](/docs/v2/configuration#fields).

### `config.removedField` [#config-removedfield]

Error. The config has a key that Rogen removed or renamed. The error is at the key, and the message says what to do instead.

```
rogen.json:4:2 - error: "modes" was removed. Put what a mode set in a project under "projects", which is written beside default.project.json as <name>.project.json. (config.removedField)
rogen.json:5:2 - error: "extends" was removed. A rogen.json describes one folder. A second output is a project under "projects", which changes the keys it needs, or a rogen.json in another folder. (config.removedField)
rogen.json:6:2 - error: "exclude" was removed. "globIgnorePaths" keeps files out of routing, leaves out a mount of the tree that it ignores, and Rogen writes it for Rojo. (config.removedField)
```

Remove the key and do what the message says. `rootDirs` is now `sourcePaths` and `syncDir` is `syncPath`. `template` is gone: write its `tree` and its other keys in `rogen.json`. `outFile` is gone: Rogen writes `default.project.json` beside `rogen.json`. `exclude` is `globIgnorePaths`, which also leaves out a mount it ignores. `extends` and `modes` are gone: a `rogen.json` describes one folder, and a project under `projects` changes what a second output needs. For `variants`, a file that replaces another goes in a later source path, which wins a clash. For `server`, `rogen serve` starts Rojo, and serving with Argon is described in [Studio](/docs/v2/studio#serve-with-argon). See [Configuration](/docs/v2/configuration#removed-keys) and [Replacing a File](/docs/v2/core-concepts/project-layout#replacing-a-file).

### `config.duplicateSourcePath` [#config-duplicatesourcepath]

Error. One folder appears twice in `sourcePaths`, so every file in it would belong to both entries.

```
rogen.json:4:3 - error: source path "src" is listed twice; a file under it would belong to both. Remove one. (config.duplicateSourcePath)
```

Remove one entry. See [Several Source Paths](/docs/v2/core-concepts/project-layout#several-source-paths).

### `config.nestedSourcePath` [#config-nestedsourcepath]

Error. One source path sits inside another, so the files in it would belong to both.

```
rogen.json:4:3 - error: source path "src/shared" is inside source path "src"; a file under it would belong to both. Remove one. (config.nestedSourcePath)
```

Remove the inner one, or move it out of the outer one. See [Several Source Paths](/docs/v2/core-concepts/project-layout#several-source-paths).

### `config.syncPathOverlapsSourcePath` [#config-syncpathoverlapssourcepath]

Error. The sync path is a source path, lies inside one, or contains one. The sync path is where Darklua or a compiler writes the code the source paths hold, so Rogen would read that output as source and write the project file from it.

```
rogen.json:4:14 - error: the sync path "/repo/src/out" is inside source path "/repo/src", so Rogen would read what the tools write as source. Set "syncPath" to a folder outside the source paths. (config.syncPathOverlapsSourcePath)
```

Set `syncPath` to a folder beside the source paths, such as `dist` or `out`. See [Darklua](/docs/v2/setups/darklua).

### `config.sourcePathsWithoutRoutes` [#config-sourcepathswithoutroutes]

Error. The config lists `sourcePaths` but declares no `routes`. Source paths are what routes scan, and without routes nothing is routed and no source path is scanned.

```
rogen.json:3:3 - error: "sourcePaths" lists what routes scan, but the config declares no routes. Add "routes", or remove "sourcePaths". (config.sourcePathsWithoutRoutes)
```

Add a `routes` map, or remove `sourcePaths` and mount the folders in the `tree` with `$path`. `rogen init` writes `server`, `client`, `shared` and `*`. See [Routing](/docs/v2/core-concepts/routing).

### `config.invalidSyncRule` [#config-invalidsyncrule]

Error. A rule in `syncRules` is not one Rojo can read: it is not an object, it has no `pattern` or `use`, its `use` is not one Rojo has, or its `exclude` or `suffix` is not a string.

```
rogen.json:7:5 - error: "syncRules[0]": a sync rule needs a "use" of serverScript, clientScript, ... (config.invalidSyncRule)
```

Fix the rule as the message says. See [Configuration](/docs/v2/configuration#sync-rules).

### `config.invalidRouteKey` [#config-invalidroutekey]

Error. A route key has characters other than letters and digits, or starts with a digit. Keys appear in folder and file names, so they have to match exactly.

```
rogen.json:6:14 - error: route key "ser-ver" is invalid: use letters and digits only, starting with a letter. (config.invalidRouteKey)
```

Rename the key, for example `server`. See [Routing](/docs/v2/core-concepts/routing).

### `config.ambiguousKey` [#config-ambiguouskey]

Error. Two declared keys differ only in the case of their first letter. A name matches a key with its first letter in either case, so both would match the same folders.

```
rogen.json:7:13 - error: "Server" and "server" differ only in the case of their first letter, so both would match the same names; keep one of them. (config.ambiguousKey)
```

Keep one of them. See [Matching](/docs/v2/core-concepts/routing#matching).

### `config.reservedProject` [#config-reservedproject]

Error. A key of `projects` is `default`. That name stands for the description itself, which Rogen writes as `default.project.json`, so no project can take it.

```
rogen.json:5:5 - error: "default" is the description itself, written as default.project.json, so it can't name a project. Pick another name. (config.reservedProject)
```

Rename the project, or move its keys to the root of `rogen.json`. See [Projects](/docs/v2/configuration#projects).

### `config.invalidProjectName` [#config-invalidprojectname]

Error. A key of `projects` can't be the stem of a project file. The name becomes `<name>.project.json`, so it takes letters, digits, `-` and `_`, and starts with a letter or digit.

```
rogen.json:5:5 - error: project name "a/b" is invalid: it is the stem of a/b.project.json, so use letters, digits, "-" and "_", starting with a letter or digit. (config.invalidProjectName)
```

Rename the project, for example `dist` or `release`. See [Projects](/docs/v2/configuration#projects).

### `config.ambiguousProject` [#config-ambiguousproject]

Error. Two keys of `projects` differ only in letter case. On Windows and macOS file names ignore case, so both would write the same project file, and the second would overwrite the first.

```
rogen.json:7:5 - error: "Dist" and "dist" differ only in letter case, so on Windows and macOS both would write the same project file. Keep one of them. (config.ambiguousProject)
```

Keep one of them. A spelling of `default` in another case is [`config.reservedProject`](#config-reservedproject) for the same reason. See [Projects](/docs/v2/configuration#projects).

### `config.projectKey` [#config-projectkey]

Error. A project sets `projects` or `serveProject`. Those say which projects there are and which one `rogen serve` serves, so they belong to the whole config.

```
rogen.json:6:7 - error: "serveProject" is set once for the whole config, not by a project. Move it out of "dist". (config.projectKey)
```

Move the key to the root of `rogen.json`. See [Projects](/docs/v2/configuration#projects).

### `config.placeListsPlaces` [#config-placelistsplaces]

Error. A place's own `rogen.json` sets `placePaths`. A place is a folder that another config lists, and places don't nest.

```
places/lobby/rogen.json:2:3 - error: a place can't list places: "placePaths" belongs to the config that lists this folder. Remove it. (config.placeListsPlaces)
```

Remove the key from the place. See [Places](/docs/v2/configuration#places).

### `config.placeSetting` [#config-placesetting]

Error. A `rogen.json` whose `placePaths` match a folder sets `servePort`, `servePlaceIds`, `blockedPlaceIds`, `placeId` or `gameId`, in the config or in one of its projects. Each place is served on its own and is its own place in Studio, and the config that lists them is never served, so no place takes these from it.

```
rogen.json:3:3 - error: "servePort" is set by each place, since a config that lists places is never served. Move it to the rogen.json of each place. (config.placeSetting)
```

Move the key into the `rogen.json` of each place it belongs to. See [Places](/docs/v2/configuration#places).

### `config.placeInSourcePath` [#config-placeinsourcepath]

Error. A place lies inside one of the source paths of the config that lists it, or one of those source paths lies inside a place. Both would read the same files: the config as its own, and the place as its own again.

```
rogen.json:3:3 - error: the place /repo/src/places/lobby is inside the source path /repo/src, so its files would belong to both. Move the place out of the source path, or the source path out of the place. (config.placeInSourcePath)
```

Move the places out of the source paths, for example to `places/*` beside `src`, or the source path out of the place. See [Places](/docs/v2/configuration#places).

### `config.unknownServeProject` [#config-unknownserveproject]

Error. `serveProject` names a project that doesn't exist. It takes `default`, or a key of `projects`.

```
rogen.json:4:19 - error: "serveProject" names "dist", which is not a project. Use "default", "release". (config.unknownServeProject)
```

Fix the name, or add the project. See [Projects](/docs/v2/configuration#projects).

## Routes

### `roblox.unsupportedService` [#roblox-unsupportedservice]

Error. A route's target doesn't start with a Roblox service Rojo can write to.

```
rogen.json:7:13 - error: "StarterPlayerScripts" is not a supported service. Did you mean "StarterPlayer/StarterPlayerScripts"? (roblox.unsupportedService)
```

Start the target with a service, then any folders: `"StarterPlayer/StarterPlayerScripts"`, `"ReplicatedStorage/Shared"`. See [Targets](/docs/v2/core-concepts/routing#targets).

### `roblox.invalidFolder` [#roblox-invalidfolder]

Error. A route's target has a folder with no name, `.` or `..`, which would make an instance of that name.

```
rogen.json:7:13 - error: the target "ServerScriptService/" has an empty folder name; write each folder between single slashes, such as "ServerScriptService/Folder". (roblox.invalidFolder)
```

Remove the extra slash, or name the folder. See [Targets](/docs/v2/core-concepts/routing#targets).

### `route.unrouted` [#route-unrouted]

Warning. No route matches the file and there's no `*` route, so it's left out of the project file.

```
src/Util.luau - warning: matched no route, so it is left out. Add a "*" route, or move it into a routing folder. (route.unrouted)
```

Move the file into a routing folder, give it an `@key` suffix, or declare a `"*"` route. See [Files That Match No Route](/docs/v2/core-concepts/routing#files-that-match-no-route).

### `route.strayAt` [#route-strayat]

Warning. A name, folder or marker file has an `@` that doesn't route, so the `@` stays in the instance name. Either it nearly spells a declared route key (a typo or a wrong case), or it spells one but isn't at the end of the name (`Report@server.bak.luau`). One warning lists every such name. An `@` that is nowhere near a route key, as in a package name like `@rbxts`, isn't reported.

```
rogen.json - warning: 2 names have an "@" that routes nowhere, so they are read as ordinary names: (route.strayAt)
  src/Inventory/Load@SERVER.luau (did you mean "@server"?)
  src/Inventory/Report@server.bak.luau ("@server" must end the name)
```

Rename the file to the spelling suggested, or move the `@key` to the end of the name. In `--json`, `fixes` holds the rename when exactly one key is closest. See [The `@` Sign](/docs/v2/core-concepts/routing#the--sign).

### `route.dotRoute` [#route-dotroute]

Warning. A route key is written after a dot, where only `@` routes, so it routes nothing: a dot-file like `.server`, which isn't a marker, a dot-folder like `.server/`, which isn't a routing folder, or a dot part of a name like `Types.shared.luau` or `Net.server/`, which stays in the name. What it names falls through to the route above it, or `*`. The key matches in any letter case, so `.SERVER/` and `Types.SHARED.luau` warn too. Rojo's `.server` and `.client` at the end of a script still route and are never reported, but only in lower case (Rojo reads `Boot.Server.luau` as a ModuleScript named `Boot.Server`, so Rogen suggests `Boot.server.luau`), and only on a script: a data file or model has no script class, so `Config.server.json` is named `Config.server` and warns. One warning lists every such name.

```
rogen.json - warning: 2 names write a route key after a dot, where only "@" routes, so they route nothing: (route.dotRoute)
  src/Inventory/.server (write "@server")
  src/Inventory/Types.shared.luau (write "Types@shared.luau")
```

Rename each to its `@` form: a marker file is `@server`, a folder `@server/`, and a name `Types@shared.luau` or `Config@server.json`. In `--json`, `fixes` holds every rename. See [Marker Files](/docs/v2/core-concepts/routing#marker-files).

### `route.folderTypo` [#route-foldertypo]

Warning. A folder is named one edit away from a declared route key, such as `Sever/` next to `Server`, so it's read as an ordinary folder and its files fall through to the route above it or `*`. The edit can be a letter added, dropped or changed, or two neighbours swapped (`Sevrer/`). A plural counts too: `Servers/` reads as an ordinary folder, so it warns; rename it if its files belong under the route. The folder's name is read with its parentheses and `^` off. Only keys of four letters or more are offered, since shorter ones are one edit from real words, and a name that matches a key in any letter case is `route.caseMismatch` instead. One warning lists every such folder.

```
rogen.json - warning: 1 folder is one edit from a declared route key, so it is read as an ordinary folder: (route.folderTypo)
  src/Inventory/Sever (did you mean "Server"?)
Rename a folder to the route key if it should route; a folder named as it is stays an ordinary folder.
```

Rename the folder to the key suggested, or, when the key in your config is the typo, fix it in `routes`. In `--json`, `fixes` holds the rename when exactly one key is closest. See [Routing Folders](/docs/v2/core-concepts/routing).

### `route.markerClash` [#route-markerclash]

Error. Two marker files in one folder name different routes, such as `@server` beside `@client`. An init script's route suffix counts as a marker, so `@server` beside `init@client.luau` clashes too. Both sit at the same level, so nothing decides which one governs. The same route twice is fine.

```
src/Inventory - error: "@client" and "@server" route this folder to different places, and nothing decides between them. Keep one. (route.markerClash)
```

Delete the marker you don't want, or move part of the folder into a subfolder with its own marker. See [Marker Files](/docs/v2/core-concepts/routing#marker-files).

### `route.ignoredAt` [#route-ignoredat]

Error. A name or marker file has an `@key` inside a folder that another route already governs, or before another `@key` in the same name (`Net@client@server/`). Only the outermost route acts, and in one name only the last `@key` routes, so this one does nothing, while the name says the file goes somewhere it doesn't.

```
src/server/Util@client.luau - error: "@client" does nothing here, because the "server" route already governs this file. Remove it, or move the file out of the "server" route's files. (route.ignoredAt)
```

Remove the `@key`, or move the file out of the governing route's folder. There's no automatic fix, since which one is right depends on where the code should run. An `@` that restates the governing route, like `Shared/Net/Remote@shared.luau`, is fine. A file that another file replaces is reported too, since its name is wrong either way. See [The Governing Route](/docs/v2/core-concepts/routing#the-governing-route).

### `route.caseMismatch` [#route-casemismatch]

Warning. A folder or marker matches a declared key except for letter case beyond the first letter, so it's read as an ordinary name.

```
src/SHARED - warning: differs from the route "shared" only in letter case, so it is read as an ordinary name. Spell it "shared" or "Shared", or declare it as written. (route.caseMismatch)
```

Rename it to the key, or declare it as written if it's meant to route. `SHARED/` may also just be a folder name, so there's no automatic fix. See [Matching](/docs/v2/core-concepts/routing#matching).

### `route.serverCodeShipped` [#route-servercodeshipped]

Warning. A file sits in a plain folder named after a server route, such as `Server/` or `(Server)/`, that an outer route outranks, so the outer route, which replicates to clients, places it. Server code under `Shared/` ships to every client.

```
rogen.json - warning: 1 file under a "server" route ships to clients, because "shared" governs it: (route.serverCodeShipped)
  src/Shared/(Server)/Datastore.luau -> ReplicatedStorage/shared/Datastore
Move it out of the "shared" route's files if it's server code, or keep it there with a "@shared" marker file in its folder.
```

Move the file out of the replicating route's folder, for example from `Shared/Server/` to `Server/`. If the folder is meant to replicate, put a marker file that restates the governing route in it, such as `Shared/Server/@shared`: it covers every file below it. `Secret@shared.luau` covers just that file. A route written with `@`, like `Shared/Data@server.luau`, is the [`route.ignoredAt`](#route-ignoredat) error instead. See [Server Code Under a Replicating Route](/docs/v2/core-concepts/routing#server-code-under-a-replicating-route).

## Tree

### `tree.reservedName` [#tree-reservedname]

Warning. The project file gets an instance whose key starts with `$`, which Rojo reserves for its own fields. Rojo keeps the instance but warns of it on every build and serve.

```
src/$Config.luau - warning: the project file gets the instance "ReplicatedStorage/shared/$Config", and Rojo reserves a leading $ for its own fields, so it warns of it on every build. Rename the file without the $. (tree.reservedName)
```

Rename the file or folder without the `$`. A `$` inside a name, as in `Cost$`, is fine, and so is a file inside a folder that Rogen gives to Rojo whole as one `$path`.

### `tree.instanceClash` [#tree-instanceclash]

Warning. Two files in one source path become the same instance, such as `Types.lua` and `Types.luau`. The last one takes the instance and the other is left out. Across source paths the last one wins without a warning: that is how a file is [replaced](/docs/v2/core-concepts/project-layout#replacing-a-file).

```
src/Inventory/Types.lua - warning: becomes "ReplicatedStorage/shared/Inventory/Types", as src/Inventory/Types.luau does, which takes its place. Rename one of them to keep both. (tree.instanceClash)
```

Rename or delete one of them. `rogen where` shows the left-out file as `replaced by`. See [Replacing a File](/docs/v2/core-concepts/project-layout#replacing-a-file).

### `tree.nodeClash` [#tree-nodeclash]

Warning. The `tree` defines a node at the same instance path as a file or folder, so the tree's node is kept and the file is left out.

```
src/Save.server.luau - warning: the tree defines "ServerScriptService/Save" too, so its node is kept and this file is left out. Rename one of them to keep both. (tree.nodeClash)
```

Rename the file, or remove the node from the `tree`. See [Configuration](/docs/v2/configuration#tree).

### `tree.initWithoutFolder` [#tree-initwithoutfolder]

Error. An init script becomes the folder it sits in, but that folder never becomes an instance. That's a source path, a plain routing folder or an invisible folder.

```
src/server/init.server.luau - error: an init script becomes the folder it sits in, but it sits in a routing folder, which never becomes an instance. Move it into a folder of its own, or rename it. (tree.initWithoutFolder)
```

Move the script into a folder of its own, or rename it so it isn't an init script. See [Init Folders](/docs/v2/core-concepts/project-layout#init-folders).

### `tree.hoistedInit` [#tree-hoistedinit]

Error. An init script's name starts with `^`. The script is its folder, so it can't be hoisted on its own; the folder can.

```
src/Net - error: ^init.luau starts with "^", but an init script is its folder, so the "^" can't hoist it alone. Put the "^" on the folder: ^Net. (tree.hoistedInit)
```

Rename the script back to `init.luau` and the folder to `^Net`. See [Hoisted Names](/docs/v2/core-concepts/routing#hoisted-names).

### `tree.deadScript` [#tree-deadscript]

Warning. A Script or LocalScript lands in a service where Roblox never runs it, such as a LocalScript in `ServerScriptService`. One warning lists every such script.

```
rogen.json - warning: 1 script will never run where it lands: (tree.deadScript)
  src/Shared/Secret.server.luau -> ReplicatedStorage/shared/Secret (a Script, placed by the "shared" route)
A Script runs in ServerScriptService or Workspace, and a LocalScript in StarterPlayerScripts, StarterCharacterScripts, StarterGui, StarterPack or ReplicatedFirst. A Script with RunContext Client never runs in ServerScriptService, which clients can't see.
```

Move the script under a route whose target runs it, or drop `.server`/`.client` to make it a ModuleScript. See [Scripts That Never Run](/docs/v2/core-concepts/routing#scripts-that-never-run).

### `tree.runContextTarget` [#tree-runcontexttarget]

Warning. The config sets `emitLegacyScripts: false`, and a route puts an `init.client` script in `StarterPlayerScripts` or `StarterCharacterScripts`. Rogen keeps the other `.client` scripts there LocalScripts with a sync rule, but Rojo reads an init script without rules, so this one is a Script with RunContext Client.

```
rogen.json - warning: emitLegacyScripts: false makes an init script in StarterPlayerScripts or StarterCharacterScripts a Script with RunContext Client, because Rojo reads init scripts without sync rules: (tree.runContextTarget)
  src/Panel/init.client.luau -> StarterPlayer/StarterPlayerScripts/Panel
Route the folder to another service, or remove emitLegacyScripts from the config.
```

Route the folder to a service such as `ReplicatedStorage` with RunContext Client, or remove `emitLegacyScripts` from `rogen.json`. See [Configuration](/docs/v2/configuration#fields).

### `tree.mountsSourcePath` [#tree-mountssourcepath]

Error. A `$path` in the `tree` mounts a source path, or a folder that holds one, so Rojo would read the whole folder and Rogen could place nothing in it.

```
rogen.json - error: "ReplicatedStorage/All" mounts the source path src, so Rojo would read all of it and Rogen would place nothing there. Mount a folder inside the source path, or remove the source path from "sourcePaths". (tree.mountsSourcePath)
```

Mount a folder inside the source path, such as a vendored package, or remove the source path from `sourcePaths`. See [Configuration](/docs/v2/configuration#tree).

### `tree.rootNotDataModel` [#tree-rootnotdatamodel]

Error. The config declares `routes`, but the root of its `tree` isn't a DataModel. A route target names a service, which only a DataModel holds. A root with a `$path` instead of a `$className` is not a DataModel either.

```
rogen.json:3:3 - error: routes name services, but the root of the tree is a Folder, not a DataModel. Give it "$className": "DataModel", or remove the routes. (tree.rootNotDataModel)
```

Give the root `"$className": "DataModel"`, or remove the routes if the project is a model. Without routes any root is valid. See [Configuration](/docs/v2/configuration#tree).

## Metadata

### `meta.unreadable` [#meta-unreadable]

Error. A `.meta.json` file was found when Rogen scanned but couldn't be read from disk: it lacks the permissions, is a folder, or was removed while the build ran.

```
src/Combat/init.meta.json - error: the meta file could not be read: permission denied. (meta.unreadable)
src/Combat/init.meta.json - error: the meta file does not exist any more; it was there when the build scanned and was removed while it ran. (meta.unreadable)
```

Fix the file's permissions, or run the build again. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.invalidSyntax` [#meta-invalidsyntax]

Error. A folder's `init.meta.json` isn't valid JSONC. Rogen merges a folder's meta into the project file, so it reads that one; Rojo reads the meta of a single file, and reports its errors itself.

```
src/Combat/init.meta.json:3:1 - error: invalid JSONC: expected '}'. (meta.invalidSyntax)
```

## Scanning

### `scan.missingSourcePath` [#scan-missingsourcepath]

Warning, or error. A folder in `sourcePaths` doesn't exist, or is a file. It is a warning while another source path is a folder, and the missing one contributes nothing. It is an error when none is, since the build would write an empty tree over your project file: `rogen build` and `rogen check` fail, and the project file stays as it was.

```
later - warning: this source path does not exist or is not a folder, so it contributes nothing. (scan.missingSourcePath)
```

```
srcc - error: this source path does not exist or is not a folder, and no other source path of the config does, so there is nothing to build. default.project.json was left as it was. Check the spelling in "sourcePaths". (scan.missingSourcePath)
```

Create the folder, fix the spelling, or remove it from `sourcePaths`. The path is relative to the folder of `rogen.json`. `rogen list` shows it too. A running `rogen watch` or `rogen serve` keeps the last good project file and builds again once a source path is back. See [Configuration](/docs/v2/configuration#fields).

### `scan.unmountedSource` [#scan-unmountedsource]

Warning. The config declares no `routes`, so no source path is scanned, but the default `src` folder holds files that nothing in the `tree` mounts. Rojo never syncs them.

```
src - warning: 3 files here are mounted by nothing in the tree, and the config declares no routes, so Rojo never syncs them. Add "routes" to place them, or mount the folder with "$path". (scan.unmountedSource)
```

Add `routes` so Rogen places the files, or mount the folder in the `tree` with a `$path`. Files that `globIgnorePaths` matches don't count. See [Configuration](/docs/v2/configuration#tree).

### `scan.extensionCase` [#scan-extensioncase]

Warning. A file's extension is written with capital letters, so Rojo doesn't read it and the file is not an instance. Rogen leaves it out of the tree as Rojo does.

```
src/Save.LUAU - warning: Rojo reads an extension only in lowercase, so it ignores this file. Rename it to Save.luau. (scan.extensionCase)
```

Rename the file as the message says. The same holds for `.JSON`, `.MODEL.JSON` and every other extension Rojo reads.

### `scan.syncRuleSuffix` [#scan-syncrulesuffix]

Warning. A sync rule takes a file but its `suffix` doesn't end the file's name. Rojo cuts the suffix off the name to name the instance, so with no suffix to cut it keeps the whole file name, extension included.

```
src/Notes.md - warning: the sync rule "*.md" cuts ".txt" off a file name, but this name does not end with it, so Rojo names the instance after the whole file name. Make the suffix end every file the pattern matches. (scan.syncRuleSuffix)
```

Change the `suffix`, or the `pattern`, so the suffix ends every file the pattern takes. See [Configuration](/docs/v2/configuration#sync-rules).

### `scan.nestedProject` [#scan-nestedproject]

Warning. A `default.project.json` lies inside a source path. Rojo reads it as a nested project, so it becomes an instance named `default`, holding that project's tree. A project file for the folder it lies in belongs outside the source paths. Other project files are left alone, since a nested project with a name of its own is a thing Rojo supports.

```
places/arena/default.project.json - warning: Rojo reads this project file as a nested project, so it becomes ReplicatedStorage/Shared/default, holding that project's tree. A project file for the folder it lies in belongs outside the source paths. (scan.nestedProject)
```

Move the file out of the source paths. If it is meant as a nested project, mount it in the `tree` with a `$path` instead, which Rogen leaves to Rojo.

### `scan.sourcePathNamedAfterKey` [#scan-sourcepathnamedafterkey]

Warning. A source path is named after a route key. Routing starts below a source path, so its name routes nothing, and its files land wherever the `*` route sends them, or nowhere. One warning lists every such source path.

```
rogen.json - warning: 2 source paths are named after a route key, but routing starts below a source path, so their names route nothing: (scan.sourcePathNamedAfterKey)
  server ("server" route)
  client ("client" route)
Move them into one folder, such as src/server and src/client, and use "sourcePaths": ["src"].
```

When the source path has a parent inside the project (`src/server`), use the parent: `"sourcePaths": ["src"]`, and the `server` folder routes. When it sits at the folder of `rogen.json`, move the folders into one code folder first, since `"."` would scan the whole repo. The build still runs and writes. See [Routing](/docs/v2/core-concepts/routing).

### `scan.unresolvedLink` [#scan-unresolvedlink]

Warning. A symlink or junction inside a source path points at nothing, or back at a directory that contains it.

```
src/Missing - warning: this link points at nothing, or back at a directory that contains it, so it contributes nothing. (scan.unresolvedLink)
```

Fix the link's target, or remove the link. See [Linked Directories](/docs/v2/core-concepts/project-layout#linked-directories).

### `scan.emptyName` [#scan-emptyname]

Warning. A script file is named only by its suffix, such as `.server.luau`, so the instance it becomes has an empty name. Rojo builds it the same way, and Studio and `require` cannot use it well.

```
src/.server.luau - warning: has no name once its suffix is taken off, so it becomes an instance with an empty name. Put a name before the suffix, as in Name.server.luau. (scan.emptyName)
```

Rename the file with a name before the suffix.

### `scan.outsideSourcePaths` [#scan-outsidesourcepaths]

Warning. `rogen check <path>` was given a path that is in no source path, and its first folder is one edit from a source path (or differs from it only in letter case), so a typo is likely. Any other path outside the source paths passes, since hooks hand `check` every changed file.

```
scr/Inventory/Server/Save.luau - warning: this path is in no source path, so no build reads it, and "scr" is one edit from the source path "src". Check the spelling. (scan.outsideSourcePaths)
```

Fix the path, or the source path in `sourcePaths` if that is the typo.

### `scan.portableName` [#scan-portablename]

Warning. A file or folder name that holds on this machine but fails on Windows or macOS, or that Rogen cannot read. A name fails when it has one of `<>:"|?*` or a control character, is a Windows device (`con`, `prn`, `aux`, `nul`, `com1` to `com9`, `lpt1` to `lpt9`, with any extension), ends in a space or a dot, or differs from a sibling only in letter case. Nothing is dropped, except for a name with a backslash: Rogen reads `\` as a folder separator, so it leaves that file out.

```
src/Bad:Name.luau - warning: its name has ":", which Windows file names cannot hold. Rename it so a checkout works on every system. (scan.portableName)
```

Rename the file or folder, and update what requires it. The check runs for each file and folder that becomes an instance, and for meta and marker files, not for files Rogen ignores.

## Serve

### `serve.noServer` [#serve-noserver]

```
rogen.json - error: No Rojo to serve with: none is pinned in a toolchain file here or above, or on the PATH. Run 'rokit add rojo-rbx/rojo', then 'rogen plugin install' to install its Studio plugin. (serve.noServer)
rogen.json - error: No Rojo to serve with: none is pinned in a toolchain file here or above, or on the PATH. Run 'rokit add rojo-rbx/rojo', then 'rogen plugin install' to install its Studio plugin. Argon is pinned, but rogen serve only starts Rojo: run 'rogen build --watch' to keep the project files current, and 'argon serve' to serve them. (serve.noServer)
```

Pin Rojo with your toolchain manager (`rokit add rojo-rbx/rojo`, or `aftman add` in an Aftman project; Foreman has no add command, so add it to `foreman.toml` by hand), then install its Studio plugin with `rogen plugin install`. Rogen never installs anything. To serve with Argon, run `rogen build --watch` and `argon serve` instead: see [Studio](/docs/v2/studio#serve-with-argon). See [CLI](/docs/v2/cli#serve).

### `serve.notInstalled` [#serve-notinstalled]

Error. A toolchain file pins Rojo, but it isn't installed, so its command isn't on the PATH.

```
rokit.toml - error: rokit.toml pins Rojo as rojo, but it isn't installed. Run 'rokit install'. (serve.notInstalled)
```

Run the manager's install command: `rokit install`, `aftman install` or `foreman install`. See [CLI](/docs/v2/cli#serve).

### `serve.serverFailed` [#serve-serverfailed]

Error. Rogen runs `<tool> --version` before it builds, and that failed, so Rojo can't start. The message ends with the first line Rojo printed. A toolchain shim on the PATH whose project doesn't pin the tool fails this way, and then the message adds the command that pins it.

```
rogen.json - error: 'rojo --version' failed, so Rojo can't start: Failed to find tool 'rojo' in any project manifest file. If Rojo isn't pinned yet, run 'rokit add rojo-rbx/rojo'. (serve.serverFailed)
```

Pin the tool, or fix the install the quoted line points at. Running `rojo --version` yourself shows the full output. See [CLI](/docs/v2/cli#serve).

### `serve.portTaken` [#serve-porttaken]

Error. Another program holds the port a config would be served on. When it's a Rojo server, the message names the project it serves. A server that already serves the same project isn't an error: `rogen serve` leaves it running, and builds for it when no `rogen serve` started it. It is one when another config here has the same project name and no `rogen serve` started the server, since Rogen can't tell which config it serves: stop that server and run `rogen serve` again.

```
rogen.json - error: Port 34872 is taken by Rojo serving shop, so default can't be served there. Give default its own servePort in rogen.json, or run 'rogen serve default --port 34873'. (serve.portTaken)
```

Stop what holds the port, give the config its own `servePort` in its `rogen.json`, or pass a free port with `--port`. With `--json`, `fixes` holds the command with a free port Rogen found. See [CLI](/docs/v2/cli#serve).

### `serve.serverExited` [#serve-serverexited]

Error. A server stopped on its own with a non-zero exit code, or couldn't be started. `rogen serve` then stops and exits with the server's code (1 when it has none).

```
rogen.json - error: Rojo stopped serving default with exit code 1; see what it said above. (serve.serverExited)
```

Read what the server said just above it, which usually says why. When it said nothing, as when it was killed, the message ends `without saying why`. See [CLI](/docs/v2/cli#serve).

### `rojo.windowsRules` [#rojo-windowsrules]

Error. Rojo 7.7.0 on Windows applies no sync rule or ignore glob whose pattern starts with `../`, and a file Rogen wrote has one, so Rojo would serve a tree that differs from the one Rogen built. This happens for every place whose root has ignore globs, since a place's patterns are written relative to its folder. Rojo 7.7.1 fixed it, and 7.5.0 to 7.6.1 are not affected.

```
shop/default.project.json - error: Rojo 7.7.0 on Windows applies no sync rule or ignore glob that starts with "../", and this file has 1: "../../src/*.md". Rojo 7.7.1 fixed it: change your Rojo pin, or update the Rojo on the PATH. (rojo.windowsRules)
```

Move to Rojo 7.7.1 or newer. See [CLI](/docs/v2/cli#serve).

### `rojo.commandFailed` [#rojo-commandfailed]

Error. Rojo exited with an error while Rogen ran it, such as `rojo build` for `rogen build -o`. The message gives how it exited and what Rojo said.

```
default.project.json - error: 'rojo build' failed (exit code 1): Failed to write to game.rbxl. (rojo.commandFailed)
```

Rogen had written the project files by then. Fix what Rojo says, such as an output folder that doesn't exist, and run the build again.

### `rojo.commandUnsupported` [#rojo-commandunsupported]

Error. The Rojo that would run has no such command: it is older than the release that added it. Today only `rogen syncback` can meet it, since `rojo syncback` came with Rojo 7.7.0.

```
default.project.json - error: Rojo 7.6.1 has no 'syncback' command; Rojo 7.7.0 added it. Change your Rojo pin to 7.7.0 or later, or update the Rojo on the PATH. (rojo.commandUnsupported)
```

Pin a newer Rojo with your toolchain manager (`rokit add rojo-rbx/rojo`), or update the one on the PATH.

## Syncback

### `syncback.removedFromProjectFile` [#syncback-removedfromprojectfile]

Error. The place no longer holds an instance that a node of the config's own `tree` defines, which Rojo's syncback refuses to remove: it doesn't edit project files. Files Rogen placed are synced through a mirror and can always be removed; this is about the nodes you wrote yourself.

```
rogen.json - error: the place no longer holds Workspace/Map, and the tree of the config defines it, which syncback cannot remove. Remove its node from the tree, then run syncback again. (syncback.removedFromProjectFile)
```

Remove the node from the `tree` of `rogen.json`, or put the instance back in the place, and run `rogen syncback` again. Nothing was written. See [CLI](/docs/v2/cli#syncback).

### `syncback.unplaced` [#syncback-unplaced]

Warning. The place holds an instance that no folder of the project can take, so syncback left it out. A new instance is written where routing would place a file for it, in the style of the nearest files; this is the case where nothing decides: no route puts files where its parent is, two routes do, the project has several source paths and no file beside it says which, or as many files beside it lie in each of two folders of one style. It is also how syncback lists what it can't write: an instance where an ignore glob would put it, a property set on a folder that no one folder of the project is, and a change Rojo itself can't sync back (a `.json` or `.toml` module). The message says why.

```
rogen.json - warning: ServerScriptService/Inventory/Mail is in the place and no folder of the project can take it, so it was left out: files beside it are in more than one place, as many in each: src/Inventory/Server, lib/Inventory/Server. (syncback.unplaced)
```

Create the file where you want it, by hand, and run `rogen syncback` again. Other changes of the same run were written. See [CLI](/docs/v2/cli#syncback).

### `syncback.misplaced` [#syncback-misplaced]

Warning. After syncback, Rogen asked where the files it placed land, and one lands at another instance than the place had. A route is missing or ambiguous for it, or the name of the file means something to routing.

```
src/Quest/Mail@sever.luau - warning: this file was written for ServerScriptService/Quest/Mail, and lands at ReplicatedStorage/Shared/Quest/Mail. Move it to where routing puts it at ServerScriptService/Quest/Mail. (syncback.misplaced)
```

Move or rename the file, and run `rogen where` on it to see the route. See [Routing](/docs/v2/core-concepts/routing).

## Migration

### `legacy.config` [#legacy-config]

Error. A `rogen.json` has keys from Rogen 1, such as `source`, `aliases` or a mode, so it is a v1 config, which v2 doesn't read.

```
rogen.json - error: this looks like a config for Rogen 1, which v2 doesn't read. See https://rogen-playfully.vercel.app/docs/v2/migrating-from-v1 to migrate it. (legacy.config)
```

Rewrite the config in v2's shape. See [Migrating from v1](/docs/v2/migrating-from-v1).
