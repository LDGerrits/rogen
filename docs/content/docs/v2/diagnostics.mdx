---
title: Diagnostics
description: Every error and warning Rogen reports, why it fires and how to fix it.
---

Every diagnostic has a stable code, such as `route.strayAt`. The terminal prints it as `file:line:col - severity: message (code)`, and `--json` adds a `url` pointing at its section on this page and, for some warnings, the `fixes` that resolve it. `rogen help <code>` prints a code's section from the version you have installed, offline.

An error stops every config in the run from being written. A warning never does, but it always names something to fix.

## Config

### `config.unreadable` [#config-unreadable]

Error. The config file isn't there, or is there but Rogen couldn't read it from disk. A missing file says where Rogen looked, and an unreadable one says why.

```
default.rogen.json - error: the config does not exist (looked for default.rogen.json). (config.unreadable)
default.rogen.json - error: the config could not be read: permission denied. (config.unreadable)
```

Fix the path or the file's permissions, or check that it's a file and not a folder. See [Configuration](/docs/v2/configuration).

### `config.invalidSyntax` [#config-invalidsyntax]

Error. The config isn't valid JSONC. Comments and trailing commas are fine, but brackets and quotes have to match.

```
default.rogen.json:4:1 - error: invalid JSONC: expected '}'. (config.invalidSyntax)
```

Fix the syntax at the line and column shown. See [Configuration](/docs/v2/configuration).

### `config.notAnObject` [#config-notanobject]

Error. The config holds a JSON value that isn't an object, such as an array or a string.

```
default.rogen.json:1:1 - error: a config must be a JSON object. (config.notAnObject)
```

Wrap the fields in `{ }`. See [Configuration](/docs/v2/configuration#fields).

### `config.wrongType` [#config-wrongtype]

Error. A field holds the wrong kind of value, such as a string where `rootDirs` needs an array.

```
default.rogen.json:2:14 - error: "rootDirs": expected an array, found a string. (config.wrongType)
```

Give the field the type the message names. See [Configuration](/docs/v2/configuration#fields).

### `config.unknownField` [#config-unknownfield]

Error. The config has a field Rogen doesn't know, often a typo or a field from Rogen 1.

```
default.rogen.json:4:2 - error: unknown field "exlude". Did you mean "exclude"? (config.unknownField)
```

Rename it to the field suggested, or remove it. A config with v1 fields also gets [`legacy.config`](#legacy-config). See [Configuration](/docs/v2/configuration#fields).

### `config.removedField` [#config-removedfield]

Error. The config has a field that Rogen removed. The error is at the field, as for an unknown field, and the message says what to do instead.

```
default.rogen.json:4:2 - error: "modes" was removed. Put what a mode set in a second config that extends this one, which can add "exclude". (config.removedField)
default.rogen.json:5:2 - error: "variants" was removed. A file that replaces another goes in a later root dir, which wins a clash, and a second config that extends this one lists that root dir. (config.removedField)
```

Remove the field and do what the message says. For `modes` and `mode`, that is a second config that [extends](/docs/v2/configuration#extending-configs) this one and adds an `exclude`, built by its name as `rogen build <name>`. For `variants`, a file that replaces another goes in a later root dir, which wins a clash, and a second config that extends this one lists that root dir. For `conflicts`, sets that exclude each other are one config each, listing their own root dir. See [Configuration](/docs/v2/configuration#fields) and [Replacing a File](/docs/v2/core-concepts/project-layout#replacing-a-file).

### `config.unnamed` [#config-unnamed]

Error. The file is called just `.rogen.json`. Every config needs a name, because commands select it by that name.

```
.rogen.json - error: a config file needs a name before ".rogen.json". Rename it to <name>.rogen.json, such as default.rogen.json. (config.unnamed)
```

Rename it, usually to `default.rogen.json`. See [Configuration](/docs/v2/configuration#finding-configs).

### `config.extendsCycle` [#config-extendscycle]

Error. Following `extends` leads back to a config already in the chain.

```
c.rogen.json:2:13 - error: extends cycle: a.rogen.json -> b.rogen.json -> c.rogen.json -> a.rogen.json. (config.extendsCycle)
```

Remove `extends` from one config in the loop. See [Extending Configs](/docs/v2/configuration#extending-configs).

### `config.extendsUnreadable` [#config-extendsunreadable]

Error. The config that `extends` names doesn't exist or can't be read. The path is relative to the config that writes it. A missing target says where Rogen looked, and an unreadable one says why.

```
default.rogen.json:2:13 - error: "extends" target "./nowhere.rogen.json" does not exist (looked for nowhere.rogen.json). Paths are relative to this config. (config.extendsUnreadable)
default.rogen.json:2:13 - error: "extends" target "./base.rogen.json" could not be read: permission denied. (config.extendsUnreadable)
```

Fix the path, or create the parent config. See [Extending Configs](/docs/v2/configuration#extending-configs).

### `config.templateUnreadable` [#config-templateunreadable]

Error. The `template` project file doesn't exist or can't be read.

```
default.rogen.json:5:14 - error: the template does not exist (looked for nope.project.json). Paths are relative to the config that sets them. (config.templateUnreadable)
default.rogen.json:5:14 - error: the template could not be read: permission denied. (config.templateUnreadable)
```

Fix the path, which is relative to the config that sets it, or create the file. See [Template](/docs/v2/core-concepts/output#template).

### `config.templateInvalid` [#config-templateinvalid]

Error. The `template` file isn't a valid Rojo project file.

```
default.rogen.json:5:14 - error: the template is not a valid Rojo project file: "tree" must be an object. (config.templateInvalid)
```

Fix the project file so Rojo would accept it: a `name` and a `tree` object. See [Template](/docs/v2/core-concepts/output#template).

### `config.outFileIsTemplate` [#config-outfileistemplate]

Error. The project file the config writes is also its template, so every build would overwrite the template.

```
default.rogen.json:11:14 - error: the output file default.project.json is also the template, and a build would overwrite it. Set "outFile" to another path. (config.outFileIsTemplate)
```

Rename the template to `template.project.json`, or set `outFile` to another path. See [Template](/docs/v2/core-concepts/output#template).

### `config.outFileIsConfig` [#config-outfileisconfig]

Error. The project file the config writes is named like a config, so a build would overwrite a config.

```
default.rogen.json:3:14 - error: the output file /repo/default.rogen.json is named like a config, and a build would overwrite it. Set "outFile" to a .project.json path. (config.outFileIsConfig)
```

Set `outFile` to a path that ends in `.project.json`. `-o` follows the same rule.

### `config.duplicateRootDir` [#config-duplicaterootdir]

Error. One directory appears twice in `rootDirs`, so every file in it would belong to both entries.

```
default.rogen.json:4:3 - error: root dir "src" is listed twice; a file under it would belong to both. Remove one. (config.duplicateRootDir)
```

Remove one entry. With `extends`, the diagnostic points at the file that wrote the entry, since a config adds its root dirs to its parent's. See [Several Root Directories](/docs/v2/core-concepts/project-layout#several-root-directories).

### `config.nestedRootDir` [#config-nestedrootdir]

Error. One root directory sits inside another, so the files in it would belong to both.

```
default.rogen.json:4:3 - error: root dir "src/shared" is inside root dir "src"; a file under it would belong to both. Remove one. (config.nestedRootDir)
```

Remove the inner one, or move it out of the outer one. See [Several Root Directories](/docs/v2/core-concepts/project-layout#several-root-directories).

### `config.syncDirOverlapsRootDir` [#config-syncdiroverlapsrootdir]

Error. The sync dir is a root dir, lies inside one, or contains one. The sync dir is where Darklua or a compiler writes the code the root dirs hold, so Rogen would read that output as source and write the project file from it.

```
default.rogen.json:4:14 - error: the sync dir "/repo/src/out" is inside root dir "/repo/src", so Rogen would read what the tools write as source. Set "syncDir" to a folder outside the root dirs. (config.syncDirOverlapsRootDir)
```

Set `syncDir` to a folder beside the root dirs, such as `dist` or `out`. See [Darklua](/docs/v2/setups/darklua).

### `config.invalidRouteKey` [#config-invalidroutekey]

Error. A route key has characters other than letters and digits, or starts with a digit. Keys appear in folder and file names, so they have to match exactly.

```
default.rogen.json:6:14 - error: route key "ser-ver" is invalid: use letters and digits only, starting with a letter. (config.invalidRouteKey)
```

Rename the key, for example `server`. See [Routing](/docs/v2/core-concepts/routing).

### `config.ambiguousKey` [#config-ambiguouskey]

Error. Two declared keys differ only in the case of their first letter. A name matches a key with its first letter in either case, so both would match the same folders.

```
default.rogen.json:7:13 - error: "Server" and "server" differ only in the case of their first letter, so both would match the same names; keep one of them. (config.ambiguousKey)
```

Keep one of them. See [Matching](/docs/v2/core-concepts/routing#matching).

### `config.unknownServer` [#config-unknownserver]

Error. The config's `server` field names a sync server Rogen can't start. It takes `"rojo"` or `"argon"`, in lowercase.

```
default.rogen.json:4:12 - error: "server" is "argn", but Rogen serves with "rojo" or "argon". Did you mean "argon"? (config.unknownServer)
```

Fix the name, or remove the field to serve with the server the project pins. See [`serve`](/docs/v2/cli#serve).

## Routes

### `roblox.unsupportedService` [#roblox-unsupportedservice]

Error. A route's target doesn't start with a Roblox service Rojo can write to.

```
default.rogen.json:7:13 - error: "StarterPlayerScripts" is not a supported service. Did you mean "StarterPlayer/StarterPlayerScripts"? (roblox.unsupportedService)
```

Start the target with a service, then any folders: `"StarterPlayer/StarterPlayerScripts"`, `"ReplicatedStorage/Shared"`. See [Targets](/docs/v2/core-concepts/routing#targets).

### `roblox.invalidFolder` [#roblox-invalidfolder]

Error. A route's target has a folder with no name, `.` or `..`, which would make an instance of that name.

```
default.rogen.json:7:13 - error: the target "ServerScriptService/" has an empty folder name; write each folder between single slashes, such as "ServerScriptService/Folder". (roblox.invalidFolder)
```

Remove the extra slash, or name the folder. See [Targets](/docs/v2/core-concepts/routing#targets).

### `route.noRoutes` [#route-noroutes]

Error. The config declares no `routes`, so no file can be placed. Rogen never picks a destination on its own.

```
default.rogen.json - error: no routes declared, so nothing can be placed. (route.noRoutes)
Add a "routes" map; 'rogen init' writes a starting set.
```

Add a `routes` map. `rogen init` writes `server`, `client`, `shared` and `*`. See [Routing](/docs/v2/core-concepts/routing).

### `route.unrouted` [#route-unrouted]

Warning. No route matches the file and there's no `*` route, so it's left out of the project file.

```
src/Util.luau - warning: matched no route, so it is left out. Add a "*" route, or move it into a routing folder. (route.unrouted)
```

Move the file into a routing folder, give it an `@key` suffix, or declare a `"*"` route. See [Files That Match No Route](/docs/v2/core-concepts/routing#files-that-match-no-route).

### `route.strayAt` [#route-strayat]

Warning. A name, folder or marker file has an `@` that doesn't route, so the `@` stays in the instance name. Either it nearly spells a declared route key (a typo or a wrong case), or it spells one but isn't at the end of the name (`Report@server.bak.luau`). One warning lists every such name. An `@` that is nowhere near a route key, as in a package name like `@rbxts`, isn't reported.

```
default.rogen.json - warning: 2 names have an "@" that routes nowhere, so they are read as ordinary names: (route.strayAt)
  src/Inventory/Load@SERVER.luau (did you mean "@server"?)
  src/Inventory/Report@server.bak.luau ("@server" must end the name)
```

Rename the file to the spelling suggested, or move the `@key` to the end of the name. In `--json`, `fixes` holds the rename when exactly one key is closest. See [The `@` Sign](/docs/v2/core-concepts/routing#the--sign).

### `route.dotRoute` [#route-dotroute]

Warning. A route key is written after a dot, where only `@` routes, so it routes nothing: a dot-file like `.server`, which isn't a marker, a dot-folder like `.server/`, which isn't a routing folder, or a dot part of a name like `Types.shared.luau` or `Net.server/`, which stays in the name. What it names falls through to the route above it, or `*`. The key matches in any letter case, so `.SERVER/` and `Types.SHARED.luau` warn too. Rojo's `.server` and `.client` at the end of a script still route and are never reported, but only in lower case (Rojo reads `Boot.Server.luau` as a ModuleScript named `Boot.Server`, so Rogen suggests `Boot.server.luau`), and only on a script: a data file or model has no script class, so `Config.server.json` is named `Config.server` and warns. One warning lists every such name.

```
default.rogen.json - warning: 2 names write a route key after a dot, where only "@" routes, so they route nothing: (route.dotRoute)
  src/Inventory/.server (write "@server")
  src/Inventory/Types.shared.luau (write "Types@shared.luau")
```

Rename each to its `@` form: a marker file is `@server`, a folder `@server/`, and a name `Types@shared.luau` or `Config@server.json`. In `--json`, `fixes` holds every rename. See [Marker Files](/docs/v2/core-concepts/routing#marker-files).

### `route.folderTypo` [#route-foldertypo]

Warning. A folder is named one edit away from a declared route key, such as `Sever/` next to `Server`, so it's read as an ordinary folder and its files fall through to the route above it or `*`. The edit can be a letter added, dropped or changed, or two neighbours swapped (`Sevrer/`). A plural counts too: `Servers/` reads as an ordinary folder, so it warns; rename it if its files belong under the route. The folder's name is read with its parentheses and `^` off. Only keys of four letters or more are offered, since shorter ones are one edit from real words, and a name that matches a key in any letter case is `route.caseMismatch` instead. One warning lists every such folder.

```
default.rogen.json - warning: 1 folder is one edit from a declared route key, so it is read as an ordinary folder: (route.folderTypo)
  src/Inventory/Sever (did you mean "Server"?)
```

Rename the folder to the key suggested, or, when the key in your config is the typo, fix it in `routes`. In `--json`, `fixes` holds the rename when exactly one key is closest. See [Routing Folders](/docs/v2/core-concepts/routing).

### `route.markerClash` [#route-markerclash]

Error. Two marker files in one folder name different routes, such as `@server` beside `@client`. An init script's route suffix counts as a marker, so `@server` beside `init@client.luau` clashes too. Both sit at the same level, so nothing decides which one governs. The same route twice is fine.

```
src/Inventory - error: "@client" and "@server" route this folder to different places, and nothing decides between them. Keep one. (route.markerClash)
```

Delete the marker you don't want, or move part of the folder into a subfolder with its own marker. See [Marker Files](/docs/v2/core-concepts/routing#marker-files).

### `route.ignoredAt` [#route-ignoredat]

Error. A name or marker file has an `@key` inside a folder that another route already governs, or before another `@key` in the same name (`Net@client@server/`). Only the outermost route acts, and in one name only the last `@key` routes, so this one does nothing, while the name says the file goes somewhere it doesn't.

```
src/server/Util@client.luau - error: "@client" does nothing here, because the "server" route already governs this file. Remove it, or move the file out of the "server" route's files. (route.ignoredAt)
```

Remove the `@key`, or move the file out of the governing route's folder. There's no automatic fix, since which one is right depends on where the code should run. An `@` that restates the governing route, like `Shared/Net/Remote@shared.luau`, is fine. A file that another file replaces is reported too, since its name is wrong either way. See [The Governing Route](/docs/v2/core-concepts/routing#the-governing-route).

### `route.caseMismatch` [#route-casemismatch]

Warning. A folder or marker matches a declared key except for letter case beyond the first letter, so it's read as an ordinary name.

```
src/SHARED - warning: differs from the route "shared" only in letter case, so it is read as an ordinary name. Spell it "shared" or "Shared", or declare it as written. (route.caseMismatch)
```

Rename it to the key, or declare it as written if it's meant to route. `SHARED/` may also just be a folder name, so there's no automatic fix. See [Matching](/docs/v2/core-concepts/routing#matching).

### `route.serverCodeShipped` [#route-servercodeshipped]

Warning. A file sits in a plain folder named after a server route, such as `Server/` or `(Server)/`, that an outer route outranks, so the outer route, which replicates to clients, places it. Server code under `Shared/` ships to every client.

```
default.rogen.json - warning: 1 file under a "server" route ships to clients, because "shared" governs it: (route.serverCodeShipped)
  src/Shared/(Server)/Datastore.luau -> ReplicatedStorage/shared/Datastore
Move it out of the "shared" route's files if it's server code, or keep it there with a "@shared" marker file in its folder.
```

Move the file out of the replicating route's folder, for example from `Shared/Server/` to `Server/`. If the folder is meant to replicate, put a marker file that restates the governing route in it, such as `Shared/Server/@shared`: it covers every file below it. `Secret@shared.luau` covers just that file. A route written with `@`, like `Shared/Data@server.luau`, is the [`route.ignoredAt`](#route-ignoredat) error instead. See [Server Code Under a Replicating Route](/docs/v2/core-concepts/routing#server-code-under-a-replicating-route).

## Tree

### `tree.reservedName` [#tree-reservedname]

Warning. The project file gets an instance whose key starts with `$`, which Rojo reserves for its own fields. Rojo keeps the instance but warns of it on every build and serve.

```
src/$Config.luau - warning: the project file gets the instance "ReplicatedStorage/shared/$Config", and Rojo reserves a leading $ for its own fields, so it warns of it on every build. Rename the file without the $. (tree.reservedName)
```

Rename the file or folder without the `$`. A `$` inside a name, as in `Cost$`, is fine, and so is a file inside a folder that Rogen gives to Rojo whole as one `$path`.

### `tree.instanceClash` [#tree-instanceclash]

Warning. Two files in one root directory become the same instance, such as `Types.lua` and `Types.luau`. The last one takes the instance and the other is left out. Across root directories the last one wins without a warning: that is how a file is [replaced](/docs/v2/core-concepts/project-layout#replacing-a-file).

```
src/Inventory/Types.lua - warning: becomes "ReplicatedStorage/shared/Inventory/Types", as src/Inventory/Types.luau does, which takes its place. Rename one of them to keep both. (tree.instanceClash)
```

Rename or delete one of them. `rogen where` shows the left-out file as `replaced by`. See [Replacing a File](/docs/v2/core-concepts/project-layout#replacing-a-file).

### `tree.templateClash` [#tree-templateclash]

Warning. The template defines a node at the same instance path as a file or folder, so the template's node is kept and the file is left out.

```
src/Save.server.luau - warning: the template defines "ServerScriptService/Save" too, so its node is kept and this file is left out. Rename one of them to keep both. (tree.templateClash)
```

Rename the file, or remove the node from the template. See [Template](/docs/v2/core-concepts/output#template).

### `tree.initWithoutFolder` [#tree-initwithoutfolder]

Error. An init script becomes the folder it sits in, but that folder never becomes an instance. That's a root directory, a plain routing folder or an invisible folder.

```
src/server/init.server.luau - error: an init script becomes the folder it sits in, but it sits in a routing folder, which never becomes an instance. Move it into a folder of its own, or rename it. (tree.initWithoutFolder)
```

Move the script into a folder of its own, or rename it so it isn't an init script. See [Init Folders](/docs/v2/core-concepts/project-layout#init-folders).

### `tree.hoistedInit` [#tree-hoistedinit]

Error. An init script's name starts with `^`. The script is its folder, so it can't be hoisted on its own; the folder can.

```
src/Net - error: ^init.luau starts with "^", but an init script is its folder, so the "^" can't hoist it alone. Put the "^" on the folder: ^Net. (tree.hoistedInit)
```

Rename the script back to `init.luau` and the folder to `^Net`. See [Hoisted Names](/docs/v2/core-concepts/routing#hoisted-names).

### `tree.deadScript` [#tree-deadscript]

Warning. A Script or LocalScript lands in a service where Roblox never runs it, such as a LocalScript in `ServerScriptService`. One warning lists every such script.

```
default.rogen.json - warning: 1 script will never run where it lands: (tree.deadScript)
  src/Shared/Secret.server.luau -> ReplicatedStorage/shared/Secret (a Script, placed by the "shared" route)
A Script runs in ServerScriptService or Workspace, and a LocalScript in StarterPlayerScripts, StarterCharacterScripts, StarterGui, StarterPack or ReplicatedFirst. A Script with RunContext Client never runs in ServerScriptService, which clients can't see.
```

Move the script under a route whose target runs it, or drop `.server`/`.client` to make it a ModuleScript. See [Scripts That Never Run](/docs/v2/core-concepts/routing#scripts-that-never-run).

### `tree.runContextTarget` [#tree-runcontexttarget]

Warning. The template sets `emitLegacyScripts: false`, but a route targets `StarterPlayerScripts` or `StarterCharacterScripts`, where RunContext scripts don't run as LocalScripts.

```
default.project.json - warning: emitLegacyScripts: false in the template isn't supported with routes that target StarterPlayerScripts or StarterCharacterScripts ("client" → StarterPlayer/StarterPlayerScripts). Route it to another service, or remove emitLegacyScripts from the template. (tree.runContextTarget)
```

Remove `emitLegacyScripts` from the template, or route client code elsewhere, such as `ReplicatedStorage` with RunContext Client. See [Template](/docs/v2/core-concepts/output#template).

### `template.mountsRootDir` [#template-mountsrootdir]

Error. A `$path` in the template mounts a root directory, or a folder that holds one, so Rojo would read the whole directory and Rogen could place nothing in it.

```
template.project.json - error: "ReplicatedStorage/All" mounts the root dir src, so Rojo would read all of it and Rogen would place nothing there. Mount a folder inside the root dir, or remove the root dir from "rootDirs". (template.mountsRootDir)
```

Mount a folder inside the root directory, such as a vendored package, or remove the root directory from `rootDirs`. See [Template](/docs/v2/core-concepts/output#template).

### `template.overridesBase` [#template-overridesbase]

Warning. A config's template sets a field on a node that the template of a config it extends sets too, to another value. The templates merge, so the nearer one's value wins.

```
places/lobby/template.project.json - warning: "ReplicatedStorage/Packages" sets $path here and in places/shared/template.project.json, which this template merges over, so this one wins. Remove it from one of them. (template.overridesBase)
```

Keep the field in one template: in the shared one when every place wants it, or in each place's own when they differ. See [Template](/docs/v2/core-concepts/output#template).

## Metadata

### `meta.unreadable` [#meta-unreadable]

Error. A `.meta.json` file was found when Rogen scanned but couldn't be read from disk: it lacks the permissions, is a folder, or was removed while the build ran.

```
src/Combat/init.meta.json - error: the meta file could not be read: permission denied. (meta.unreadable)
src/Combat/init.meta.json - error: the meta file does not exist any more; it was there when the build scanned and was removed while it ran. (meta.unreadable)
```

Fix the file's permissions, or run the build again. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.invalidSyntax` [#meta-invalidsyntax]

Error. A folder's `init.meta.json` isn't valid JSONC. Rogen merges a folder's meta into the project file, so it reads that one; Rojo reads the meta of a single file, and reports its errors itself.

```
src/Combat/init.meta.json:3:1 - error: invalid JSONC: expected '}'. (meta.invalidSyntax)
```

Fix the syntax at the line and column shown. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.byteOrderMark` [#meta-byteordermark]

Error. A meta file starts with a byte order mark (the invisible character some editors and PowerShell's `Out-File` put first in a UTF-8 file). Rojo can't read a file that begins with one and refuses the whole project, so Rogen stops before it writes a project file that Rojo would then fail on.

```
src/Combat/init.meta.json:1:1 - error: starts with a byte order mark, which Rojo can't read, so it refuses the project. Save the file as UTF-8 without one. (meta.byteOrderMark)
```

Save the file as UTF-8 without a byte order mark. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.notAnObject` [#meta-notanobject]

Error. A folder's `init.meta.json` holds a JSON value that isn't an object.

```
src/Combat/init.meta.json:1:1 - error: a meta file must be a JSON object. (meta.notAnObject)
```

Wrap the fields in `{ }`. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.wrongType` [#meta-wrongtype]

Error. A field in a folder's `init.meta.json` holds the wrong kind of value.

```
src/Combat/init.meta.json:4:16 - error: "attributes": expected an object, found an array. (meta.wrongType)
```

Give the field the type the message names, as Rojo's meta format expects. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.unknownField` [#meta-unknownfield]

Warning. A meta file has a field that is a slip from one Rojo reads, such as `classname` for `className`. Rojo ignores a field it doesn't know without a word, so the property never applies. A field that resembles none, such as `$schema`, is left alone.

```
src/Combat/init.meta.json:2:3 - warning: unknown field "classname"; Rojo ignores it. Did you mean "className"? (meta.unknownField)
```

Rename it to the field suggested, or remove it. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.unclaimed` [#meta-unclaimed]

Warning. A `.meta.json` file belongs to no file, so Rojo ignores it. A file's meta is named after the name Rojo gives the file, without `.server`, `.client` or `.plugin`.

```
src/Inventory/Save.server.meta.json - warning: belongs to no file, so Rojo ignores it. Rojo reads Save.meta.json. (meta.unclaimed)
```

Rename it to the name the message gives, or delete it. A folder's meta is `init.meta.json` inside the folder. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.appliesToNothing` [#meta-appliestonothing]

Warning. An `init.meta.json` sits in a folder that never becomes an instance, such as a routing folder or an invisible folder.

```
src/Combat/server/init.meta.json - warning: applies to nothing, because a routing folder never becomes an instance. Move the meta into the folder that should get it. (meta.appliesToNothing)
```

Move it into the feature folder that should get it. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.sharedWithScript` [#meta-sharedwithscript]

Warning. A folder's `init.meta.json` would apply to an instance that a script defines, because the folder and the script become the same instance. Rojo reads the script there, so the folder's meta applies to nothing.

```
src/Net/init.meta.json - warning: this folder shares "ServerScriptService/Net" with Net.server.luau, which is what Rojo reads there, so its meta applies to nothing. Put it in Net.meta.json beside the script, or turn the folder into an init folder. (meta.sharedWithScript)
```

Put the fields in the script's own meta file, as the message names, or make the folder an init folder. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.templatePath` [#meta-templatepath]

Warning. The template gives the folder's instance its own `$path`, so Rogen can't copy the folder's meta there.

```
src/Combat/init.meta.json - warning: the template gives "ServerScriptService/Combat" its own $path, so this meta isn't copied there. Set the fields on the template's node instead. (meta.templatePath)
```

Set `$className`, `$properties` or `$attributes` on the template's node. See [Template](/docs/v2/core-concepts/output#template).

### `meta.templateClass` [#meta-templateclass]

Warning. The template and a folder's meta give one instance different classes. The template wins.

```
src/Combat/init.meta.json - warning: the template makes "ServerScriptService/Combat" a Model, so its class is kept over this meta's Actor. (meta.templateClass)
```

Remove `$className` from the template's node, or `className` from the meta. See [Template](/docs/v2/core-concepts/output#template).

### `meta.sameNode` [#meta-samenode]

Error. Two folders in one root directory become the same instance, such as `src/Combat/` and `src/server/Combat/`, and both have an `init.meta.json`. Neither ranks above the other.

```
src/Combat/init.meta.json - error: src/Combat/init.meta.json and src/server/Combat/init.meta.json both apply to "ServerScriptService/Combat" from one root dir, and neither ranks above the other. Keep one of them. (meta.sameNode)
```

Merge them into one meta file. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.idOnSeveralNodes` [#meta-idonseveralnodes]

Error. A folder's meta sets an `id`, but its files are split across services, so the meta would be copied onto several instances. A Rojo ref id must be unique.

```
src/Combat/init.meta.json - error: id "combat" would be copied onto 2 instances (ServerScriptService/Combat, ReplicatedStorage/Combat), but a ref must be unique. Remove the id, or keep the folder's files in one service. (meta.idOnSeveralNodes)
```

Remove the `id`, or keep the folder's files in one service. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

### `meta.runContextOnModule` [#meta-runcontextonmodule]

Error. A meta file sets `RunContext` on a ModuleScript, which has none, so Rojo refuses the meta.

```
src/Net/init.meta.json - error: sets a RunContext, but init.luau is a ModuleScript, which has none, so Rojo refuses this meta. Name the script .server or .client to make it a Script, or remove RunContext. (meta.runContextOnModule)
```

Name the script `.server` or `.client`, or remove `RunContext`. See [Rojo's Script Suffixes](/docs/v2/core-concepts/routing#rojos-script-suffixes).

### `meta.classNameOnScript` [#meta-classnameonscript]

Error. A folder's `init.meta.json` sets `className`, but the folder holds an init script. The script is the folder's instance and decides its class (`init.luau` a ModuleScript, `init.server.luau` a Script, `init.client.luau` a LocalScript), so Rojo refuses the meta.

```
src/Net/init.meta.json - error: sets a className, but its folder holds an init script, which decides the class, so Rojo refuses this meta. Remove className, or rename the script to change its class. (meta.classNameOnScript)
```

Remove `className`, or name the init script for the class you want. See [Metadata Files](/docs/v2/core-concepts/project-layout#metadata-files).

## Scanning

### `scan.missingRootDir` [#scan-missingrootdir]

Warning. A directory in `rootDirs` doesn't exist, or is a file, so it contributes nothing.

```
later - warning: this root dir does not exist or is not a folder, so it contributes nothing. (scan.missingRootDir)
```

Create it, or remove it from `rootDirs`. The path is relative to the config that sets it. See [Configuration](/docs/v2/configuration#fields).

### `scan.extensionCase` [#scan-extensioncase]

Warning. A file's extension is written with capital letters, so Rojo doesn't read it and the file is not an instance. Rogen leaves it out of the tree as Rojo does.

```
src/Save.LUAU - warning: Rojo reads an extension only in lowercase, so it ignores this file. Rename it to Save.luau. (scan.extensionCase)
```

Rename the file as the message says. The same holds for `.JSON`, `.MODEL.JSON` and every other extension Rojo reads.

### `scan.nestedProject` [#scan-nestedproject]

Warning. A `default.project.json` lies inside a root dir. Rojo reads it as a nested project, so it becomes an instance named `default`, holding that project's tree. That is what a project file in a place's folder, such as `places/arena/default.project.json`, does by mistake: it was meant for the place, not for the game. Other project files are left alone, since a nested project with a name of its own is a thing Rojo supports.

```
places/arena/default.project.json - warning: Rojo reads this project file as a nested project, so it becomes ReplicatedStorage/Shared/default, holding that project's tree. A project file for the folder it lies in belongs outside the root dirs. (scan.nestedProject)
```

Move the file out of the root dirs. For a place, `rogen init <place>` copies the `<place>.project.json` beside the config to the place's template, which Rogen builds the project file from. If it is meant as a nested project, mount it in the template with a `$path` instead, which Rogen leaves to Rojo.

### `scan.rootDirNamedAfterKey` [#scan-rootdirnamedafterkey]

Warning. A root directory is named after a route key. Routing starts below a root directory, so its name routes nothing, and its files land wherever the `*` route sends them, or nowhere. One warning lists every such root dir.

```
default.rogen.json - warning: 2 root dirs are named after a route key, but routing starts below a root dir, so their names route nothing: (scan.rootDirNamedAfterKey)
  server ("server" route)
  client ("client" route)
Move them into one folder, such as src/server and src/client, and use "rootDirs": ["src"].
```

When the root dir has a parent inside the project (`src/server`), use the parent: `"rootDirs": ["src"]`, and the `server` folder routes. When it sits at the config's own folder, move the folders into one code folder first, since `"."` would scan the whole repo. The build still runs and writes. See [Routing](/docs/v2/core-concepts/routing).

### `scan.unresolvedLink` [#scan-unresolvedlink]

Warning. A symlink or junction inside a root directory points at nothing, or back at a directory that contains it.

```
src/Missing - warning: this link points at nothing, or back at a directory that contains it, so it contributes nothing. (scan.unresolvedLink)
```

Fix the link's target, or remove the link. See [Linked Directories](/docs/v2/core-concepts/project-layout#linked-directories).

## Output

### `output.sameOutFile` [#output-sameoutfile]

Error. Two configs in one run write the same project file.

```
game.project.json - error: "a.rogen.json" and "b.rogen.json" write the same file, game.project.json. Give each its own "outFile". (output.sameOutFile)
```

Give each config its own `outFile`. `outFile` isn't inherited through `extends`, so this usually comes from setting it by hand. See [Output](/docs/v2/core-concepts/output#output).

### `output.writeFailed` [#output-writefailed]

Error. The project file couldn't be written to disk. The message gives the reason without the system's error code.

```
default.project.json - error: the project file could not be written: permission denied. (output.writeFailed)
```

Check that the folder is writable and that no other program locks the file. Rogen creates the folder if it is missing. See [Output](/docs/v2/core-concepts/output#output).

### `output.nothingEmitted` [#output-nothingemitted]

Warning. The config has a `syncDir`, but nothing the compiler or processor should have written for a root directory exists there. Rojo would find nothing to sync.

When the sync directory itself doesn't exist, which is the case before the compiler or processor has run once, there is one warning for the config, whatever the number of root directories:

```
out - warning: the sync dir "out" doesn't exist yet, so Rojo has nothing to sync. Run your compiler or processor first. (output.nothingEmitted)
```

When it exists and a root directory's part of it is missing, the warning names that root directory, the nearest path that does exist, and where the output was found if it is rooted one level off:

```
src - warning: nothing emitted for root dir "src" exists under "out/src". The nearest path that exists is "out" — has your compiler or processor run? (output.nothingEmitted)
core - warning: nothing emitted for root dir "core" exists under "out/core". Found "out/Types.luau" — is the output of your compiler or processor rooted differently? (output.nothingEmitted)
```

Run the compiler or processor first. If the message finds the files elsewhere, point `syncDir` at the folder that mirrors the root directories. See [Sync Directory](/docs/v2/core-concepts/output#sync-directory).

### `output.metaNotSynced` [#output-metanotsynced]

Warning. `.meta.json` files have no copy in the sync directory, so Rojo doesn't apply them. Either the compiler didn't copy them, or a processor converted them: Darklua turns them into `.meta.lua`, which Rojo reads as a ModuleScript.

```
default.project.json - warning: 1 meta file has no copy under "dist" (src/Inventory/Save.meta.json), so Rojo doesn't apply it. The processor turned it into .meta.lua, which Rojo syncs as a ModuleScript instead of applying. Darklua converts every .meta.json this way. (output.metaNotSynced)
```

Copy the `.meta.json` files unchanged into the sync directory after the compiler or processor runs. See [Data Files](/docs/v2/setups/darklua#data-files).

### `output.dataFileConverted` [#output-datafileconverted]

Warning. A processor turned data files such as `.json` or `.txt` into Lua modules in the sync directory, so Rojo doesn't find them at the path the build expects.

```
default.project.json - warning: 1 data file was turned into a Lua module under "dist" (src/Inventory/Rates.json: expected "dist/Inventory/Rates.json", found "dist/Inventory/Rates.lua"). Rojo finds nothing at the path the build expects, or a ModuleScript where a folder collapses. Darklua converts .txt, .json, .toml, .yaml and .yml files this way, and has no option to copy them. Copy the data files unchanged into the sync dir after it runs, or require them as modules. (output.dataFileConverted)
```

Copy the data files unchanged into the sync directory after the processor runs, or require them as modules. See [Data Files](/docs/v2/setups/darklua#data-files).

## Init

### `init.configExists` [#init-configexists]

Error. The config `init` would write already exists, and `init` never overwrites one. A run that can't ask (no terminal, `-y`, `--json`, CI or an agent) adds a place beside an existing `default.rogen.json`, which needs a name.

```
default.rogen.json - error: this config already exists. To add a place beside it, run 'rogen init <name>'. (init.configExists)
```

Give a new name, such as `rogen init lobby`, or delete the config to start over. See [CLI](/docs/v2/cli).

### `init.fileExists` [#init-fileexists]

Error. A file `init` would write, such as the template or a roblox-ts `tsconfig`, already exists.

```
template.project.json - error: this file already exists, and init never overwrites one. Pick another name. (init.fileExists)
```

Pick another config name, or move the file out of the way. See [CLI](/docs/v2/cli).

### `init.invalidPlaceFolder` [#init-invalidplacefolder]

Error. The folder given for a new place can't hold it: it overlaps one of `default`'s root directories, is outside the project, or isn't a relative path.

```
src/lobby - error: src/lobby overlaps src, one of default's root dirs. Pick a folder outside it. (init.invalidPlaceFolder)
```

Pick a folder of its own, such as `places/lobby`. See [Multi-Place](/docs/v2/setups/multi-place).

### `init.templateUnreadable` [#init-templateunreadable]

Error. `init` found a hand-written project file to keep as the template, but couldn't read it to copy it.

```
default.project.json - error: couldn't read this file to copy it: permission denied. (init.templateUnreadable)
default.project.json - error: this file does not exist, so it can't be copied. (init.templateUnreadable)
```

Fix the file's permissions, or move it out of the way. See [Template](/docs/v2/core-concepts/output#template).

## Serve

### `serve.noServer` [#serve-noserver]

Error. `rogen serve` found no sync server: neither Rojo nor Argon is pinned in a `rokit.toml`, `aftman.toml` or `foreman.toml` in the folder or above, and neither is on the PATH. With `--server`, or a config's `server`, only that server counts.

```
default.rogen.json - error: No Rojo or Argon to serve with: none is pinned in a toolchain file here or above, or on the PATH. Run 'rokit add rojo-rbx/rojo', then 'rojo plugin install' to install its Studio plugin. (serve.noServer)
```

Pin the server with your toolchain manager (`rokit add rojo-rbx/rojo`, or `aftman add` in an Aftman project; Foreman has no add command, so add it to `foreman.toml` by hand), then install its Studio plugin with `rojo plugin install`. Rogen never installs anything. See [CLI](/docs/v2/cli#serve).

### `serve.notInstalled` [#serve-notinstalled]

Error. A toolchain file pins the server, but it isn't installed, so its command isn't on the PATH.

```
rokit.toml - error: rokit.toml pins Rojo as rojo, but it isn't installed. Run 'rokit install'. (serve.notInstalled)
```

Run the manager's install command: `rokit install`, `aftman install` or `foreman install`. See [CLI](/docs/v2/cli#serve).

### `serve.serverFailed` [#serve-serverfailed]

Error. Rogen runs `<tool> --version` before it builds, and that failed, so the server can't start. The message ends with the first line the server printed. A toolchain shim on the PATH whose project doesn't pin the tool fails this way, and then the message adds the command that pins it.

```
default.rogen.json - error: 'rojo --version' failed, so Rojo can't start: Failed to find tool 'rojo' in any project manifest file. If Rojo isn't pinned yet, run 'rokit add rojo-rbx/rojo'. (serve.serverFailed)
```

Pin the tool, or fix the install the quoted line points at. Running `rojo --version` (or `argon --version`) yourself shows the full output. See [CLI](/docs/v2/cli#serve).

### `serve.portTaken` [#serve-porttaken]

Error. Another program holds the port a config would be served on. When it's a Rojo or Argon server, the message names the project it serves. A server that already serves the same project isn't an error: `rogen serve` leaves it running, and builds for it when no `rogen serve` started it. It is one when another config here has the same project name and no `rogen serve` started the server, since Rogen can't tell which config it serves: stop that server and run `rogen serve` again.

```
default.rogen.json - error: Port 34872 is taken by Rojo serving shop, so default can't be served there. Give default a template with its own servePort, or run 'rogen serve default -- --port 34873'. (serve.portTaken)
```

Stop what holds the port, give the config its own `servePort` in its template, or pass a free port after `--`. With `--json`, `fixes` holds the command with a free port Rogen found. See [CLI](/docs/v2/cli#serve).

### `serve.otherServer` [#serve-otherserver]

Error. While `rogen serve` runs, a config that is served now names a `server` other than the one this serve runs: a config was added, or an edit changed a `server` field. One serve runs one server, so the config isn't served with the other one, and the servers already running go on. It is said once for a config, again if the config stops naming another server and then does again. `--server` ends the question, since it picks the server over every config's field.

```
lobby.rogen.json - error: lobby names "server": "argon", but this serve runs rojo, and one serve runs one server. Restart it to serve with argon, or serve lobby on its own, as 'rogen serve lobby'. (serve.otherServer)
```

Restart `rogen serve` to serve with the new server, or serve the config on its own. At startup the same disagreement stops the serve instead, with exit 2. See [CLI](/docs/v2/cli#serve).

### `serve.serverExited` [#serve-serverexited]

Error. A server stopped on its own with a non-zero exit code, or couldn't be started. `rogen serve` then stops and exits with the server's code (1 when it has none).

```
default.rogen.json - error: Rojo stopped serving default with exit code 1; see what it said above. (serve.serverExited)
```

Read what the server said just above it, which usually says why. When it said nothing, as when it was killed, the message ends `without saying why`. See [CLI](/docs/v2/cli#serve).

## Migration

### `legacy.config` [#legacy-config]

Warning. A config that failed to load has fields from Rogen 1, such as `source`, `aliases` or `modes`. v2 doesn't read v1 configs.

```
default.rogen.json - warning: this looks like a config for Rogen 1, which v2 doesn't read. See https://rogen-playfully.vercel.app/docs/v2/migrating-from-v1 to migrate it. (legacy.config)
```

Rewrite the config in v2's shape. See [Migrating from v1](/docs/v2/migrating-from-v1).
