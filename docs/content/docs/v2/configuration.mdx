A **config** is a `<name>.rogen.json` file that describes one tree and the project file it builds. When you don't name one, Rogen uses `default.rogen.json`. Comments and trailing commas are fine.

There are nine fields, none nested more than one level. Unknown keys and wrong types are errors.

---

## Fields

| Field | Default | What it does |
|---|---|---|
| `$schema` | none | The published JSON schema, for editor validation and completion. Not inherited. |
| `extends` | none | Another `*.rogen.json` to inherit from. See [Extending Configs](#extending-configs). |
| `rootDirs` | `["src"]` | The directories to scan and watch. They merge into one tree, and the later one wins a clash. |
| `routes` | none | Route keys and their targets, like `"Service/Folder"`. Required. See [Routing](/docs/v2/core-concepts/routing). |
| `variants` | `{}` | Every variant the project uses, and whether it's on. See [Variants](/docs/v2/core-concepts/variants). |
| `exclude` | `[]` | Globs for files that are never built. |
| `template` | none | A Rojo project file to merge the tree into. See [Template](/docs/v2/core-concepts/output#template). |
| `syncDir` | none | The folder Rojo syncs from, usually your compiler's output. See [Sync Directory](/docs/v2/core-concepts/output#sync-directory). |
| `outFile` | `<name>.project.json` | The project file to write. Not inherited. See [Output](/docs/v2/core-concepts/output#output). |

All paths in a config are relative to the config's folder, while paths on the command line are relative to the working directory.

---

## Extending Configs

Use `extends` when a config is a small variation on another: a second place, other variants, or the same tree rendered from another folder. Rogen has no profiles; each file is one tree and one output.

```json title="lobby.rogen.json"
{
	"extends": "./default.rogen.json",
	"rootDirs": ["src", "places/lobby"]
}
```

| Kind | Fields | Behavior |
|---|---|---|
| Map | `routes`, `variants` | merged key by key; the child wins |
| List | `rootDirs`, `exclude` | the child replaces |
| String | `syncDir`, `template` | the child replaces |
| Not inherited | `outFile`, `$schema` | always the config's own value, or its default |

A child can add or replace values but never remove them. To drop something, flip the chain so the config without it is the parent, or `exclude` the files. Relative paths resolve against the file that wrote them. A cycle is an error that shows the loop.

`rogen list --json` prints a config fully resolved, with defaults filled in and paths made absolute.

## Finding Configs

`rogen build lobby` reads `lobby.rogen.json`, and `rogen build places/lobby.rogen.json` reads that file: a name with a `/` or ending in `.json` is a path. With no name, Rogen reads every `*.rogen.json` in the folder.

A file called just `.rogen.json` is an error, since every config needs a name. That was v1's file name, so Rogen also links to [Migrating from v1](/docs/v2/migrating-from-v1).

## Diagnostics

Every diagnostic points at the problem:

```
lobby.rogen.json:7:3 - error: unknown field "outDir".
```

Errors stop the build. Warnings don't, and the build still exits with 0. You'll get warnings for:

- files that match no route,
- names that look like a route key or variant but aren't,
- server code that ships to clients,
- scripts placed where they'll never run,
- an empty sync directory or a missing root directory,
- instances that clash with the template.

[Diagnostics](/docs/v2/diagnostics) explains every code, with an example and the fix.
