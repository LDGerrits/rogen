v2 reads configs and file names differently, so a v1 project needs a new config and some renamed files. `rogen init` makes both: it reads your v1 config and writes a v2 config that puts every file where v1 did.

## Why v2 Changed

v1 had many small rules that could disagree, and each problem got its own switch or marker file. v2 has three rules that hold everywhere:

- **The outermost route governs.** In v1 the deepest rule won, so `ReplicatedFirst/main.client.luau` went to `StarterPlayerScripts`, and holding a folder still took `.structure` or `.sync`. In v2 a folder's route covers everything inside it.
- **Only `@` routes a name.** v1 read routes from prefixes and suffixes, so `HttpClient.luau` went to the client as `Http`. In v2 only a name like `Save@server.luau` routes, and Rojo's `.server` and `.client` keep their meaning.
- **You write every route.** v1's keywords and wrapper folders were built in, and unmatched files went to `ReplicatedStorage`. In v2 only the routes you declare exist. `rogen init` declares a `*` route for the files that match none, and without it such a file is left out with a warning.

## Move a Project to v2

<Steps>

<Step>
### Commit Your Work

`rogen init` renames files, so start from a clean work tree. Then `git diff` shows everything it changed, and `git checkout .` takes it back.

</Step>

<Step>
### Run `rogen init`

[Install v2](/docs/v2/installation) and run `rogen init` in the folder that holds `.rogen.json`. To see the plan first, run `rogen init --dry-run`.

`init` finds the v1 config and migrates it:

- It writes a config for each mode that ran: `default.rogen.json` for the project v1 wrote to `default.project.json`, and `build.rogen.json` for a Darklua mode that wrote `build.project.json`. A mode whose `build` folder isn't the source folder, such as roblox-ts's `out`, gets it as its `compiledPath`.
- It takes the tree from the config's `project`, not from the `default.project.json` that v1 generated. From then on, `rogen write` writes that file.
- It writes routes that keep v1's wrapper folders, such as `"Server": "ServerScriptService/server"`, with your `casing`, `unwrap` and `aliases`. Your scripts land where v1 put them, so your requires keep working.
- It renames each file that v1 routed by a word in its name to v2's `@` form, such as `Combat_Server.luau` to `Combat@Server.luau`, and each marker file such as `.server` to `@Server`. The instance names stay the same.
- It renames `.rogen.json` to `.rogen.json.v1`, so that no command reads it.

</Step>

<Step>
### Fix What `init` Couldn't Carry Over

`init` warns about each thing it leaves for you, with the file and what to do. These are [tags](#tags), the `.structure`, `.unwrap` and `.sync` marker files, roblox-ts files that v1 routed by their names, and files that v1 placed by the deepest rule. The warnings are listed under [Migration](/docs/v2/diagnostics#migration) on the diagnostics page.

</Step>

<Step>
### Run `rogen check`

```bash
rogen check
```

The step is done when `rogen check` prints nothing.

</Step>

<Step>
### Compare With Your v1 Build

Run `rogen serve` and compare Studio's Explorer with your v1 build. When every script sits where it did, delete `.rogen.json.v1`.

</Step>

</Steps>

If you ran an earlier v2's `rogen init` and it lifted the tree that v1 generated, start again: delete `default.rogen.json`, rename `.rogen.json.v1` back to `.rogen.json`, and run `rogen init`.

## What Replaces Each v1 Feature

| v1 | v2 |
|---|---|
| `source`, `-s` | `sourcePaths` |
| `aliases`, built-in keywords | `routes` |
| `casing`, `unwrap`, `.unwrap` | the route's target path |
| `verbatim`, `.verbatim` | not needed |
| keywords in names | `@key` or a routing folder. See [Names](#names) |
| `tags`, `-t` | an overlay source path. See [Tags](#tags) |
| modes, `-m` | a config for each mode, named after its `output`, such as `build.rogen.json` |
| a mode's `build`, `-b` | `compiledPath` |
| a mode's `output`, `-o` | none. `rogen build -o` now builds a place |
| `project`, `template`, `-p` | `tree` in the config |
| `.structure` | a marker file such as `@shared` |
| `.sync` | a `$path` node in the `tree` |
| `^` at the service's root | `^` at the route's target |
| several places from one config | a config per place |

### Names

`rogen init` renames these for you:

```
v1: src/Combat/server_Combat.luau     v2: src/Combat/Combat@Server.luau
v1: src/Combat/Combat_Server.luau     v2: src/Combat/Combat@Server.luau
v1: src/Combat/Types.shared.luau      v2: src/Combat/Types@Shared.luau
v1: src/Combat/Hud.client.luau        v2: unchanged
v1: src/Combat/.server                v2: src/Combat/@Server
```

A roblox-ts file keeps its name, since renaming it breaks the imports of it. Rename it yourself and update the imports.

### Tags

Few projects used tags. Move a file that v1 built only under a tag into a folder of its own, and list that folder as a later source path, where its file replaces the one at the same path:

```
v1: src/Teleport/TeleportDev.luau (tag dev)
v2: dev/Teleport/Teleport.luau (the dev source path)
```

Write a second config without it, such as `release.rogen.json` with `"sourcePaths": ["src"]` and its own `name`.
