v2 reads neither v1's config nor most of v1's file names. While a v1 config is in the folder, every command stops with [`legacy.config`](/docs/v2/diagnostics#legacy-config). There is no `migrate` command. You write a new config with `rogen init`, then rename files until `rogen check` is clean.

## Why v2 Changed

v1 placed a file by many small rules that could disagree, often without a warning, and each problem got its own switch or marker file. v2 replaces them with rules that hold everywhere.

**The outermost route governs.** In v1 the deepest rule won, so a suffix could override its folder: `ReplicatedFirst/main.client.luau` went to `StarterPlayerScripts`. Because any deeper rule could move a file, v1 needed the `.structure` and `.sync` markers to hold a folder still. In v2 a folder's route covers everything inside it, with no marker, and the routes below it are ignored.

**Only `@` routes a name.** v1 read routes from prefixes and from suffixes after almost any separator, so ordinary names matched by accident: `HttpClient.luau` went to the client as `Http`. Keeping a keyword in a name took `verbatim` or a `.verbatim` marker. In v2 a name routes only with `@`, as in `Save@server.luau`: this name, at that place. Rojo's `.server` and `.client` keep their meaning.

**You write every route.** v1's keywords and wrapper folders were built in, so changing them took `aliases`, `casing`, `unwrap` and `.unwrap`. Files that matched nothing went to `ReplicatedStorage`, where server code could reach clients. In v2 a route is a key and a target path that you write, such as `"Shared": "ReplicatedStorage/Shared"`, and the target can be any path under a service that Rojo writes to. Only declared routes exist, and a file that matches none is left out with a warning.

The config itself is a Rojo project file with three more keys, so Rojo's documentation covers the rest of it.

## Move a Project to v2

<Steps>

<Step>
### Set the v1 Config Aside

Rename every v1 config in the project folder: `.rogen.json`, and any other `*.rogen.json` that v1 read. v2 then skips it, and you keep it to compare against:

```bash
mv .rogen.json .rogen.json.v1
```

</Step>

<Step>
### Run `rogen init`

[Install v2](/docs/v2/installation), then run `init` in the project folder:

```bash
rogen init
```

It writes `default.rogen.json`. If you have a `default.project.json`, `init` lifts its keys into `default.rogen.json`. Rogen writes `default.project.json` from then on, so `init` prints `git rm --cached default.project.json` to stop git from tracking it.

</Step>

<Step>
### Match Your Old Paths

v1 put a wrapper folder under each service, such as `ServerScriptService/server`. In v2, a route's target is the whole path. To keep your v1 `require` paths, write the wrappers into the targets:

```json title="default.rogen.json"
{
	"routes": {
		"server": "ServerScriptService/server",
		"client": "StarterPlayer/StarterPlayerScripts/client",
		"shared": "ReplicatedStorage/shared",
		"*": "ReplicatedStorage/shared"
	}
}
```

If you used `unwrap`, leave the wrapper out. If you used `casing: "PascalCase"`, capitalise it. Add each of your `aliases` as a route.

</Step>

<Step>
### Rename Files Until `rogen check` Is Clean

```bash
rogen check
```

Each v1 file name that no longer routes gets a warning that names the fix, such as [`route.unrouted`](/docs/v2/diagnostics#route-unrouted) or [`route.dotRoute`](/docs/v2/diagnostics#route-dotroute). `--json` lists the renames. Use the [table below](#what-replaces-each-v1-feature) to rename or move each file, and run `rogen write` when `check` says to. The step is done when `rogen check` prints nothing and exits 0.

Files that v1 built only under a tag raise no warning. Move them as [Tags](#tags) describes.

</Step>

<Step>
### Compare With Your v1 Build

Serve the project with `rogen serve`, and compare Studio's Explorer with your v1 build. When every script sits at the same path as before, delete `.rogen.json.v1`.

</Step>

</Steps>

## What Replaces Each v1 Feature

| v1 | v2 |
|---|---|
| `.rogen.json` | `default.rogen.json`, which `init` writes |
| `source`, `-s` | `sourcePaths` |
| `aliases`, built-in service keywords | `routes`. Only declared keys route |
| `casing`, `unwrap`, `.unwrap` | the route's target, written as a path |
| `verbatim`, `.verbatim` | nothing. v2 keeps every name as it is |
| prefix and suffix keywords | `@key` at the end of the name, or a routing folder. See [Names](#names) |
| `tags`, `-t` | an overlay source path. See [Tags](#tags) |
| modes, `-m` | a second complete config: `dist.rogen.json` writes `dist.project.json`, and `rogen serve dist` serves it |
| a mode's `build`, `-b` | `compiledPath` |
| a mode's `output`, `-o` | none. Rogen writes the project file beside its config. `rogen build -o game.rbxl` builds a place with Rojo |
| `project`, `template`, `-p` | `tree`, written in `default.rogen.json`. `-p` now builds a plugin: `rogen build -p Tool.rbxm` |
| `.structure` | a marker file in the folder, such as `@shared`. It governs everything below it |
| `.sync` | a plain `$path` node in the `tree`. Rogen leaves that folder alone |
| `^` on a file | an invisible folder: `src/(Physics)/Server/CollisionService.luau` lands at `ServerScriptService/CollisionService` |
| the deepest rule wins | the outermost [route governs](/docs/v2/core-concepts/routing#the-governing-route). `src/ReplicatedFirst/main.client.luau` now lands in `ReplicatedFirst`, not in the client folder |
| unmatched files go to `ReplicatedStorage` | a `"*"` route that you declare. Without one, unmatched files are left out |
| several places from one config | a folder per place, each with its own `default.rogen.json`. Shared code is a plain folder that each place lists in `sourcePaths` |

### Names

v2 routes by name only with `@key` at the end of the name, or with Rojo's `.server` and `.client` on a script. A [routing folder](/docs/v2/core-concepts/routing#routing-folders) is often the better choice:

```
v1: src/Combat/server_Combat.luau     v2: src/Combat/Server/Combat.luau
v1: src/Combat/Combat_Server.luau     v2: src/Combat/Combat@server.luau
v1: src/Combat/CombatServer.luau      v2: src/Combat/Combat@server.luau
v1: src/Combat/Types.shared.luau      v2: src/Combat/Types@shared.luau
v1: src/Combat/Hud.client.luau        v2: unchanged
v1: src/Combat/Gun.server.rbxm        v2: src/Combat/Gun@server.rbxm
v1: src/Combat/.server                v2: src/Combat/@server
```

Marker files, models and data files take `@` too, because Rojo reads `.server` only on a script.

### Tags

A file that v1 built only while a tag was on moves to an **overlay source path**: a folder of its own that only the configs that want it list. A later source path wins a clash, and a file with no twin in an earlier source path is added. List the overlay in `default.rogen.json` if your everyday build wants it. Then write a second complete config, such as `release.rogen.json`, without it:

```
v1: src/Teleport/Teleport.luau, src/Teleport/TeleportDev.luau (tag dev)
v2: src/Teleport/Teleport.luau, dev/Teleport/Teleport.luau (the dev source path)
```

```json title="default.rogen.json"
{
	"name": "Game",
	"sourcePaths": ["src", "dev"],
	"routes": { "server": "ServerScriptService", "*": "ReplicatedStorage" }
}
```

```json title="release.rogen.json"
{
	"name": "Game",
	"sourcePaths": ["src"],
	"routes": { "server": "ServerScriptService", "*": "ReplicatedStorage" }
}
```

`rogen write` writes `default.project.json` with the overlay and `release.project.json` without it. The second config needs its own `name`, because Rojo crashes on a project file other than `default.project.json` that has none. To leave a file out of every build, such as a spec, list it in `globIgnorePaths`.

<Callout type="warn" title="Old tag files ship">
	v1 left `TeleportDev.luau` out when `dev` was off. In v2 it is an ordinary file that ships in every build, and `Teleport.dev.luau` is just a name. Move these files before your first v2 release.
</Callout>
