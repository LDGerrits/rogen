A diagnostic reads `file:line:col - severity: message (code)`:

```
src/Greeter/Save@sever.luau - warning: did you mean "@Server"? (route.strayAt)
```

An error stops Rogen from writing the project file. A warning doesn't, but it still names something to fix. `rogen help <code>` prints what a code means, and [Diagnostics](/docs/v2/diagnostics) has a section for every code.

## Exit Codes

| Code | When |
|---|---|
| 0 | The command did what it was asked. Warnings don't change it. |
| 1 | The project has errors. `rogen check` also exits 1 on any warning. |
| 2 | The command line is wrong. |

## JSON

With `--json`, a command prints one JSON document on one line of stdout and nothing else. Match a diagnostic on its `code`, not on its `message`. `rogen help <command> --json` gives the shape of a command's document, and `rogen doc output` explains every key.

## Running in CI

`rogen check` writes nothing and exits 1 on any diagnostic. Under GitHub Actions, it also shows each diagnostic on the file in the pull request. This workflow installs the tools that `rokit.toml` pins, which must include Rogen, then checks and builds the game:

```yaml title=".github/workflows/ci.yml"
name: CI
on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: CompeyDev/setup-rokit@v0.2.1
      - run: rogen check
      - run: rogen build -o game.rbxl
```
