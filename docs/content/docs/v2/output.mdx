## Diagnostics

A diagnostic reads `file:line:col - severity: message (code)`:

```
default.rogen.json:5:3 - error: "route" is not a Rojo key and not Rogen's, and Rojo rejects a project file with a key it doesn't know. Did you mean "routes"? (config.unknownField)
src/Greeter/Save@sever.luau - warning: did you mean "@Server"? (route.strayAt)
```

An error stops Rogen from writing the project file. A warning doesn't, but it still names something to fix. `rogen help route.strayAt` prints what a code means, and [Diagnostics](/docs/v2/diagnostics) has a section for every code.

Results go to stdout. Warnings, errors and `--verbose` lines go to stderr, except in `rogen check`, whose diagnostics are its result. Rojo's commands print one line for each thing they did, such as `Wrote default.project.json.` and `Built game.rbxl.`, on the stream where Rojo prints its own.

## Exit Codes

| Code | When |
|---|---|
| 0 | The command did what it was asked. Warnings don't change it. |
| 1 | The project has errors: an invalid config, a failed build or write, or a cancelled `init`. `rogen check` also exits 1 on any warning. |
| 2 | The command line is wrong, such as an unknown command or option. |
| 129, 130, 143 | `serve` or a `--watch` command stopped with SIGHUP, Ctrl+C or SIGTERM. |

`serve`, `build --watch` and `sourcemap --watch` exit 1 when Rojo crashes again right after Rogen restarted it, or stops watching on its own.

## JSON

With `--json`, a command prints one JSON document on one line of stdout and nothing else, whatever the exit code:

```
$ rogen check --json
{"diagnostics":[{"file":"/home/me/game/src/Greeter/Save@sever.luau","severity":"warning","code":"route.strayAt","message":"did you mean \"@Server\"?","url":"https://rogen-roblox.vercel.app/docs/v2/diagnostics#route-strayat","fixes":[{"rename":{"from":"/home/me/game/src/Greeter/Save@sever.luau","to":"/home/me/game/src/Greeter/Save@Server.luau"}}]}]}
```

Match a diagnostic on its `code`, not on its `message`. `serve --json`, `build --watch --json` and `sourcemap --watch --json` print one JSON object per line for as long as they run. `rogen help <command> --json` gives the shape of a command's document, and `rogen doc output` explains every key.

## Running in CI

Under GitHub Actions, `build` and `check` also write each diagnostic as a workflow command, so GitHub shows it on the file in the pull request:

```
::warning file=src/Greeter/Save@sever.luau,title=route.strayAt::did you mean "@Server"?
```

`rogen check` writes nothing and exits 1 on any diagnostic, so it fails the job on a warning that `rogen build` lets through. This workflow installs the tools that `rokit.toml` pins, which must include Rogen, then checks and builds the game:

```yaml title=".github/workflows/ci.yml"
name: CI
on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: CompeyDev/setup-rokit@v0.2.1
      - run: rogen check
      - run: rogen build -o game.rbxl
```

## Update Notice

When a newer release is out, Rogen prints one line on stderr after the command, once a day, with the update command for the way you installed it. It never prints the line under CI, in a pipe, or with `--json`. To turn the check off, set `ROGEN_NO_UPDATE_CHECK=1`.
