A **variant** is an alternative version of a file that lives right next to it. When `mock` is on, `Analytics.mock.luau` *becomes* `Analytics`. When it's off, the file is left out. (If you only want to leave files out, use [`exclude`](/docs/v2/core-concepts/project-layout#excluding-files).)

Variants are independent switches: any number can be on, and each is off unless `--variant` turns it on.

## Declaring Variants

`variants` is a list of names:

```json title="default.rogen.json"
{
	"variants": ["mock", "debug", "halloween"]
}
```

A declared variant is off unless `--variant` turns it on. A variant that's on is **active**, and one that's off is **dormant**. Files of a dormant variant are **pruned** from the output. A variant can't share its name with a route key.

There is no default per variant, so the command line alone decides which variants a build has on. A dot part that matches no declared variant, like the `prod` in `Service.prod.luau`, is just part of the name.

<Callout type="warn" title="Variants used to be a map">
	`"variants": { "mock": false }` is a config error that prints the list form. Write `"variants": ["mock"]`, and pass `--variant mock` to turn it on.
</Callout>

## Marking Files

Variants are marked the same three ways as [routes](/docs/v2/core-concepts/routing), with the same matching rules. The only difference is the sign: a route is written with `@` and a variant with a dot, in a marker file as in a suffix.

| | Route key | Variant |
|---|---|---|
| **Folder** named after it (`server/`, `mock/`, `(mock)/`) | removed from the tree | removed from the tree |
| **Marker file** (`@server`, `.mock`) | applies below; the folder keeps its name | applies below; the folder keeps its name |
| **Suffix** (`Combat@server`, `Analytics.mock`) | stripped when governing | stripped when active |

Since variants are declared, other dotted names like `Button.spec.luau` are left alone. Rogen only speaks up when a dot is followed by one letter off a variant, like `Analytics.mok.luau`, a `.mok/` folder or a `.mok` marker file. Only the dot counts: `AnalyticsMock.luau` is an ordinary name.

Put the variant before an `@` route and Rojo's suffix last: `Analytics.mock@server.luau`, `Save.mock.server.luau`. Rogen warns about `Save.server.mock.luau`, which Rojo would read as a `ModuleScript`.

Rogen reads names the same way in every build. Where a file lands never depends on which variants are on, and a mistake in a name is reported even while its variant is off, so a build with every variant off still catches it.

## Variant Folders

A folder named after a variant never appears in the tree. When the variant is active, its contents move up into the parent; when it's dormant, the whole folder is pruned. That lets you swap implementations without touching a `require`:

```
src/Analytics/dev/Service.luau   ->  Analytics/Service   (dev active)
src/Analytics/prod/Service.luau  ->  pruned              (prod dormant)
```

## Precedence

Within one root directory, the files that land on one instance compete, and the active file with the most variants wins quietly. It has to have every variant the others have: a plain file has none, so any variant replaces it, and `mock/Service.dev.luau` (mock and dev) replaces `mock/Service.luau` (mock). Two active files where neither has all of the other's variants, like `Service.mock.luau` and `Service.dev.luau`, are an error. Two plain files get a warning. Across root directories, the last one wins.

Nesting means "and": `mock/dev/Service.luau` is used only while both `mock` and `dev` are on.

A variant has to land where the plain file beside it does, or it would ship next to it instead of replacing it. `Analytics.mock@server.luau` beside `Analytics.luau` is an error, as is a `^` or a route marker that only one of them has. Route them the same way: `Analytics.mock@server.luau` beside `Analytics@server.luau`.

Variants are independent switches, but a set of alternatives like `dev/Service.luau` and `prod/Service.luau` is meant to have one of them on. With both off, `Service` is missing and whatever requires it fails in Studio, so Rogen warns:

```
default.rogen.json - warning: 1 instance is missing, because none of the variants that give it is on: (variant.noneActive)
  ReplicatedStorage/shared/Analytics/Service (dev, prod)
Turn one of its variants on, or add a plain file.
```

A lone variant, like `DebugPanel.dev.luau`, doesn't warn: disappearing when it's off is the point.

## Conflicts

Some variants must never be on together, like two seasonal events. List them in `conflicts`, as groups of which at most one may be on:

```json title="default.rogen.json"
{
	"variants": ["halloween", "christmas"],
	"conflicts": [["halloween", "christmas"]]
}
```

Two on at once is an error, and the message names `--variant` as the source:

```bash
rogen build --variant halloween --variant christmas       # error: they conflict
rogen build --variant christmas
```

A variant may sit in several groups, and each is checked. Under [`extends`](/docs/v2/configuration#extending-configs) the groups add up, so a place can add a group but never dissolve a shared one.

## Turning Variants On and Off

Both flags can be repeated, and `--no-variant` applies last:

```bash
rogen build --variant halloween --no-variant mock
```

A variant is on when `--variant` adds it, and off otherwise or when `--no-variant` removes it. Nothing else turns one on.

To keep a build around as a second output with other files left out, add a config that extends the first and adds an `exclude`. Put it in a folder of its own, since beside `default.rogen.json` it would take the place of the config `rogen serve` syncs to Studio. `rogen build release/release.rogen.json` then writes `release/release.project.json`, for example without the specs:

```json title="release/release.rogen.json"
{
	"extends": "../default.rogen.json",
	"exclude": ["../**/*.spec.luau"]
}
```

A glob is relative to the file that wrote it, so this one starts with `..` to reach the files of the config above it.

<Callout type="info" title="Not Roblox's Tags">
	Variants used to be called tags, and were renamed to avoid confusion with Roblox's CollectionService Tags.
</Callout>
