A **variant** is another version of a file that sits right next to it. `Analytics.mock.luau` is a variant of `Analytics`: when the `mock` variant is on, it *becomes* `Analytics`, and when it's off, the file is left out.

That's all variants are for. To leave files out without replacing them, use [`exclude`](/docs/v2/configuration#exclude).

## Declaring Variants

List every variant your project uses in the config's `variants` map, along with whether it's on:

```json title="default.rogen.json"
{
	"variants": {
		"mock": false,
		"dev": false
	}
}
```

A variant that's on for the current build is **active**, and one that's off is **dormant**. A file of a dormant variant is **pruned**, meaning it's left out of the output.

A variant can't share its name with a route key, but it can share one with a config.

## Marking Files

You mark a variant the same three ways you [route](/docs/v2/core-concepts/routing) a file, with the same matching rules. The only difference is the suffix: a route uses `@`, and a variant uses a dot.

| | Route key | Variant |
|---|---|---|
| **Folder** named after it (`server/`, `mock/`, `(mock)/`) | removed from the tree | removed from the tree |
| **Marker file** (`.server`, `.mock`) | applies below; the folder keeps its name | applies below; the folder keeps its name |
| **Suffix** (`Combat@server`, `Analytics.mock`) | stripped when governing | stripped when active |

Since the whole set is declared, Rogen can tell a variant from an ordinary dotted name. `Button.spec.luau` and `Button.story.luau` stay as they are unless you declare `spec` or `story`. Rogen only speaks up when a dotted part is one letter off a declared variant, so `Analytics.mok.luau` gets `did you mean ".mock" for ".mok"?`, once per build.

The dot is the only form. `Analytics-mock.luau`, `Analytics_mock.luau` and `AnalyticsMock.luau` are ordinary names, and a dormant `mock` doesn't prune them.

A variant combines with an `@` route in either order. Write the variant first and the route last, like `first.last@domain`: `Analytics.mock@server.luau`. Rojo's `.server` or `.client` always goes at the very end. `Save.mock.server.luau` is a `Script`, while `Save.server.mock.luau` is a `ModuleScript`, so Rogen warns about that one.

## Variant Folders

A folder named after a declared variant is a **variant folder**. Like a routing folder, it never shows up in the tree. When the variant is active, the folder is removed and its contents move up into the parent. When it's dormant, the whole folder is pruned.

That lets you swap implementations at build time without touching a single `require`:

```
src/Analytics/dev/Service.luau   ->  Analytics/Service   (dev active: dev/ removed)
src/Analytics/prod/Service.luau  ->  pruned              (prod dormant)
```

Both files target the same instance, and the active variant decides which one gets there. `(mock)/` works as well, since parentheses come off before names are matched.

## Precedence

Within one root directory:

1. A variant quietly beats the plain file with the same instance name. That's the point of variants, not a clash.
2. Two active variants that claim the same instance name are an error, and Rogen names both files.
3. Two plain files with the same instance name get a warning.
4. Across root directories, the last one wins, after the rules above are applied.

## Turning Variants On and Off

The config says whether a variant is on, and the CLI can override that for a single run:

```bash
rogen build --variant mock
rogen build --variant mock --no-variant dev
```

You can repeat both flags, and naming a variant that none of the built configs declare is an error. See the [CLI reference](/docs/v2/cli#options).

To keep a combination around, add a second config that extends the first and flips the variant:

```json title="mocked.rogen.json"
{
	"extends": "./default.rogen.json",
	"variants": { "mock": true }
}
```

`rogen build mocked` then writes `mocked.project.json`.
