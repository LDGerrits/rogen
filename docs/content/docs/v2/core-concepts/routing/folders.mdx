---
title: Routing Folders
description: Keep all of a feature's code in one folder
---

A folder named after a route key sends everything inside it to that route's target. Give each feature a folder, and inside it one routing folder for each side it runs on:

<RouteFigure
	disk={`
  src/
    Combat/
      Client/
        CombatController.luau
      Server/
        DamageService.luau
      Shared/
        Weapons.luau
    Data/
      Server/
        PlayerData.luau
    Shop/
      Client/
        ShopUi.luau
      Shared/
        Prices.luau
`}
	studio={`
  ReplicatedStorage
    Shared/
      Combat/
        Weapons
      Shop/
        Prices
  ServerScriptService
    Combat/
      DamageService
    Data/
      PlayerData
  StarterPlayer
    StarterPlayerScripts
      Combat/
        CombatController
      Shop/
        ShopUi
`}
/>

The routing folders disappear, and each feature folder appears under every service it runs in. `Data` runs only on the server, so it has only a `Server/` folder.

Code requires the other parts by their path in the game, as in `require(ReplicatedStorage.Shared.Combat.Weapons)`.

## Spelling It `@Server`

A routing folder can also be named `@Server/`. It routes the same as `Server/`, and the `@` shows that the folder is a route, not a feature named Server.

The two differ only inside a route's files, where `Server/` is a plain folder that keeps its name. Under `Shared/`, it ships to clients with a [`route.serverCodeShipped`](/docs/v2/diagnostics#route-servercodeshipped) warning. `@Server/` is an error there instead ([`route.ignoredAt`](/docs/v2/diagnostics#route-ignoredat)), and under `Server/` it repeats the route and disappears.
