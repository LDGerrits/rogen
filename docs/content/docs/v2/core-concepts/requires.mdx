title: Requires
description: How code in one feature folder reaches code that runs somewhere else.
---

A feature folder keeps its files side by side on disk, but Rogen places them in different services in the game:

```
src/Inventory/Server/InventoryService.luau  ->  ServerScriptService/Inventory/InventoryService
src/Inventory/Shared/InventoryTypes.luau    ->  ReplicatedStorage/Shared/Inventory/InventoryTypes
```

A `require` runs in the game, so it resolves against the **instance tree**, not the folders on disk. `InventoryService` can't reach `InventoryTypes` as a sibling, because in the game it isn't one. How you write the require depends on your setup.

<Tabs items={["Luau", "Luau with Darklua", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    Require by instance path:

    ```luau title="src/Inventory/Server/InventoryService.luau"
    local ReplicatedStorage = game:GetService("ReplicatedStorage")
    local InventoryTypes = require(ReplicatedStorage.Shared.Inventory.InventoryTypes)
    ```

    luau-lsp resolves these through the sourcemap it generates from `default.project.json`, so types, completion and go-to-definition follow the require to the right file.

    A relative string require also resolves against the instance tree, so `./` only reaches files that land in the same folder in the game. `require("./InventoryData")` from `Server/InventoryService.luau` works when `InventoryData.luau` sits in `Server/` too. A require that crosses to another service doesn't.
  </Tab>
  <Tab value="Luau with Darklua">
    Write requires as paths on disk, and let Darklua's `convert_require` rule rewrite them into instance requires:

    ```luau title="src/Inventory/Server/InventoryService.luau"
    local InventoryTypes = require("../Shared/InventoryTypes")
    ```

    ```json title=".darklua.json"
    {
    	"rules": [
    		{
    			"rule": "convert_require",
    			"current": { "name": "path" },
    			"target": {
    				"name": "roblox",
    				"rojo_sourcemap": "./sourcemap.json",
    				"indexing_style": "property"
    			}
    		}
    	]
    }
    ```

    Darklua looks each file up in `sourcemap.json` to find the instance it becomes. That's why `default.project.json` is rooted at your source, and why the sourcemap has to be kept current as files move. See the [Darklua guide](/docs/v2/setups/darklua).
  </Tab>
  <Tab value="roblox-ts">
    Import by file path:

    ```ts title="src/Inventory/server/InventoryService.ts"
    import { InventoryTypes } from "../shared/InventoryTypes";
    ```

    `rbxtsc` turns each import into an instance require by reading the project file, so the generated code reaches `ReplicatedStorage` wherever the file sits on disk. Keep `rogen watch` running next to `rbxtsc -w`, so the project file is current before it compiles.
  </Tab>
</Tabs>

## What Each Side Can See

Where a file lands decides who can require it. Shared code (`ReplicatedStorage`) runs on both sides, so it can't require anything that only the server can see (`ServerScriptService`, `ServerStorage`). Two files in one feature folder can end up on sides that can't see each other, so check where a file lands before you require it.

<Callout type="info" title="Find the instance path of a file">
	`rogen where <file>` prints the instance path a file lands at, even for a file you haven't created yet. The reverse works too: `rogen where ServerScriptService.Inventory.Save` prints the file behind an instance.
</Callout>
