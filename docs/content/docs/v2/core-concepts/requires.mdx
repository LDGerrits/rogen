title: Requires
description: How code in one feature folder reaches code that runs somewhere else.
---

import { Callout } from "fumadocs-ui/components/callout";
import { Tab, Tabs } from "fumadocs-ui/components/tabs";

Files that sit side by side in a feature folder can end up in different services:

```
src/Inventory/Server/InventoryService.luau  ->  ServerScriptService/Inventory/InventoryService
src/Inventory/Shared/InventoryTypes.luau    ->  ReplicatedStorage/Shared/Inventory/InventoryTypes
```

A `require` runs in the game, so it resolves against the instance tree, not your folders. In the game, `InventoryTypes` isn't a sibling of `InventoryService`. How you reach it depends on your setup.

<Tabs items={["Luau", "Luau with Darklua", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    Require by instance path:

    ```luau title="src/Inventory/Server/InventoryService.luau"
    local ReplicatedStorage = game:GetService("ReplicatedStorage")
    local InventoryTypes = require(ReplicatedStorage.Shared.Inventory.InventoryTypes)
    ```

    luau-lsp resolves these through the sourcemap it builds from `default.project.json`, so types and go-to-definition still lead to the right file. Relative string requires like `require("./InventoryData")` also resolve in the game, so they only reach files routed into the same folder.
  </Tab>
  <Tab value="Luau with Darklua">
    Write requires as paths on disk and let Darklua's `convert_require` rule turn them into instance requires:

    ```luau title="src/Inventory/Server/InventoryService.luau"
    local InventoryTypes = require("../Shared/InventoryTypes")
    ```

    ```json title=".darklua.json"
    {
    	"rules": [
    		{
    			"rule": "convert_require",
    			"current": { "name": "path" },
    			"target": {
    				"name": "roblox",
    				"rojo_sourcemap": "./sourcemap.json",
    				"indexing_style": "property"
    			}
    		}
    	]
    }
    ```

    Darklua uses `sourcemap.json` to find each file's instance, so keep it up to date as files move. See the [Darklua guide](/docs/v2/setups/darklua).
  </Tab>
  <Tab value="roblox-ts">
    Import by file path:

    ```ts title="src/Inventory/server/InventoryService.ts"
    import { InventoryTypes } from "../shared/InventoryTypes";
    ```

    `rbxtsc` reads the project file to turn imports into instance requires, so keep `rogen watch` running next to `rbxtsc -w`.
  </Tab>
</Tabs>

The `@` in a routed file name only exists on disk. Instance requires use the game name (`InventoryService`), and path requires use the file name (`./InventoryService@server`).

## What Each Side Can See

Shared code runs on both sides, so it can't require anything only the server can see, like `ServerScriptService` or `ServerStorage`. Files in the same feature folder can land on sides that can't see each other, so check where a file lands before you require it.

<Callout type="info" title="Find the instance path of a file">
	`rogen where <file>` prints a file's instance path, even before the file exists. It works in reverse too: `rogen where ServerScriptService.Inventory.Save` prints the file behind an instance.
</Callout>
