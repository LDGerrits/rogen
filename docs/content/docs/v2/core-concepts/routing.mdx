A **route** sends files to a **target**, a path that starts at a Roblox **service**. You declare routes in the config's `routes` map, and each route's name is its **route key**.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```json title="default.rogen.json"
    {
    	"routes": {
    		"Server": "ServerScriptService",
    		"Client": "StarterPlayer/StarterPlayerScripts",
    		"Shared": "ReplicatedStorage/Shared",
    		"*": "ReplicatedStorage/Shared"
    	}
    }
    ```
  </Tab>
  <Tab value="roblox-ts">
    ```json title="default.rogen.json"
    {
    	"routes": {
    		"server": "ServerScriptService",
    		"client": "StarterPlayer/StarterPlayerScripts",
    		"shared": "ReplicatedStorage/shared",
    		"*": "ReplicatedStorage/shared"
    	}
    }
    ```
  </Tab>
</Tabs>

`rogen init` writes this set for the language it detects. Nothing is built in: the only routes are the ones your config declares, so `ReplicatedFirst` is a route key only if you add it.

## Routing Folders

Name a folder after a route key and everything inside it goes to that route's target. This is the recommended layout: each **feature folder** holds one routing folder per side.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```
    src/Inventory/Server/InventoryService.luau  ->  ServerScriptService/Inventory/InventoryService
    src/Inventory/Client/InventoryController.luau  ->  StarterPlayer/StarterPlayerScripts/Inventory/InventoryController
    src/Inventory/Shared/InventoryTypes.luau  ->  ReplicatedStorage/Shared/Inventory/InventoryTypes
    ```
  </Tab>
  <Tab value="roblox-ts">
    ```
    src/Inventory/server/InventoryService.ts  ->  ServerScriptService/Inventory/InventoryService
    src/Inventory/client/InventoryController.ts  ->  StarterPlayer/StarterPlayerScripts/Inventory/InventoryController
    src/Inventory/shared/InventoryTypes.ts  ->  ReplicatedStorage/shared/Inventory/InventoryTypes
    ```
  </Tab>
</Tabs>

The routing folder only exists to route, so it disappears from the generated tree. The feature folder stays: `Inventory` shows up under each target.

Luau projects tend to capitalize these folders (`Server/`) and roblox-ts projects don't (`server/`). Either spelling matches the same key, because the [first letter can be either case](#matching).

## The `@` Sign

When a feature is too small for a folder per side, route by name instead. Rogen adds one sign of its own for this, `@`, and it reads like an email address: this name, at that place. The rule is short: **`@key` at the end of a name routes, and whatever comes before the `@` is the name.**

```
Inventory/InventoryService@server.luau  ->  ServerScriptService/Inventory/InventoryService
Matchmaking@server/Queue.luau           ->  ServerScriptService/Matchmaking/Queue
Inventory/@server/Save.luau             ->  ServerScriptService/Inventory/Save
```

- **On a file**, `@server` routes that file and comes off its name. It never changes the script's class, so `InventoryService@server.luau` is still a `ModuleScript`. This is how you put a module in another service without a folder.
- **On a folder**, `Matchmaking@server/` routes everything inside and keeps the name `Matchmaking`.
- **On its own**, `@server/` has no name before the `@`, so no folder appears in the game. It's the same as a plain `server/` routing folder.

Because `@` means nothing else, a typo gets caught: an `@` that nearly spells a declared route draws one warning that names it, so `Save@sever.luau` and `@sever/` both get `did you mean "@Server"?`. Any other `@` stays in the name without a word, since package names use it too (`@rbxts/`, `sleitnick_knit@1.5.1`).

## Marker Files

An empty dot-file named after a route key, such as `.server`, routes its folder and everything below it. Like `Matchmaking@server/`, the folder **keeps its name**, but you don't have to rename it.

```
src/Anti-cheat/.server
src/Anti-cheat/Check.luau  ->  ServerScriptService/Anti-cheat/Check
```

## Rojo's Script Suffixes

Rojo reads `.server` and `.client` at the end of a script name as its class: `Bootstrap.server.luau` is a `Script` and `Hud.client.luau` is a `LocalScript`. When your config declares a `server` or `client` key, these suffixes route as well, because a script has to land where it can run:

```
src/Inventory/Bootstrap.server.luau  ->  ServerScriptService/Inventory/Bootstrap   (a Script)
src/Inventory/Hud.client.luau        ->  StarterPlayer/StarterPlayerScripts/Inventory/Hud   (a LocalScript)
```

The dot belongs to Rojo, so no other key routes through it. `Types.shared.luau` is an instance named `Types.shared`. Write `Types@shared.luau` to route it.

The dot is also how you mark a [variant](/docs/v2/core-concepts/variants), such as `Analytics.mock.luau`. A variant and an `@` route combine in either order, and these docs write the variant first: `Analytics.mock@server.luau`. Rojo's `.server` or `.client` always goes last.

## Matching

A folder, marker file or `@` matches a route key when it spells the key **exactly**, except that the first letter can be either case. With the key `server`:

| Matches | Doesn't match |
|---|---|
| `server/`, `Server/` | `SERVER/`, `sErver/` |
| `.server`, `.Server` | `.SERVER` |
| `Save@server.luau`, `Save@Server.luau` | `Save@SERVER.luau` |

Rogen never guesses. A folder that differs from a key in the case of a later letter isn't routed, and `rogen build` warns about it, naming the key it looks like.

Route keys other than `*` start with a letter and contain only letters and digits. Two keys that differ only in the case of their first letter, like `server` and `Server`, are an error.

## The Governing Route

More than one route can apply to a path. Rogen walks from the root directory down to the file and uses the **first** route it meets, the **governing route**. Every route after it is ignored completely: a routing folder further down keeps its name, and a suffix stays whatever Rojo makes of it.

With routes `ReplicatedFirst`, `server` and `client`:

```
src/ReplicatedFirst/main.client.luau  ->  ReplicatedFirst/main
src/ReplicatedFirst/client/main.luau  ->  ReplicatedFirst/client/main
src/Inventory/Hud.client.luau         ->  StarterPlayer/StarterPlayerScripts/Inventory/Hud
src/server/Inventory/Hud.client.luau  ->  ServerScriptService/Inventory/Hud
```

### Server Code Under a Replicating Route

An ignored route can put server code where clients can read it:

```
src/Shared/Server/Datastore.luau    ->  ReplicatedStorage/Shared/Server/Datastore
src/Shared/(Server)/Datastore.luau  ->  ReplicatedStorage/Shared/Datastore
```

`Shared/` governs, so `Server/` is an ordinary folder and `Datastore` ends up in `ReplicatedStorage`, where every client can read it. Rogen warns once when an ignored route points at a server-only service (`ServerScriptService` or `ServerStorage`) but the file lands in a service that replicates:

```
default.rogen.json - warning: 1 file under a "Server" route ships to clients, because "Shared" governs it:
  src/Shared/Server/Datastore.luau -> ReplicatedStorage/Shared/Server/Datastore
Move it out of the "Shared" route's files if it's server code.
```

This covers modules, models and data files. A script's source doesn't replicate, so scripts get their own warning, below. Other ignored routes don't draw a warning. Parentheses still hide a folder, as the second line shows. See [Invisible Folders](/docs/v2/core-concepts/project-layout#invisible-folders).

### Scripts That Never Run

A `Script` only runs in `ServerScriptService` or `Workspace`, and a `LocalScript` only in `StarterPlayerScripts`, `StarterCharacterScripts`, `StarterGui`, `StarterPack` or `ReplicatedFirst`. Rogen knows each script's class and where it lands, so it warns once about the ones that won't run:

```
src/Inventory/Server/Hud.client.luau  ->  a LocalScript in ServerScriptService
src/Shared/Secret.server.luau         ->  a Script in ReplicatedStorage
```

This happens when a folder governs and a `.client` suffix only sets the class. With `emitLegacyScripts: false` in the template, Rojo makes every script a `Script` with a `RunContext` instead (`Server` for `.server`, `Client` for `.client`). A `Server` script also runs in `ReplicatedStorage`, and a `Client` script runs wherever clients can see it, so Rogen only warns about a `Client` script in `ServerScriptService`. Routes that target `StarterPlayerScripts` or `StarterCharacterScripts` get their own warning, since a `Client` script there runs twice.

A `RunContext` in the script's own `.meta.json` (`"properties": { "RunContext": "Client" }`) wins over both, and Rogen reads it. A script in `ServerStorage` is never reported. Nothing runs there, but it's where scripts are kept for code to clone out.

`rogen where` shows the governing route for any file, and how it matched. It also shows what happened to a file that used an old suffix form. `src/Net/HttpClient.luau` isn't routed, so it prints `route * (fallback)`.

## Files That Match No Route

The `*` route is the **fallback route**: it catches every file no other route matched. You declare it like any other route:

```json
"*": "ReplicatedStorage/Shared"
```

Without `*`, those files are **unrouted**. Rogen leaves them out of the output and warns about each one, up to ten, then says how many more it skipped. It never picks a destination for you, so code can't reach the client by accident.

A config with no routes at all can't build. That's an error, not an empty project.

<Callout type="info" title="Why declare both shared and *">
	`*` catches unmatched files. The `shared` key is what turns `shared/` into a routing folder and `Types@shared.luau` into a route, so the folder disappears from the tree and `@shared` comes off the name. Without the key, both would keep their names in the game.
</Callout>

## Targets

A target is a path. `"ServerScriptService"` puts files at the root of the service, and `"ReplicatedStorage/Shared"` also wraps them in a `Shared` folder that Rogen creates. The first segment must be a supported service, such as `ServerScriptService`, `ReplicatedStorage`, `ReplicatedFirst`, `StarterPlayer`, `StarterGui` or `TextChatService`, and any further segments are folders. Rogen rejects a target that doesn't start with a service, which catches typos.

You have to write `StarterPlayer/StarterPlayerScripts` out in full, because Rogen doesn't know what children a service has.
