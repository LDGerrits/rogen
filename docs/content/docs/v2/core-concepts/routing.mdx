A **route** sends files to a **target**, a path that starts at a Roblox **service**. You declare routes in the config's `routes` map, and each route's name is its **route key**.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```json title="default.rogen.json"
    {
    	"routes": {
    		"Server": "ServerScriptService",
    		"Client": "StarterPlayer/StarterPlayerScripts",
    		"Shared": "ReplicatedStorage/Shared",
    		"*": "ReplicatedStorage/Shared"
    	}
    }
    ```
  </Tab>
  <Tab value="roblox-ts">
    ```json title="default.rogen.json"
    {
    	"routes": {
    		"server": "ServerScriptService",
    		"client": "StarterPlayer/StarterPlayerScripts",
    		"shared": "ReplicatedStorage/shared",
    		"*": "ReplicatedStorage/shared"
    	}
    }
    ```
  </Tab>
</Tabs>

`rogen init` writes this set for you. Nothing is built in, so a route like `ReplicatedFirst` only exists once you declare it.

## Routing Folders

Name a folder after a route key and everything inside goes to that route's target. This is the layout we recommend: each **feature folder** gets one routing folder per side.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```
    src/Inventory/Server/InventoryService.luau  ->  ServerScriptService/Inventory/InventoryService
    src/Inventory/Client/InventoryController.luau  ->  StarterPlayer/StarterPlayerScripts/Inventory/InventoryController
    src/Inventory/Shared/InventoryTypes.luau  ->  ReplicatedStorage/Shared/Inventory/InventoryTypes
    ```
  </Tab>
  <Tab value="roblox-ts">
    ```
    src/Inventory/server/InventoryService.ts  ->  ServerScriptService/Inventory/InventoryService
    src/Inventory/client/InventoryController.ts  ->  StarterPlayer/StarterPlayerScripts/Inventory/InventoryController
    src/Inventory/shared/InventoryTypes.ts  ->  ReplicatedStorage/shared/Inventory/InventoryTypes
    ```
  </Tab>
</Tabs>

The routing folder disappears from the tree, while the feature folder stays, which is why `Inventory` shows up under each target. `Server/` and `server/` both match the key, since the [first letter can be either case](#matching).

## The `@` Sign

When a feature is too small for a folder per side, route by name instead. `@key` at the end of a name routes it, and whatever comes before the `@` is the name, much like an email address.

```
Inventory/InventoryService@server.luau  ->  ServerScriptService/Inventory/InventoryService
Matchmaking@server/Queue.luau           ->  ServerScriptService/Matchmaking/Queue
Inventory/@server/Save.luau             ->  ServerScriptService/Inventory/Save
```

On a file, `@server` routes just that file and never changes its class, so `InventoryService@server.luau` is still a `ModuleScript`. On a folder, it routes everything inside and keeps the folder's name. A bare `@server/` has no name, so it works like a plain routing folder.

An `@` that nearly spells a route key gets a warning, so `Save@sever.luau` gets `did you mean "@Server"?`. Any other `@` stays in the name, since package names use it too (`@rbxts/`, `sleitnick_knit@1.5.1`).

## Marker Files

An empty file named after a route key, like `.server`, routes the folder it sits in and everything below. The folder keeps its name, so you don't have to rename anything.

```
src/Anti-cheat/.server
src/Anti-cheat/Check.luau  ->  ServerScriptService/Anti-cheat/Check
```

## Rojo's Script Suffixes

Rojo reads `.server` and `.client` as a script's class: `Bootstrap.server.luau` is a `Script` and `Hud.client.luau` a `LocalScript`. If your config has a `server` or `client` key, these suffixes route the file too, so the script lands somewhere it can run:

```
src/Inventory/Bootstrap.server.luau  ->  ServerScriptService/Inventory/Bootstrap   (a Script)
src/Inventory/Hud.client.luau        ->  StarterPlayer/StarterPlayerScripts/Inventory/Hud   (a LocalScript)
```

No other key routes through a dot. `Types.shared.luau` is just an instance called `Types.shared`; write `Types@shared.luau` to route it. A dot does mark a [variant](/docs/v2/core-concepts/variants), and the two combine as `Analytics.mock@server.luau`, with Rojo's suffix always last.

## Matching

A name matches a route key when it spells it exactly, except that the first letter can be either case. With the key `server`:

| Matches | Doesn't match |
|---|---|
| `server/`, `Server/` | `SERVER/`, `sErver/` |
| `.server`, `.Server` | `.SERVER` |
| `Save@server.luau`, `Save@Server.luau` | `Save@SERVER.luau` |

Near misses aren't routed, but `rogen build` warns about them. Route keys other than `*` are letters and digits starting with a letter, and two keys that differ only in their first letter's case are an error.

## The Governing Route

When several routes apply to a path, the first one Rogen meets walking down from the root directory wins. That's the **governing route**, and everything below it is ignored: a deeper routing folder keeps its name, and a suffix only sets the class.

With routes `ReplicatedFirst`, `server` and `client`:

```
src/ReplicatedFirst/main.client.luau  ->  ReplicatedFirst/main
src/ReplicatedFirst/client/main.luau  ->  ReplicatedFirst/client/main
src/Inventory/Hud.client.luau         ->  StarterPlayer/StarterPlayerScripts/Inventory/Hud
src/server/Inventory/Hud.client.luau  ->  ServerScriptService/Inventory/Hud
```

### Server Code Under a Replicating Route

This means a `Server/` folder inside `Shared/` is just a folder, and its code ships to every client:

```
src/Shared/Server/Datastore.luau    ->  ReplicatedStorage/Shared/Server/Datastore
src/Shared/(Server)/Datastore.luau  ->  ReplicatedStorage/Shared/Datastore
```

Rogen warns when an ignored route points at `ServerScriptService` or `ServerStorage` but the file lands somewhere that replicates:

```
default.rogen.json - warning: 1 file under a "Server" route ships to clients, because "Shared" governs it:
  src/Shared/Server/Datastore.luau -> ReplicatedStorage/Shared/Server/Datastore
Move it out of the "Shared" route's files if it's server code.
```

### Scripts That Never Run

A `Script` only runs in `ServerScriptService` or `Workspace`, and a `LocalScript` only in `StarterPlayerScripts`, `StarterCharacterScripts`, `StarterGui`, `StarterPack` or `ReplicatedFirst`. Rogen warns about scripts that land anywhere else, except `ServerStorage`, where scripts are kept for cloning:

```
src/Inventory/Server/Hud.client.luau  ->  a LocalScript in ServerScriptService
src/Shared/Secret.server.luau         ->  a Script in ReplicatedStorage
```

<Callout type="info" title="RunContext scripts">
	With `emitLegacyScripts: false` in your template, every script is a `Script` with a `RunContext`, which runs in more places. Rogen then only warns about `Client` scripts in `ServerScriptService`, or under `StarterPlayerScripts` and `StarterCharacterScripts`, where they'd run twice. It also reads a `RunContext` from the script's `.meta.json`.
</Callout>

`rogen where` shows which route governs any file and how it matched.

## Files That Match No Route

The `*` route is the **fallback route**. It catches every file no other route matched:

```json
"*": "ReplicatedStorage/Shared"
```

Without it, those files are **unrouted**: Rogen leaves them out and warns about each one. It never picks a destination for you, so code can't end up on the client by accident. A config with no routes at all is an error.

<Callout type="info" title="Why declare both shared and *">
	`*` only catches leftovers. You still need the `shared` key for `shared/` to act as a routing folder and for `@shared` to route, otherwise both keep their names in the game.
</Callout>

## Targets

A target is a path. `"ServerScriptService"` puts files at the service's root, and `"ReplicatedStorage/Shared"` wraps them in a `Shared` folder. The first segment has to be a supported service (such as `ServerScriptService`, `ReplicatedStorage`, `ReplicatedFirst`, `StarterPlayer`, `StarterGui` or `TextChatService`), which catches typos. Write `StarterPlayer/StarterPlayerScripts` in full, since Rogen doesn't know a service's children.
