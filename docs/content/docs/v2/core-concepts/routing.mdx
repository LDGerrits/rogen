A **route** sends files to a **target**: a path that starts at a Roblox **service**. Routes are declared in the config's `routes` map, and the name of a route is its **route key**.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```json title="default.rogen.json"
    {
    	"routes": {
    		"Server": "ServerScriptService",
    		"Client": "StarterPlayer/StarterPlayerScripts",
    		"Shared": "ReplicatedStorage/Shared",
    		"*": "ReplicatedStorage/Shared"
    	}
    }
    ```
  </Tab>
  <Tab value="roblox-ts">
    ```json title="default.rogen.json"
    {
    	"routes": {
    		"server": "ServerScriptService",
    		"client": "StarterPlayer/StarterPlayerScripts",
    		"shared": "ReplicatedStorage/shared",
    		"*": "ReplicatedStorage/shared"
    	}
    }
    ```
  </Tab>
</Tabs>

`rogen init` writes this set for the language it detects. Nothing is built in: only the routes a config declares exist, so a service name such as `ReplicatedFirst` is a route key only when the config declares it.

A file is routed in one of three ways. All three match a declared route key.

## Routing Folders

Name a folder after a route key, and everything inside it goes to that route's target. This is the recommended layout: a **feature folder** holds one routing folder per side.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```
    src/Inventory/Server/InventoryService.luau  ->  ServerScriptService/Inventory/InventoryService
    src/Inventory/Client/InventoryController.luau  ->  StarterPlayer/StarterPlayerScripts/Inventory/InventoryController
    src/Inventory/Shared/InventoryTypes.luau  ->  ReplicatedStorage/Shared/Inventory/InventoryTypes
    ```
  </Tab>
  <Tab value="roblox-ts">
    ```
    src/Inventory/server/InventoryService.ts  ->  ServerScriptService/Inventory/InventoryService
    src/Inventory/client/InventoryController.ts  ->  StarterPlayer/StarterPlayerScripts/Inventory/InventoryController
    src/Inventory/shared/InventoryTypes.ts  ->  ReplicatedStorage/shared/Inventory/InventoryTypes
    ```
  </Tab>
</Tabs>

A routing folder exists only to route, so it never appears in the generated tree. The `Inventory` folder does: Rogen keeps the feature folder's name under each target.

Luau projects usually capitalize the folder (`Server/`) and roblox-ts projects don't (`server/`). One route key matches both spellings, because the [first letter may be in either case](#matching).

Files can also go through the `*` route, or be routed one by one with the other two methods below.

### Keeping the Folder's Name

Write the folder as `Name@key` to route it **and keep its name**. A bare `@key` routes and leaves no folder, which is what a plain `Server/` does.

```
src/Matchmaking@server/Queue.luau  ->  ServerScriptService/Matchmaking/Queue
src/Inventory/@server/Save.luau    ->  ServerScriptService/Inventory/Save
```

Use `Name@key` when a folder is both a feature and a route, and a flat layout reads better than `Matchmaking/Server/`.

## Marker Files

An empty dot-file named after a route key (`.server`) routes its directory and every directory below it. Unlike a routing folder, the marked folder **keeps its name**, like `Name@key`.

```
src/Anti-cheat/.server
src/Anti-cheat/Check.luau  ->  ServerScriptService/Anti-cheat/Check
```

## Suffixes

`@key` at the end of a file name routes that file. Whatever stands before the `@` is the name, and the suffix is stripped from the instance name:

```
Combat@server.luau  ->  ServerScriptService/.../Combat
Hud@client.luau     ->  StarterPlayer/StarterPlayerScripts/.../Hud
```

`@` is the only sign Rogen adds, and it reads like an email address: this name, at that place. Nothing else in a name routes a file. Rogen doesn't read `Combat-server.luau`, `Combat_server.luau`, `Combat+server.luau` or `CombatServer.luau` as routes, so `HttpClient.luau` stays `HttpClient`.

Rojo's own suffixes still work. Rojo reads `.server` and `.client` at the end of a script name as the script's class, and a file has to land where it runs, so Rogen routes on them when a route key of that name is declared:

```
Bootstrap.server.luau  ->  ServerScriptService/.../Bootstrap   (a Script)
Hud.client.luau        ->  StarterPlayer/StarterPlayerScripts/.../Hud   (a LocalScript)
```

No other route key routes through a dot: `Types.shared.luau` is an instance named `Types.shared`, and `Types@shared.luau` is the route.

<Callout type="info" title="A suffix sets where a script goes, not its class">
	`Combat@server.luau` is a `ModuleScript` in `ServerScriptService`, and `Bootstrap.server.luau` is a `Script`. An `@` suffix decides **where** a file goes, never **what class** it is, so it is how a module reaches another service without a folder. Routing folders read best when a feature has several files per side, and suffixes suit a small feature with a file or two.
</Callout>

An `@` followed by a near miss of a declared route is a typo, so `rogen build` warns once, naming the route: `Save@sever.luau` and the folder `@sever/` get `did you mean "@server"?`. Any other `@` stays in the name silently, since package names use it too (`@rbxts/`, `sleitnick_knit@1.5.1`). A dot part that isn't a [variant](/docs/v2/core-concepts/variants), such as `.spec`, stays in the name silently.

## Matching

A folder, marker file or suffix matches a route key when it spells the key **exactly**, except that the first letter may be in either case. With the key `server`:

| Matches | Doesn't match |
|---|---|
| `server/`, `Server/`, `Queue@server/` | `SERVER/`, `sErver/` |
| `.server`, `.Server` | `.SERVER` |
| `Combat@server.luau`, `Combat@Server.luau` | `Combat@SERVER.luau` |

A folder or marker that differs from a key only in letter case beyond the first letter isn't routed, and `rogen build` warns about it, naming the key it resembles. Nothing is guessed.

Route keys (other than `*`) use letters and digits and start with a letter, and two keys that differ only in the case of their first letter (`server` and `Server`) are an error.

## The Governing Route

Several rules can apply to one path. Rogen walks from the root directory down to the file and takes the **first** route it finds: the **governing route**. Every route after it is **ignored whole**: an ignored routing folder is an ordinary folder that keeps its name, and an ignored suffix stays in the name as Rojo reads it.

With routes `ReplicatedFirst`, `server` and `client`:

```
src/ReplicatedFirst/main.client.luau     ->  ReplicatedFirst/main
src/ReplicatedFirst/client/main.luau     ->  ReplicatedFirst/client/main
src/server/Inventory/Hud.client.luau     ->  ServerScriptService/Inventory/Hud
src/Inventory/Hud.client.luau            ->  StarterPlayer/StarterPlayerScripts/Inventory/Hud
```

- The **governing** folder is removed from the tree (or keeps its name, as `Name@key`), and the **governing** suffix is stripped from the instance name.
- An **ignored** routing folder (`client/` under `ReplicatedFirst/`) is an ordinary folder. It can collapse, and its `init.meta.json` applies. Wrap it as `(client)/` to hide it.
- An **ignored** suffix isn't touched. The name is whatever Rojo makes of the file: `main.client.luau` is a `LocalScript` named `main`, while `Save@server.luau` stays `Save@server`.

### Server Code Under a Replicating Route

An ignored route can put server code where clients can read it. `src/Shared/Server/Datastore.luau` lands in `ReplicatedStorage/Shared/Server/Datastore`, because `Shared` governs and `Server` is ignored. Rogen warns once when an ignored route targets a server-only service (`ServerScriptService`, `ServerStorage`) while the file lands in a service that replicates:

```
warning: 2 files under a "server" route ship to clients, because "shared" governs them:
  src/Shared/Server/Datastore.luau -> ReplicatedStorage/Shared/Server/Datastore
Move them out of the "shared" route's files if they're server code.
```

The warning covers modules, models and data files. A script's source doesn't replicate, so scripts have their own warning below. Rogen doesn't warn about other nested routes it ignores.

### Scripts That Never Run

A `Script` runs only in `ServerScriptService` or `Workspace`, and a `LocalScript` only in `StarterPlayerScripts`, `StarterCharacterScripts`, `StarterGui`, `StarterPack` or `ReplicatedFirst`. Rogen knows each script's class and where it lands, and warns once about the ones that will never run:

```
src/Inventory/Server/Hud.client.luau  ->  a LocalScript in ServerScriptService
src/Shared/Secret.server.luau         ->  a Script in ReplicatedStorage
```

A `Script` whose `.meta.json` sets a `RunContext` other than `Legacy` (`"properties": { "RunContext": "Client" }`) runs by that context, so Rogen reads the meta and doesn't warn about it. With `emitLegacyScripts: false` in the template, Rojo gives scripts a run context instead, so a script runs by its context and not by where it lands. Rogen then skips this warning, and warns only about routes that target `StarterPlayerScripts` or `StarterCharacterScripts`.

### Names That Route by Accident

Only `@` and Rojo's `.server` and `.client` route, so a name seldom routes by accident. `rogen where` shows where a file lands and which suffix routed it. A file that used another form lands in the `*` route:

```
src/Net/HttpClient.luau  ->  ReplicatedStorage/Shared/Net/HttpClient · route * (fallback)
```

## Files That Match No Route

The `*` route is the **fallback route**. It catches files that no route matched. Declare it like any other route:

```json
"*": "ReplicatedStorage/Shared"
```

Without `*`, those files are **unrouted**: they're left out of the output, and Rogen warns about each one, up to ten. The last warning says how many more went unlisted. Rogen never picks a destination itself, so code never reaches the client by accident.

A config that declares no routes at all can't build. That's an error, not an empty project.

<Callout type="info" title="Why declare both shared and *">
	`*` catches unmatched files. The `shared` key is what makes `Types@shared.luau` and a `shared/` folder *declared* routes, so the suffix is stripped and the folder is removed from the tree. Without the key, `Types@shared.luau` would ship as an instance literally named `Types@shared`.
</Callout>

## Targets

A target is a path: `"ServerScriptService"` puts files at the service root, and `"ReplicatedStorage/Shared"` also wraps them in a `Shared` folder that Rogen creates. The first segment must be a supported service, such as `ServerScriptService`, `ReplicatedStorage`, `ReplicatedFirst`, `StarterPlayer`, `StarterGui` or `TextChatService`. Any further segments are folders. Rogen rejects a target whose first segment isn't a service, which catches typos.

`StarterPlayer/StarterPlayerScripts` is written out in full because Rogen has no built-in knowledge of a service's children.
