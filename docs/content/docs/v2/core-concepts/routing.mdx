A **route** sends files to a **target**, a path that starts at a Roblox **service**. You declare routes in the config's `routes` map, and each route's name is its **route key**.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```json title="default.rogen.json"
    {
    	"rogen": {
    		"routes": {
    			"Server": "ServerScriptService",
    			"Client": "StarterPlayer/StarterPlayerScripts",
    			"Shared": "ReplicatedStorage/Shared"
    		}
    	}
    }
    ```
  </Tab>
  <Tab value="roblox-ts">
    ```json title="default.rogen.json"
    {
    	"rogen": {
    		"routes": {
    			"server": "ServerScriptService",
    			"client": "StarterPlayer/StarterPlayerScripts",
    			"shared": "ReplicatedStorage/shared"
    		}
    	}
    }
    ```
  </Tab>
</Tabs>

`rogen init` writes this set for you. Nothing is built in, so a route like `ReplicatedFirst` only exists once you declare it.

## Routing Folders

Name a folder after a route key and everything inside goes to that route's target. This is the layout we recommend: each **feature folder** gets one routing folder per side.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```
    src/Inventory/Server/InventoryService.luau  ->  ServerScriptService/Inventory/InventoryService
    src/Inventory/Client/InventoryController.luau  ->  StarterPlayer/StarterPlayerScripts/Inventory/InventoryController
    src/Inventory/Shared/InventoryTypes.luau  ->  ReplicatedStorage/Shared/Inventory/InventoryTypes
    ```
  </Tab>
  <Tab value="roblox-ts">
    ```
    src/Inventory/server/InventoryService.ts  ->  ServerScriptService/Inventory/InventoryService
    src/Inventory/client/InventoryController.ts  ->  StarterPlayer/StarterPlayerScripts/Inventory/InventoryController
    src/Inventory/shared/InventoryTypes.ts  ->  ReplicatedStorage/shared/Inventory/InventoryTypes
    ```
  </Tab>
</Tabs>

The routing folder disappears from the tree, while the feature folder stays, which is why `Inventory` shows up under each target. `Server/` and `server/` both match the key, since the [first letter can be either case](#matching).

## The `@` Sign

When a feature is too small for a folder per side, route by name instead. `@key` at the end of a name routes it, and whatever comes before the `@` is the name, much like an email address.

```
Inventory/InventoryService@server.luau  ->  ServerScriptService/Inventory/InventoryService
Matchmaking@server/Queue.luau           ->  ServerScriptService/Matchmaking/Queue
Inventory/@server/Save.luau             ->  ServerScriptService/Inventory/Save
```

On a file, `@server` routes just that file and never changes its class, so `InventoryService@server.luau` is still a `ModuleScript`. On a folder, it routes everything inside and keeps the folder's name. A bare `@server/` has no name, so it works like a plain routing folder.

An `@` that nearly spells a route key gets a warning, so `Save@sever.luau` gets `did you mean "@Server"?`. Any other `@` stays in the name, since package names use it too (`@rbxts/`, `sleitnick_knit@1.5.1`).

## Marker Files

An empty file named after a route key with its `@`, like `@server`, routes the folder it sits in and everything below. It works like a bare `@server/` folder, except that the folder keeps its name, so you don't have to rename anything.

```
src/Anti-cheat/@server
src/Anti-cheat/Check.luau  ->  ServerScriptService/Anti-cheat/Check
```

Create one with `touch @server`, or `New-Item '@server'` in PowerShell, where an unquoted `@` means something else. A dot-file like `.server` isn't a route marker, because only `@` routes; Rogen warns about it and names the `@` form. A folder takes one route: two route markers in it, or one beside an init script with a different route suffix, are an error.

## Rojo's Script Suffixes

Rojo reads `.server` and `.client` as a script's class: `Bootstrap.server.luau` is a `Script` and `Hud.client.luau` a `LocalScript`. If your config has a `server` or `client` key, these suffixes route the file too, so the script lands somewhere it can run:

```
src/Inventory/Bootstrap.server.luau  ->  ServerScriptService/Inventory/Bootstrap   (a Script)
src/Inventory/Hud.client.luau        ->  StarterPlayer/StarterPlayerScripts/Inventory/Hud   (a LocalScript)
```

No other key routes through a dot, and nothing but a script does. `Types.shared.luau` is just an instance called `Types.shared`, and `Config.server.json` one called `Config.server`, since a data file or model has no script class; Rogen warns about each. Write `Types@shared.luau` and `Config@server.json` to route them. Any other dot is part of the name, as in Rojo, so `Analytics.mock.luau` is an instance called `Analytics.mock`.

## Matching

A name matches a route key when it spells it exactly, except that the first letter can be either case. With the key `server`:

| Matches | Doesn't match |
|---|---|
| `server/`, `Server/` | `SERVER/`, `sErver/` |
| `@server`, `@Server` | `@SERVER` |
| `Save@server.luau`, `Save@Server.luau` | `Save@SERVER.luau` |

Near misses aren't routed, but `rogen build` warns about them. Route keys other than `*` are letters and digits starting with a letter, and two keys that differ only in their first letter's case are an error.

## The Governing Route

When several routes apply to a path, the first one Rogen meets walking down from the source path wins. That's the **governing route**, and everything below it is ignored: a deeper routing folder keeps its name, and a suffix only sets the class.

With routes `ReplicatedFirst`, `server` and `client`:

```
src/ReplicatedFirst/main.client.luau  ->  ReplicatedFirst/main
src/ReplicatedFirst/client/main.luau  ->  ReplicatedFirst/client/main
src/Inventory/Hud.client.luau         ->  StarterPlayer/StarterPlayerScripts/Inventory/Hud
src/server/Inventory/Hud.client.luau  ->  ServerScriptService/Inventory/Hud
```

An `@` below the governing route is an error, since it would do nothing while its name says the file goes elsewhere: `server/Util@client.luau`, `server/Ui@client/` and a `server/Ui/@client` marker each stop the build. An `@` that restates the governing route is fine, and comes off the name like any route: `Shared/Net/Remote@Shared.luau` lands as `Remote`.

### Server Code Under a Replicating Route

This means a `Server/` folder inside `Shared/` is just a folder, and its code ships to every client:

```
src/Shared/Server/Datastore.luau    ->  ReplicatedStorage/Shared/Server/Datastore
src/Shared/(Server)/Datastore.luau  ->  ReplicatedStorage/Shared/Datastore
```

Rogen warns when such a folder's route points at `ServerScriptService` or `ServerStorage` but the file lands somewhere that replicates:

```
default.rogen.json - warning: 1 file under a server-only route ships to clients, because an outer route governs it: (route.serverCodeShipped)
  src/Shared/Server/Datastore.luau (ships to clients as ReplicatedStorage/Shared/Server/Datastore: move it out of the "Shared" route's files if it's server code, or keep it there with a "@Shared" marker file in its folder)
```

If the folder is meant to replicate, say so where it is: a `Shared/Server/@Shared` marker restates the governing route, and Rogen stops warning about every file below it. There's no ignore list in the config.

### Scripts That Never Run

A `Script` only runs in `ServerScriptService` or `Workspace`, and a `LocalScript` only in `StarterPlayerScripts`, `StarterCharacterScripts`, `StarterGui`, `StarterPack` or `ReplicatedFirst`. Rogen warns about scripts that land anywhere else, except `ServerStorage`, where scripts are kept for cloning:

```
src/Inventory/Server/Hud.client.luau  ->  a LocalScript in ServerScriptService
src/Shared/Secret.server.luau         ->  a Script in ReplicatedStorage
```

<Callout type="info" title="RunContext scripts">
	With `emitLegacyScripts: false` in your config, every script is a `Script` with a `RunContext`, which runs in more places. Rogen keeps the `.client` scripts it routes to `StarterPlayerScripts` and `StarterCharacterScripts` as LocalScripts, with one [sync rule](/docs/v2/configuration#sync-rules) per file in the project file. Rogen then only warns about `Client` scripts in `ServerScriptService`, where they'd never run. It also reads a `RunContext` from the script's `.meta.json`.
</Callout>

`rogen where` shows which route governs any file and how it matched.

## Files That Match No Route

A file that no route matches is **unrouted**: Rogen leaves it out and warns about each one, naming the routing folders of its feature to move it into:

```
src/Shop/Secrets.luau - warning: matched no route, so it is left out. Move it into src/Shop/Server, Client or Shared. (route.unrouted)
```

Rogen can't read Luau, so it can't tell server code from shared code; the folder is the only statement of where a file belongs. It never picks a destination for you, so code can't end up on the client by accident. That is why `rogen init` writes no route for these files. A config with no `routes` at all routes nothing: no source path is scanned.

The `*` route is the **fallback route**. Declare it to send every file no other route matched to one target instead, such as a layer that runs everywhere (see [Layered](/docs/v2/architectures/layered)). `rogen init --unmatched shared` writes it:

```json
"*": "ReplicatedStorage/Shared"
```

<Callout type="info" title="Why declare both shared and *">
	`*` only catches leftovers. You still need the `shared` key for `shared/` to act as a routing folder and for `@shared` to route, otherwise both keep their names in the game.
</Callout>

## Hoisted Names

A file lands at its route's target, followed by every folder above it. A name that starts with `^` lands **directly at the target** instead, and every folder in between is dropped:

```
routes: character -> "StarterPlayer/StarterCharacterScripts"
        *         -> "ReplicatedStorage/Shared"

src/Player/@character
src/Player/^Animate.client.luau  ->  StarterCharacterScripts/Animate
src/Player/Sprint.client.luau    ->  StarterCharacterScripts/Player/Sprint
src/Ui/^Hud/Health.luau          ->  ReplicatedStorage/Shared/Hud/Health
```

It's for instances Roblox only reads at the top of a container, such as an `Animate` or `Health` script in `StarterCharacterScripts`, or a `PlayerModule` in `StarterPlayerScripts`. An invisible folder hoists everything in it; `^` hoists one name and leaves the feature folder whole.

- The target stays whole: `^` only drops folders from disk, never the ones a target creates, so `ReplicatedStorage/Shared` keeps `Shared`.
- Every folder in between goes, including a `Name@key/` folder and the folders above the governing route. It works under any route, `*` included, and an unrouted file stays unrouted.
- A folder takes it too: `^Hud/` lands `Hud` at the target, with its contents nested as usual. `(^Name)/`, or `^(Name)/`, puts its contents at the target.
- The `^` comes off the name, so `^Animate.client.luau` is `Animate`. Its meta file is `^Animate.meta.json`.
- An init script can't take it, since the script is its folder: `^init.luau` is an error. Put the `^` on the folder.

Shells treat `^` specially (cmd.exe as an escape, zsh with `EXTENDED_GLOB` as negation), so quote it: `touch '^Animate.client.luau'`. `rogen where` marks a hoisted file with `hoisted by ^`.

## Targets

A target is a path. `"ServerScriptService"` puts files at the service's root, and `"ReplicatedStorage/Shared"` wraps them in a `Shared` folder. The first segment has to be a supported service (such as `ServerScriptService`, `ReplicatedStorage`, `ReplicatedFirst`, `StarterPlayer`, `StarterGui` or `TextChatService`), which catches typos. Write `StarterPlayer/StarterPlayerScripts` in full, since Rogen doesn't know a service's children.
