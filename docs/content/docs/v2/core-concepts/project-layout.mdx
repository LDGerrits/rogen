Rogen scans the **root directories** in `rootDirs` and turns them into a tree. Routes and variants do most of the shaping, but a few more rules apply.

## Invisible Folders

Wrap a folder name in parentheses, like `(Internals)`, to group files on disk without the folder appearing in the game. Parentheses are stripped before matching, so `(mock)` is still a variant folder and `(server)` a routing folder.

```
src/Inventory/(Internals)/Slots.luau  ->  Inventory/Slots
```

## Init Folders

A folder with an `init` script (`init.luau`, `init.server.luau`, or roblox-ts's `index.ts`) is one instance, as in Rojo: the script is the folder, and the other files in it are its children. Each of them is still routed and varied like any other file, so a folder split across routes gets a copy of its init ModuleScript in each. An init script with no folder of its own to become, in a root directory or a plain routing folder, is an error.

## Data Files

Scripts (`.luau`, `.lua`, `.ts`, `.tsx`), models (`.rbxm`, `.rbxmx`) and data files (`.json`, `.toml`, `.csv`, `.txt`, `.yaml`, `.yml`) all become instances, just as in Rojo. Route and variant suffixes go before the extension. `.d.ts` files are skipped.

## Metadata Files

A `*.meta.json` file sets a class, properties or attributes that a file or folder can't express on its own.

For a file, name the meta after the instance name Rojo gives it, without `.server`, `.client` or `.plugin`: `Save.server.luau` takes `Save.meta.json`. A variant file keeps its full name, so `Analytics.mock.luau` takes `Analytics.mock.meta.json` even when it's renamed in the game.

For a folder, `init.meta.json` applies to every node the folder becomes. This makes a feature folder an `Actor` in every service it lands in:

```json title="src/Combat/init.meta.json"
{ "className": "Actor" }
```

When several folders become the same node, the last root directory with a meta wins. Two metas reaching the same node within one root directory are an error, as is an `id` that would end up on two nodes. If the template defines the node too, the template wins.

Rogen warns about metadata with nothing to apply to, such as an `init.meta.json` in a routing, variant or invisible folder, or a `*.meta.json` no file claims.

<Callout type="warn" title="Darklua drops metadata">
	With a `syncDir`, Rojo reads metadata from your compiler's output. roblox-ts copies it over, but Darklua turns each file into a stray `.meta.lua` module. Folder meta survives because Rogen reads it from your source, and Rogen warns about any other `*.meta.json` missing from the sync directory.
</Callout>

## Excluding Files

`exclude` lists globs, relative to the config, for files that should never be built. Rogen doesn't route or warn about excluded files.

```json
{ "exclude": ["**/*.spec.luau", "**/*.story.luau"] }
```

A `*.rogen.json` inside a root dir is never built, whatever `exclude` says: a config is Rogen's own file, not game data. `rogen where` reports it as `excluded · matches *.rogen.json`.

To sync a vendored library exactly as it is, [mount it in the template](/docs/v2/core-concepts/output#template) instead.

### Leaving Out `_` Files

Rogen gives a leading `_` no meaning, since ordinary Roblox names start with it too (Wally's `Packages/_Index`). If your project uses `_` for drafts and scratch files, exclude them:

```json
{ "exclude": ["**/_*"] }
```

An excluded folder isn't walked, so this covers `_Drafts/` and everything in it, and `rogen where` names the glob for each file it leaves out:

```
$ rogen where src
src/Shop.luau -> ReplicatedStorage/Shared/Shop · route * (fallback)
src/_Draft.luau -> excluded · matches **/_*
src/_Drafts -> excluded · matches **/_*
```

<Callout type="warn" title="Excluded means missing">
	An excluded file isn't in the game, so a `require` of a `_` module fails at runtime.
</Callout>

## Linked Directories

Symlinks and Windows junctions inside a root directory are followed, which is handy for sharing code between repos. The project file keeps the link's own path, so it stays portable. Broken or looping links are skipped with a warning.

## Several Root Directories

Several root directories merge into one tree, and the later one wins any clash. That's how one codebase serves several places; see the [multi-place guide](/docs/v2/setups/multi-place). Root directories can't nest, and one that doesn't exist yet only gets a warning until it appears.

<Callout type="info" title="Rogen only reads names">
	The tree depends only on file and folder names, so editing a script's contents never changes the output.
</Callout>
