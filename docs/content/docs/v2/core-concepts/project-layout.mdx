Rogen scans the **source paths** in `sourcePaths` and turns them into a tree. Routes do most of the shaping, but a few more rules apply.

## Invisible Folders

Wrap a folder name in parentheses, like `(Internals)`, to group files on disk without the folder appearing in the game. Parentheses are stripped before matching, so `(server)` is still a routing folder.

```
src/Inventory/(Internals)/Slots.luau  ->  Inventory/Slots
```

## Init Folders

A folder with an `init` script (`init.luau`, `init.server.luau`, or roblox-ts's `index.ts`) is one instance, as in Rojo: the script is the folder, and the other files in it are its children. So is a folder with an `init.csv`, which becomes a LocalizationTable and is copied like an init ModuleScript. Each of them is still routed like any other file. An init script with no folder of its own to become, in a source path or a plain routing folder, is an error.

An init script's route routes its whole folder, as a [marker file](/docs/v2/core-concepts/routing#marker-files) would: `Combat/init@server.luau`, or `Combat/init.server.luau` when your config has a `server` key, sends everything in `Combat/` to the server. A route on the init script and a marker file that names another route in the same folder clash: `init@client.luau` beside `init@server.luau` is an error.

An init ModuleScript with no route of its own goes wherever its folder does. When the folder is split across routes, say `Combat/Server/` and `Combat/Shared/`, it becomes a `Combat` instance in each service, and each one gets a copy of `init.luau` with only the files routed there as children. `rogen where` lists the copies (`· also ServerScriptService/Combat`). An init `Script` or `LocalScript` is never copied, since every copy would run.

<Callout type="warn" title="Write a copied init for the files beside it">
	Which children a copy has depends on where it sits, not on who runs it. On the server, shared code that requires `ReplicatedStorage.Shared.Combat` gets the copy there, so `RunService:IsServer()` is true but `script.Damage` doesn't exist. The server can also load both copies, each with its own state. Keep a copied init free of state, and look its children up instead of assuming them:

	```luau title="src/Combat/init.luau"
	return setmetatable({}, {
		__index = function(_, name)
			local child = script:FindFirstChild(name)
			return child and require(child)
		end,
	})
	```
</Callout>

## Nested Projects

A folder that holds a `default.project.json` (or `default.project.jsonc`) is that project, as in Rojo: the folder becomes one instance, named by the project's `name`, or by the folder without one, and Rojo reads only what the project's `tree` mounts. Rogen doesn't route the other files in the folder; `rogen where` says `in a nested project` for them. Any other `.project.json` file becomes an instance named by its project's `name`, or by the file without one: `Lib.project.json` with `"name": "Other"` is `Other`.

A `default.project.json` in a source path itself has no folder to become, so Rogen warns ([`scan.nestedProject`](/docs/v2/diagnostics#scan-nestedproject)).

## Data Files

Scripts (`.luau`, `.lua`, `.ts`, `.tsx`), models (`.rbxm`, `.rbxmx`) and data files (`.json`, `.jsonc`, `.toml`, `.csv`, `.txt`, `.yaml`, `.yml`) all become instances, just as in Rojo. Route suffixes go before the extension. `.d.ts` files are skipped.

A folder is an instance because of the files in it. One with nothing that places (it is empty, or holds only a `.gitkeep` or a `README.md`) is left out of the project file, where Rojo reading the same directory would make it an empty Folder. To keep an empty Folder, declare it in the `tree` of the config.

## Metadata Files

A `*.meta.json` file (or `*.meta.jsonc`, which Rojo applies after it) sets a class, properties or attributes that a file or folder can't express on its own.

For a file, name the meta after the instance name Rojo gives it, without `.server`, `.client` or `.plugin`: `Save.server.luau` takes `Save.meta.json`. A dot is part of the name, so `Analytics.mock.luau` takes `Analytics.mock.meta.json`.

For a folder, `init.meta.json` applies to every node the folder becomes. This makes a feature folder an `Actor` in every service it lands in:

```json title="src/Combat/init.meta.json"
{ "className": "Actor" }
```

When several folders become the same node, the last source path with a meta wins. Two metas reaching the same node within one source path are an error, as is an `id` that would end up on two nodes. If the `tree` defines the node too, the tree wins.

Rogen warns about metadata with nothing to apply to, such as an `init.meta.json` in a routing or invisible folder, or a `*.meta.json` no file claims.

<Callout type="warn" title="Darklua drops metadata">
	With a `compiledPath`, Rojo reads metadata from your compiler's output. roblox-ts copies it over, but Darklua turns each file into a stray `.meta.lua` module. Folder meta survives because Rogen reads it from your source, and Rogen warns about any other `*.meta.json` missing from the compiled path.
</Callout>

## Leaving Out Files

`globIgnorePaths` lists globs, relative to the config, for files that should never be built. Rojo ignores them, Rogen writes the list to the project file, and Rogen doesn't route or warn about them.

```json
{ "globIgnorePaths": ["**/*.spec.luau", "**/*.story.luau"] }
```

A `.rogen.json` file inside a source path is never built, whatever the globs say: a config is Rogen's own file, not game data. `rogen where` reports it as `ignored`.

A glob that ignores some of the files a `tree` `$path` mounts leaves the mount, and Rojo ignores those files. A glob that names the mounted folder or file ignores nothing of it, as in Rojo. A glob that covers all of a mounted folder with `/**` leaves the mount out of the project file, where Rojo would keep an empty Folder. To sync a vendored library exactly as it is, [mount it in the tree](/docs/v2/configuration#tree) instead.

### Leaving Out `_` Files

Rogen gives a leading `_` no meaning, since ordinary Roblox names start with it too (Wally's `Packages/_Index`). If your project uses `_` for drafts and scratch files, ignore them:

```json
{ "globIgnorePaths": ["**/_*"] }
```

An ignored folder isn't walked, so this covers `_Drafts/` and everything in it, and `rogen where` names the glob for each file it leaves out (here in a config with a `"*"` route, which places `src/Shop.luau`):

```
$ rogen where src
src/Shop.luau -> ReplicatedStorage/Shared/Shop · route * (fallback)
src/_Draft.luau -> ignored · matches **/_*
src/_Drafts -> ignored · matches **/_*
```

<Callout type="warn" title="Ignored means missing">
	An ignored file isn't in the game, so a `require` of a `_` module fails at runtime.
</Callout>

## Linked Directories

Symlinks and Windows junctions inside a source path are followed, which is handy for sharing code between repos. The project file keeps the link's own path, so it stays portable. Broken or looping links are skipped with a warning.

## Several Source Paths

Several source paths merge into one tree, and the later one wins any clash. Source paths can't nest, and one that doesn't exist yet only gets a warning until it appears.

```json title="default.rogen.json"
{ "rogen": { "sourcePaths": ["core", "game"] } }
```

## Replacing a File

Put the replacement in a later source path. When two source paths give one instance, the last one wins, and Rogen says nothing about it. This swaps in a mock `Analytics`:

```json title="default.rogen.json"
{ "rogen": { "sourcePaths": ["src", "dev"] } }
```

```
src/Analytics/Analytics.luau  ->  left out
dev/Analytics/Analytics.luau  ->  Analytics
```

To keep the swap out of the default build, give the build that wants it a config of its own. `mock.rogen.json` is a complete file beside the default, with the same `name`, `routes` and `tree` and the longer list:

```json title="mock.rogen.json"
{
	"name": "Game",
	"tree": { "$className": "DataModel" },
	"rogen": {
		"sourcePaths": ["src", "dev"],
		"routes": {
			"Server": "ServerScriptService",
			"Client": "StarterPlayer/StarterPlayerScripts",
			"Shared": "ReplicatedStorage/Shared"
		}
	}
}
```

`rogen build mock` writes `mock.project.json` and nothing else. A config doesn't inherit from another, so the second one states its own routes. The same goes for files that only one build has: a source path that one config lists and another doesn't, or a [`globIgnorePaths`](#leaving-out-files) entry in one config, leaves them out of the other. Two files in one source path that give one instance are a [`tree.instanceClash`](/docs/v2/diagnostics#tree-instanceclash) warning, and the last one wins.

<Callout type="info" title="Rogen only reads names">
	The tree depends only on file and folder names, so editing a script's contents never changes the output.
</Callout>
