A **build** is one run that turns your root directories into an **output** for a single config. This page covers that output and how its paths find your code.

## Output

The output is the Rojo project file a config writes, set by `outFile`. It's named after the config by default, so `default.rogen.json` writes `default.project.json` and `lobby.rogen.json` writes `lobby.project.json`. Since `outFile` is never inherited through `extends`, every config writes its own file, and if you need a second project file, you add a second config.

**Rogen owns the output.** A build creates the file if it's missing and replaces whatever is there, hand-written or not, so anything Rogen can't know about belongs in the [template](#template). When nothing has changed, Rogen leaves the file alone, so Rojo doesn't re-sync and `watch` doesn't trip over its own write.

<Callout type="info" title="The default output is the one tools find">
	`rojo serve` with no argument picks up `default.project.json`, and so does luau-lsp when it generates its sourcemap. Darklua needs these two to be different files, so there `default` points at your source and you serve `sync.project.json` instead. See the [Darklua guide](/docs/v2/setups/darklua).
</Callout>

## Template

The **template** is a Rojo project file that Rogen merges its generated tree into, set by `template`. It's always a path to a `*.project.json`, never an inline tree, and it holds the things Rogen can't know: the DataModel name, package mounts and `$properties`. Without one, Rogen starts from an empty `DataModel` named after the config's folder.

When the template and the generated tree define the same instance, **the template wins** and Rogen warns you. A `$path` below a service, such as a package mount, defines that folder's entire contents, so generated files under it are left out as well. A `$path` on a service itself still accepts generated children.

A `$path` that points **inside a root directory** hands that folder or file over to Rojo. Rogen skips it during the scan, so nothing in it is routed, swapped by a variant or warned about, and `rogen where` reports it as `mounted`. That's how you sync a vendored library exactly as it is. Pointing a `$path` at a root directory itself, at a folder above one, or inside an init folder (which Rojo reads whole) is an error.

A child config's `template` replaces its parent's, and `--template` replaces both.

`rogen init` writes a template when it finds packages to mount. If you already have a hand-written project file that a build would replace, `init` copies it to `template.project.json` instead, or lets you use another project file as it is.

## Sync Directory

If you use a compiler, Rojo syncs from its output rather than your source. That output folder is the **sync directory**, set by `syncDir`: usually `out` for roblox-ts and `dist` for Darklua. The `$path`s Rogen writes then point into it instead of at the root directories. Plain Luau has no compiler, so its paths point straight at your source.

A file at `p` is written as `syncDir / relative(commonRoot, p)`, with `.ts` and `.tsx` changed to `.luau`. The **common root** is the deepest folder that contains every root directory; you never set it yourself, but `rogen list --json` shows it. With a single root directory, the common root is that directory, so `syncDir` simply takes its place:

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    Darklua processes `src` into `dist`, so with `"syncDir": "dist"`:

    ```
    src/Inventory/Server/Save.luau  ->  $path: dist/Inventory/Server/Save.luau
    ```
  </Tab>
  <Tab value="roblox-ts">
    `rbxtsc` compiles `src` into `out`, so with `"syncDir": "out"`:

    ```
    src/Inventory/server/Save.ts  ->  $path: out/Inventory/server/Save.luau
    ```
  </Tab>
</Tabs>

With several root directories, the common root moves up, and each path keeps the part that tells the root directories apart. For `["core", "places/lobby"]` the common root is the repo root, so paths land at `dist/core/…` and `dist/places/lobby/…`. That's how compilers behave too: `tsc` roots its output at the common prefix of its inputs.

A few more things to know:

- `syncDir` only affects paths Rogen generates. A `$path` from the template, like Wally's `Packages`, is copied through untouched.
- After a build, Rogen checks each root directory, and if none of its paths exist it warns you with the path it expected and the closest one it found. That usually means the compiler hasn't run yet, or writes somewhere else.
- Rogen never reads the sync directory, so compiled files whose source has been deleted will still sync. Clean the directory as part of your compile step.

### One Tree, Two Renderings

A **rendering** is the tree written out as a project file, with all its `$path`s rooted at one folder. To render the same tree from a different folder, add a second config that `extends` the first and sets a `syncDir`. That's how a Darklua setup gets one project file for Studio and another for Darklua; the [Darklua guide](/docs/v2/setups/darklua) walks through it.

## Building While Watching

It's safe to run `rogen build` while `rogen watch` is writing the same output, so after adding, moving or renaming files you can always run a build and trust the result.
