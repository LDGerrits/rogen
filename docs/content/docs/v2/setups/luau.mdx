Luau is the simplest setup. There's no compiler, so Rojo syncs straight from your source and you don't need a compiled path.

<Steps>

<Step>
### Create the Config

In the project root, run:

```bash
rogen init
```

In a terminal it asks only what it can't tell from the folder: the language in an empty folder, and `One place or several?` for a new project. It then shows the whole plan once, and Enter accepts it:


The summary lists every file it will write and every command it will run, so nothing happens that wasn't shown. [`init`](/docs/v2/cli#init-path) explains Customise, the flags and the runs that skip the summary.

A run without a terminal, or with `-y`, writes the same files, builds `default.project.json` from the config and prints this (in a terminal each line follows a check mark):

The sample is Rogen's version of what `rojo init` writes, and `init` describes it. The tree mounts each service's folder in `place`, so the place is playable at once and the config holds only what you edit. `place` is no source path: Rogen routes nothing in it, and `rogen syncback` writes a change in Studio to those files, not to the config. This is the config that Enter at the summary gives:

```json title="default.rogen.json"
{
	"tree": {
		"$className": "DataModel",
		"Lighting": { "$path": "place/Lighting" },
		"SoundService": { "$path": "place/SoundService" },
		"Workspace": { "$path": "place/Workspace" }
	},
	"rogen": {
		"sourcePaths": ["src"],
		"routes": {
			"Server": "ServerScriptService",
			"Client": "StarterPlayer/StarterPlayerScripts",
			"Shared": "ReplicatedStorage/Shared"
		}
	}
}
```

To change the project later (a route, a source path, Darklua), edit the `.rogen.json` in place, which keeps its comments, and run `rogen check`: `init` never changes a config that exists (see [A folder that has a config](/docs/v2/cli#a-folder-that-has-a-config)). For several places, see [Several Places](/docs/v2/setups/places). If you already have a hand-written `default.project.json`, see [Coming from Rojo](/docs/v2/coming-from-rojo). If `init` finds Wally or Pesde, it mounts their package folders (as optional, so nothing breaks before you install) in the `tree` of `default.rogen.json`. The `.gitignore` it writes lists `*.project.json`: see [Ignore or commit the project files](/docs/v2/core-concepts/output#ignore-or-commit-the-project-files).

</Step>

<Step>
### Lay Out a Feature

Give each feature a folder under `src`, with a routing folder per side:

```
src/Inventory/Server/InventoryService.luau
src/Inventory/Client/InventoryController.luau
src/Inventory/Shared/InventoryTypes.luau
```

That is the layout of `src/Greeter` too. Rogen puts these in `ServerScriptService/Inventory`, `StarterPlayer/StarterPlayerScripts/Inventory` and `ReplicatedStorage/Shared/Inventory`. [Routing](/docs/v2/core-concepts/routing) explains the details.

</Step>

<Step>
### Serve

Start Rogen:

```bash
rogen serve
```

It builds `default.project.json`, starts Rojo on it, and keeps it up to date as you add, move and rename files. Connect from the Studio plugin once it prints `Serving <folder> with Rojo`, where `<folder>` is the name of your project folder.

</Step>

</Steps>

<Callout type="info">
	Rogen runs the Rojo your project pins, else the one on the PATH: see [`serve`](/docs/v2/cli#serve). To run Rojo yourself, run `rogen write --watch` and `rojo serve` side by side: with no argument, `rojo serve` picks up `default.project.json`.
</Callout>
