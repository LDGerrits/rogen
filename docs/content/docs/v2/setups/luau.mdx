Luau is the simplest setup. There's no compiler, so Rojo syncs straight from your source and you don't need a compiled path.

<Steps>

<Step>
### Create the Config

In the project root, run:

```bash
rogen init
```

In a terminal it asks only what it can't tell from the folder: the language in an empty folder, and `One place or several?` for a new project. It then shows the whole plan once, and Enter accepts it:

The summary lists every file it will write and every command it will run, so nothing happens that wasn't shown. `init` writes the pin for Rojo in `rokit.toml` and installs nothing: run `rokit install` yourself. Customise goes through every question, each with its answer preselected, and shows the plan again. A flag answers its line before the summary, and `-y`, `--json` or a run without a terminal skip the summary and take the same defaults.

It writes `default.rogen.json`, builds `default.project.json` from it, writes a small sample game in `src/Greeter` and `place`, adds an `AGENTS.md` that tells coding agents how the project is laid out and a `.gitignore` when there is none, starts a git repository when the folder is in none, and tells you what to do next. A run without a terminal, or with `-y`, prints this (in a terminal each line follows a check mark):

The sample is Rogen's version of what `rojo init` writes: three hello-world scripts, in one feature folder. `Greeting.luau` is a module that the server and the client script both require. Rojo's Baseplate and the Lighting and SoundService settings are Rojo files in `place`: an `init.meta.json` for each service, which names its class, and `Baseplate.model.json`. The tree mounts each service's folder, so the place is playable at once and the config holds only what you edit. `place` is no source path: Rogen routes nothing in it, and `rogen syncback` writes a change in Studio to those files, not to the config. Skip the sample with `rogen init --no-sample`, which writes no `place` and a tree of `"$className": "DataModel"` only; it is written only in a folder with no code.

```json title="default.rogen.json"
{
	"tree": {
		"$className": "DataModel",
		"Lighting": { "$path": "place/Lighting" },
		"SoundService": { "$path": "place/SoundService" },
		"Workspace": { "$path": "place/Workspace" }
	},
	"rogen": {
		"sourcePaths": ["src"],
		"routes": {
			"Server": "ServerScriptService",
			"Client": "StarterPlayer/StarterPlayerScripts",
			"Shared": "ReplicatedStorage/Shared"
		}
	}
}
```

To change the project later (a route, a source path, Darklua), edit the `.rogen.json` in place, which keeps its comments, and run `rogen check`: `init` never changes a config that exists (see [A folder that has a config](/docs/v2/cli#a-folder-that-has-a-config)). For several places, see [Several Places](/docs/v2/setups/places). Customise asks about your source paths, your routes and where files that match no route should go; Enter at the summary gives the config above. If it finds Wally or Pesde, it mounts their package folders (as optional, so nothing breaks before you install) in the `tree` of `default.rogen.json`. If you already have a hand-written `default.project.json`, it lifts that into `default.rogen.json` instead, so you don't lose anything, and turns the folders it mounted from `src` into routes, so the first build puts every script where Rojo had it. See [Coming from Rojo](/docs/v2/coming-from-rojo). It writes a `release.rogen.json` without the specs when it finds a test runner. The `.gitignore` it writes lists `*.project.json`, since Rogen writes those files: see [Ignore or commit the project files](/docs/v2/core-concepts/output#ignore-or-commit-the-project-files).

</Step>

<Step>
### Lay Out a Feature

Give each feature a folder under `src`, with a routing folder per side:

```
src/Inventory/Server/InventoryService.luau
src/Inventory/Client/InventoryController.luau
src/Inventory/Shared/InventoryTypes.luau
```

That is the layout of `src/Greeter` too. Rogen puts these in `ServerScriptService/Inventory`, `StarterPlayer/StarterPlayerScripts/Inventory` and `ReplicatedStorage/Shared/Inventory`. [Routing](/docs/v2/core-concepts/routing) explains the details.

</Step>

<Step>
### Serve

Start Rogen:

```bash
rogen serve
```

It builds `default.project.json`, starts Rojo on it, and keeps it up to date as you add, move and rename files. Connect from the Studio plugin once it prints `Serving <folder> with Rojo`, where `<folder>` is the name of your project folder.

</Step>

</Steps>

<Callout type="info">
	Rogen runs the Rojo your project pins in `rokit.toml` (or Aftman's or Foreman's file), else the one on the PATH. To run Rojo yourself, run `rogen build --watch` and `rojo serve` side by side: with no argument, `rojo serve` picks up `default.project.json`.
</Callout>
