Luau is the simplest setup. There's no compiler, so Rojo syncs straight from your source and you don't need a sync path.

<Steps>

<Step>
### Create the Config

In the project root, run:

```bash
rogen init
```

In a terminal it asks only what it can't tell from the folder: the language in an empty folder, and `One place or several?` for a new project. It then shows the whole plan once, and Enter accepts it:

```
Create this project?
  Project   one place, Luau, sample Greeter
  Code      src → Server, Client, Shared; other files to
            ReplicatedStorage/Shared
  Darklua   no
  Agents    rules in AGENTS.md
  Rojo      pin Rojo 7.7.1 in rokit.toml, install the Studio plugin
  Git       .gitignore, git init
  Files     rogen.json, .gitignore, src/Greeter/Shared/Greeting.luau, ...
  Runs      rokit add rojo-rbx/rojo@7.7.1, rojo plugin install
  ● Yes   ○ Customise (ask every question)   ○ Cancel
```

The summary lists every file it will write and every command it will run, so nothing happens that wasn't shown. Customise goes through every question, each with its answer preselected, and shows the plan again. A flag answers its line before the summary, and `-y`, `--json` or a run without a terminal skip the summary and take the same defaults.

It writes `rogen.json`, builds `default.project.json` from it, writes a small sample game in `src/Greeter`, adds an `AGENTS.md` that tells coding agents how the project is laid out and a `.gitignore` when there is none, starts a git repository when the folder is in none, and tells you what to do next:

```
Created rogen.json.
Created .gitignore.
Created src/Greeter/Shared/Greeting.luau.
Created src/Greeter/Server/Greeter.server.luau.
Created src/Greeter/Client/Greeter.client.luau.
Created README.md.
Created AGENTS.md.
Initialised a git repository.
default.project.json · wrote
Next steps
  Run:
    rogen serve
  Add your own routes under "routes" in rogen.json.
Wrote 7 files.
```

The sample is Rogen's version of what `rojo init` writes: three hello-world scripts, in one feature folder. `Greeting.luau` is a module that the server and the client script both require, and the tree keeps Rojo's Baseplate, Lighting and SoundService, so the place is playable at once. Skip it with `rogen init --no-sample`; it is written only in a folder with no code.

```json title="rogen.json"
{
	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
	"tree": { "$className": "DataModel" },
	"sourcePaths": ["src"],
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared",
		"*": "ReplicatedStorage/Shared"
	}
}
```

For several places, see [Several Places](/docs/v2/setups/places). Customise asks about your source paths, your routes and where files that match no route should go; Enter at the summary gives the config above. If it finds Wally or Pesde, it mounts their package folders (as optional, so nothing breaks before you install) in the `tree` of `rogen.json`. If you already have a hand-written `default.project.json`, it lifts that into `rogen.json` instead, so you don't lose anything, and turns the folders it mounted from `src` into routes, so the first build puts every script where Rojo had it. See [Coming from Rojo](/docs/v2/coming-from-rojo). It writes a `release` project without the specs when it finds a test runner. Whether to ignore or commit the project files is yours to decide: see [Ignore or commit the project files](/docs/v2/core-concepts/output#ignore-or-commit-the-project-files).

</Step>

<Step>
### Lay Out a Feature

Give each feature a folder under `src`, with a routing folder per side:

```
src/Inventory/Server/InventoryService.luau
src/Inventory/Client/InventoryController.luau
src/Inventory/Shared/InventoryTypes.luau
```

That is the layout of `src/Greeter` too. Rogen puts these in `ServerScriptService/Inventory`, `StarterPlayer/StarterPlayerScripts/Inventory` and `ReplicatedStorage/Shared/Inventory`. [Routing](/docs/v2/core-concepts/routing) explains the details.

</Step>

<Step>
### Serve

Start Rogen:

```bash
rogen serve
```

It builds `default.project.json`, starts Rojo on it, and keeps it up to date as you add, move and rename files. Connect from the Studio plugin once it prints `Serving <folder> with Rojo`, where `<folder>` is the name of your project folder.

</Step>

</Steps>

<Callout type="info">
	Rogen runs the Rojo your project pins in `rokit.toml` (or Aftman's or Foreman's file), else the one on the PATH. To run Rojo yourself, run `rogen build --watch` and `rojo serve` side by side: with no argument, `rojo serve` picks up `default.project.json`.
</Callout>
