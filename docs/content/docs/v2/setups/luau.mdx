In a Luau game, Rojo syncs your source files as they are. This page covers what you meet day to day once [Creating a New Game](/docs/v2/new-game) has set the game up.

## Keep the Editor's Sourcemap Current

luau-lsp reads `sourcemap.json` to know where each file sits in the game. Its VS Code extension writes that file by running `rojo sourcemap --watch` on `default.project.json`.

`rogen init` gitignores `*.project.json`, so a fresh clone has no project file, and luau-lsp warns:

```
Unable to find project file default.project.json for Rojo sourcemap generation.
```

After you clone, run `rogen write`. Then run **Luau: Regenerate Sourcemap** from the command palette, or reopen the editor.

A new file in a feature folder reaches the sourcemap by itself. A new feature folder needs a new entry in `default.project.json`. `rogen serve` writes it as you add the folder. When serve isn't running, run `rogen write`.

## Require by Instance

A Luau `require` names where the module is in the game, not where the file is on disk. `rogen where` prints the require for a file:

```
$ rogen where src/Greeter/Shared/Greeting.luau
src/Greeter/Shared/Greeting.luau -> ReplicatedStorage/Shared/Greeter/Greeting · route Shared (folder)
  require(game:GetService("ReplicatedStorage").Shared.Greeter.Greeting)
```

For a file that no other code can require, it says why:

```
$ rogen where src/Greeter/Server/Greeter.server.luau
src/Greeter/Server/Greeter.server.luau -> ServerScriptService/Greeter/Greeter · route Server (folder)
  no require by this path: a script runs on its own and is not a module
```

A string require such as `require("./Prices")` also resolves in the game, so it reaches only the files routed into the same folder. [What Each Side Can Require](/docs/v2/core-concepts/routing#what-each-side-can-require) says which modules each side can reach.

## Packages

When a `wally.toml` is there, `rogen init` mounts Wally's `Packages` in ReplicatedStorage and `ServerPackages` in ServerScriptService. Require a package by its instance, such as `require(ReplicatedStorage.Packages.Promise)`. To mount a package folder yourself, see [The Tree](/docs/v2/core-concepts/routing/tree).

## Using Darklua

[Darklua](https://github.com/seaofvoices/darklua) rewrites your code into a folder of its own, such as `dist`, and Rojo syncs from there. Its `convert_require` rule turns a require by file path into a require by instance:

```lua title="src/Inventory/Server/InventoryService.server.luau"
local InventoryTypes = require("../Shared/InventoryTypes")
```

```lua title="dist/Inventory/Server/InventoryService.server.luau"
local InventoryTypes = require(game:GetService('ReplicatedStorage'):WaitForChild('Shared'):WaitForChild('Inventory'):WaitForChild('InventoryTypes'))
```

The path is the file's path on disk, so a server script can reach `Shared` through `..`. Darklua finds the instance in `sourcemap.json`, which must map your source files:

```json title=".darklua.json"
{
	"rules": [
		{
			"rule": "convert_require",
			"current": { "name": "path" },
			"target": {
				"name": "roblox",
				"rojo_sourcemap": "sourcemap.json",
				"indexing_style": "wait_for_child"
			}
		}
	]
}
```

### Two Configs

The game needs two configs. `default.rogen.json` reads `src`, and the sourcemap comes from it. `dist.rogen.json` is a full copy that adds `"compiledPath": "dist"` and a `name`, and Rojo serves the project file it writes:

```json title="dist.rogen.json"
{
	"name": "my-game",
	"sourcePaths": ["src"],
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared",
		"*": "ReplicatedStorage/Shared"
	},
	"compiledPath": "dist",
	"tree": { "$className": "DataModel" }
}
```

When you run `rogen init` on a Rojo project whose code Darklua already writes to a folder of its own, it writes both configs for you. Otherwise, copy `default.rogen.json` and add those two keys. A change to `routes`, `sourcePaths` or `tree` goes into both files. Add `dist` to `.gitignore`.

### Serve the Processed Code

Run each command in its own terminal, in this order:

```bash
rogen sourcemap --watch -o sourcemap.json
darklua process src dist --watch
rogen serve dist
```

Start the sourcemap first. Without `sourcemap.json`, Darklua stops on each file with `unable to find sourcemap.json`. Darklua processes every file again when the sourcemap changes, so the requires in a new feature folder convert too. A bare `rogen serve` serves `src` without Darklua.

To build a release, run the same steps once:

```bash
rogen sourcemap -o sourcemap.json
darklua process src dist
rogen build dist -o game.rbxl
```

Darklua turns `.txt`, `.json`, `.toml`, `.yaml` and `.yml` files into Lua modules, so Rojo doesn't find them where the project file points. Rogen warns with [`output.dataFileConverted`](/docs/v2/diagnostics#output-datafileconverted).
