With [roblox-ts](https://roblox-ts.com/), Rogen reads your uncompiled `src` folder to decide where each file goes, then writes paths into the compiled output, with `.ts` swapped for `.luau`. `rbxtsc` and `rojo serve` both read that same project file.

<Steps>

<Step>
### Start the Project

In an empty folder, one command sets up roblox-ts and Rogen together:

```bash
rogen init --language roblox-ts
```

`init` runs `npm create roblox-ts@latest -- game --dir . --yes --git=false --skipBuild` first, which writes `package.json`, `tsconfig.json`, the compiler's settings and `node_modules` (it needs npm and the network, and takes about ten seconds). Git stays Rogen's step.

`init` then replaces create-roblox-ts's sample with the Greeter sample in TypeScript, `src/Greeter/{server,client,shared}`, writes `default.rogen.json`, and lists `/node_modules`, `/out`, `/include` and `*.tsbuildinfo` in the `.gitignore` it creates. The next steps are `npm run watch`, which compiles as you edit, and `rogen serve`.

If npm fails, `init` writes none of its own files and names the command to run yourself; with that done, `rogen init` sets Rogen up in the project as in the next step (without the sample). For several places, see [roblox-ts with Places](/docs/v2/setups/places#roblox-ts-with-places).

A folder that already has a `package.json`, a `tsconfig.json` or code gets no scaffold: `init` sets Rogen up in it.

</Step>

<Step>
### Create the Config

In an existing project's root, run `init`. It recognizes roblox-ts from your `tsconfig.json`:

```bash
rogen init
```

A run without a terminal, or with `-y`, prints:

```
Syncing from out, where roblox-ts compiles to.
Took the defaults: --kind place, --language roblox-ts, --no-darklua, --source-path src, --route server, --route client, --route shared, --unmatched leave, --agent-rules.
Created default.rogen.json.
Created .gitignore.
Created AGENTS.md.
Created rokit.toml.
Initialised a git repository.
default.project.json · wrote
Next steps
  Run 'rokit install' to install Rojo.
  Run 'rogen plugin install' to install Rojo's Studio plugin.
  Run each in its own terminal:
    rbxtsc -w
    rogen serve
  In Studio, press Connect in the Rojo plugin.
  Add your own routes under "routes" in default.rogen.json.
  Edit default.rogen.json and leave default.project.json alone, since 'rogen write' overwrites it. After you add a feature folder, run 'rogen write' so the editor's default.project.json follows.
Wrote 4 files.
```

```json title="default.rogen.json"
{
	"tree": {
		"$className": "DataModel",
		"ReplicatedStorage": {
			"rbxts_include": {
				"$path": { "optional": "include" },
				"node_modules": {
					"$className": "Folder",
					"@rbxts": { "$path": { "optional": "node_modules/@rbxts" } }
				}
			}
		}
	},
	"rogen": {
		"sourcePaths": ["src"],
		"routes": {
			"server": "ServerScriptService",
			"client": "StarterPlayer/StarterPlayerScripts",
			"shared": "ReplicatedStorage/shared"
		},
		"compiledPath": "out"
	}
}
```

The `compiledPath` comes from the `outDir` in `tsconfig.json` (or `out` if that isn't set), and the `tree` mounts `include` and `node_modules/@rbxts` the way roblox-ts projects expect. Rojo syncs from the compiled path, so it serves your compiled code, while Rogen routes by the folders in `src`. The `.gitignore` it writes lists `*.project.json`, since Rogen writes those files: see [Ignore or commit the project files](/docs/v2/core-concepts/output#ignore-or-commit-the-project-files).

</Step>

<Step>
### Lay Out a Feature

roblox-ts projects use lowercase routing folders:

```
src/Inventory/server/InventoryService.ts
src/Inventory/client/InventoryController.ts
src/Inventory/shared/InventoryTypes.ts
```

Rogen puts these in `ServerScriptService/Inventory`, `StarterPlayer/StarterPlayerScripts/Inventory` and `ReplicatedStorage/shared/Inventory`, with paths pointing into `out/Inventory/…`.

</Step>

<Step>
### Run the Pipeline

Run the compiler and Rogen side by side, each in its own terminal:

```bash
rbxtsc -w
rogen serve
```

`rogen serve` writes `default.project.json` from `default.rogen.json`, starts Rojo on it once the write succeeds, and writes again as you add, move and rename files. Rogen doesn't run `rbxtsc`. To start both with one command, use a task runner such as `concurrently`:

```json
"scripts": {
	"dev": "concurrently \"rbxtsc -w\" \"rogen serve\""
}
```

</Step>

</Steps>

<Callout type="info">
	Every path Rogen writes is optional, so the project file still works on a fresh checkout before `rbxtsc` has created `out`.
</Callout>
