A game with a lobby, a match and a shop is several places that share code. Rogen keeps what they share in one root `rogen.json`, and each **place** is a folder under it. A place inherits the root's keys and projects, adds its own code, and gets its own project files in its own folder, so each place has its own sourcemap for the editor.

<Steps>

<Step>
### Set Up the Root

In an empty folder, run:

```bash
rogen init --places
```

(or answer `Several places` to `One place or several?`). It writes this layout, with the Greeter sample of the [Luau setup](/docs/v2/setups/luau) as the shared code:

```
places/
  shared/src/Greeter/...        shared by every place
  game/
    rogen.json                  pins the port
    src/Game/Server/Game.server.luau
rogen.json                      sourcePaths: ["places/shared/src"], placePaths: ["places/*"]
<folder>.code-workspace         the root, places/game
README.md
```

`places/shared` is the code every place shares, not a place: a folder that `placePaths` matches by a glob and that holds a root source path is skipped (see [Places](/docs/v2/configuration#places)). Open the `.code-workspace` rather than the folder, so the editor runs a language server for each place. `--no-sample` leaves the two source folders empty.

To turn an existing project into one with places, run `rogen init` in the folder that holds the shared code as for any [setup](/docs/v2/setups/luau): the root's `rogen.json` has the routes, the `tree` and the packages every place uses.

</Step>

<Step>
### Add a Place

Below the root, run `rogen init` with the place's folder, for a second place or for each place of a project you set up yourself:

```bash
rogen init places/lobby
```

In a terminal it asks, when no `placePaths` glob lists the folder yet, whether to add the parent as a glob (`places/*`, the default) or only this folder, then which source paths the place has, and its place ID. It writes the place's `rogen.json`, builds its project file, and writes a `.code-workspace` that lists the root and every place:

```
places/
  lobby/
    rogen.json
    src/
  arena/
    src/
rogen.json
src/
```

```json title="places/lobby/rogen.json"
{
	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
	"servePort": 34872
}
```

A place needs no `rogen.json`: `places/arena` above is a place named `arena` just by matching the glob. A place's `rogen.json` holds what differs. See [Places](/docs/v2/configuration#places) for what a place inherits and what it never does.

</Step>

<Step>
### Put Code Where It Belongs

Code every place needs goes in the root's `src`. A place's own code goes in its `src`, which Rogen adds after the root's: both are routed by the root's routes, and the place's code wins a clash.

```
src/Inventory/Server/InventoryService.luau        every place
places/lobby/src/Lobby/Server/LobbyService.luau   the lobby only
```

</Step>

<Step>
### Serve

```bash
rogen serve
```

At the root, `serve` serves every place on its own port and never the root, which is only the shared code. A place without a `servePort` gets 34872 plus its index among the places without one, sorted by path, and `rogen init` pins the port into the place it adds so adding another place never moves it. `rogen list` shows each place's project file and port. Run `rogen serve` inside a place, or name it (`rogen serve places/lobby`), to serve just that one.

Studio remembers a port per place, so a Studio opened on the wrong place can end up on another place's port. Give each place its `servePlaceIds` and Rojo refuses the connection from any other place: see [Several places](/docs/v2/studio#several-places).

</Step>

<Step>
### Open the Editor

Open the `.code-workspace` that `init` wrote. luau-lsp starts one language server per workspace folder, so each place gets the sourcemap of its own project file. `rogen sourcemap`, run at the root, writes a `sourcemap.json` beside each place's project file for tools that don't run an editor.

</Step>

</Steps>

## roblox-ts with Places

`rogen init --language roblox-ts --places` in an empty folder runs [create-roblox-ts](/docs/v2/setups/roblox-ts) for the root's `package.json` and `node_modules`, then lays out the places. rbxtsc compiles one `tsconfig.json` at a time, so each place has one of its own, and the code the places share is compiled once into each place's `out`:

```
package.json, node_modules/                from create-roblox-ts, at the root
tsconfig.json                              the editor's: checks places/shared/src
places/shared/src/Greeter/...              shared by every place
places/game/tsconfig.json                  compiles src and ../shared/src into out
places/game/rogen.json                     name, syncPath "out", the include override
places/game/src/Game/server/Game.server.ts
```

The place's `tsconfig.json` lists both source folders in `rootDirs` and in `paths`, so `import { greeting } from "Greeter/shared/Greeting"` works from either, and `typeRoots` names the root's `node_modules/@rbxts`. rbxtsc writes its runtime into the `include` beside the `tsconfig.json` it reads, so the place's `rogen.json` overrides the `rbxts_include` mount to the place's own `include`. The root has no `syncPath` and mounts `include` as optional, since nothing compiles into the root. `init` points the `build` and `watch` scripts of `package.json` at the first place, so `npm run watch` compiles it.

`rogen init places/lobby` in such a root writes the same files for the new place, and says to add `rbxtsc -p places/lobby` and `rbxtsc -w -p places/lobby` to the scripts. Run the watch of each place in a terminal of its own.

## Projects in Places

A project of the root is a project of every place. `release` in the root's `rogen.json` writes `release.project.json` in each place's folder, and `rogen build release -o game.rbxl` inside a place builds that place's release. A place may declare projects of its own too.

## Darklua with Places

Each place's Darklua config sits beside that place's sourcemap. A place inherits the root's `syncPath` as the root's own folder, so places that don't set one share one `dist`. The processed copy of the shared code is the same from every place as long as the places mount it at the same instance paths. A place that mounts it somewhere else, or should have a `dist` of its own, sets its own `syncPath` in its `rogen.json`. See the [Darklua guide](/docs/v2/setups/darklua).

<Callout type="info">
	A config that lists places is never served, and it can't set `servePort`, `servePlaceIds`, `blockedPlaceIds`, `placeId` or `gameId`: each place sets its own ([`config.placeSetting`](/docs/v2/diagnostics#config-placesetting)).
</Callout>
