[Darklua](https://github.com/seaofvoices/darklua) rewrites your code into a folder of its own, the **sync path**, and Rojo syncs from there. Rogen still reads your source to decide where files go; it just points Rojo's paths at the sync path.

<Steps>

<Step>
### Define the Sync Path

This guide assumes Darklua reads `src` and writes `dist`. With roblox-ts, it reads the compiled `out` folder instead.

</Step>

<Step>
### Create the Config

Run `rogen init`. It spots your `.darklua.json` and asks whether Darklua processes your code. Commit `default.project.json` with the rest, so a fresh clone works before anyone has run `rogen build`: see [Commit the project file](/docs/v2/core-concepts/output#commit-the-project-file).

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    `init` writes one `rogen.json`, with `"syncPath": "dist"`:

    ```json title="rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"sourcePaths": ["src"],
    	"routes": {
    		"Server": "ServerScriptService",
    		"Client": "StarterPlayer/StarterPlayerScripts",
    		"Shared": "ReplicatedStorage/Shared",
    		"*": "ReplicatedStorage/Shared"
    	},
    	"syncPath": "dist"
    }
    ```
  </Tab>
  <Tab value="roblox-ts">
    `init` writes one `rogen.json`, with `"syncPath": "dist"`. `rbxtsc` compiles `src` into `out`, and Darklua processes `out` into the sync path:

    ```json title="rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"tree": {
    		"$className": "DataModel",
    		"ReplicatedStorage": {
    			"rbxts_include": {
    				"$path": { "optional": "include" },
    				"node_modules": {
    					"$className": "Folder",
    					"@rbxts": { "$path": { "optional": "node_modules/@rbxts" } }
    				}
    			}
    		}
    	},
    	"sourcePaths": ["src"],
    	"routes": {
    		"server": "ServerScriptService",
    		"client": "StarterPlayer/StarterPlayerScripts",
    		"shared": "ReplicatedStorage/shared",
    		"*": "ReplicatedStorage/shared"
    	},
    	"syncPath": "dist"
    }
    ```
  </Tab>
</Tabs>

Rojo syncs from the sync path, so `default.project.json` points into `dist`. There is one project file: the one you serve is the one luau-lsp builds `sourcemap.json` from, and Darklua's `convert_require` reads that same sourcemap. With roblox-ts, `rbxtsc` reads the same file too.

</Step>

<Step>
### Run the Pipeline

`init` prints the commands to run side by side. Rogen doesn't run Darklua or the compiler, so a task runner such as `concurrently` can start them all with one command.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```
    Run:
      rogen serve
    Have Darklua process your code into the sync path:
      darklua process src dist
    ```

    With several source paths, `init` prints one Darklua command each (`darklua process lib dist/lib`). Run them with `--watch`, each in its own terminal:

    ```bash
    darklua process src dist --watch
    rogen serve
    ```

    luau-lsp keeps `sourcemap.json` current while your editor is open. Without it, run:

    ```bash
    rojo sourcemap default.project.json --output sourcemap.json --watch
    ```
  </Tab>
  <Tab value="roblox-ts">
    ```
    Run each in its own terminal:
      rbxtsc -w
      rogen serve
    Have Darklua process your code into the sync path:
      darklua process out dist
    ```

    ```bash
    rbxtsc -w
    darklua process out dist --watch
    rogen serve
    ```
  </Tab>
</Tabs>

</Step>

</Steps>

## Data Files

Darklua turns `.txt`, `.json`, `.toml`, `.yaml` and `.yml` files into Lua modules (`src/Note.txt` becomes `dist/Note.lua`) and drops `.csv` files. Rogen still points at `dist/Note.txt`, so the instance goes missing, and Rogen warns:

```
rogen.json - warning: 1 data file was turned into a Lua module under "dist" (src/Note.txt: expected "dist/Note.txt", found "dist/Note.lua"). (output.dataFileConverted)
```

Either require the module (`require(script.Parent.Note)` returns the string), or copy the data files into `dist` after Darklua runs.
