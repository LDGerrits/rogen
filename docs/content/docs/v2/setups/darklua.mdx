[Darklua](https://github.com/seaofvoices/darklua) rewrites your code into a folder of its own, the **compiled path**, and Rojo syncs from there. Rogen still reads your source to decide where files go; a second config file points Rojo's paths at the compiled path.

Two configs matter here. `default.rogen.json` keeps pointing at your source, which is what luau-lsp builds `sourcemap.json` from and what Darklua's `convert_require` reads. `dist.rogen.json` is a complete copy of it that also sets the compiled path, and writes `dist.project.json`, which is what Studio syncs. A bare `rogen serve` serves `default.rogen.json`, so it serves unprocessed source, as a bare `rojo serve` would: serve the processed code with `rogen serve dist`. `init` prints that line.

<Step>
### Define the Compiled Path

This guide assumes Darklua reads `src` and writes `dist`. With roblox-ts, it reads the compiled `out` folder instead.

</Step>

<Step>
### Create the Config

Run `rogen init`. It spots your `.darklua.json` and asks whether Darklua processes your code. With `--darklua` and no `.darklua.json`, it writes one, writes Darklua's pin into your tool manager's file next to Rojo's (you run `rokit install` to get it) unless that file already pins it or `darklua --version` already runs, and lists the compiled path in the `.gitignore` it creates. It never edits a `.gitignore` that exists: if that one doesn't list the compiled path, `init` tells you the line to add.

`init` writes `dist.rogen.json` for a new project only. To add Darklua to one you already set up, copy `default.rogen.json` to `dist.rogen.json`, give it a `name` (a file other than `default` needs one) and add `"compiledPath": "dist"`, then write `.darklua.json` yourself. A change to `routes` or `tree` goes into both files: see [More Files](/docs/v2/configuration#more-files).

Rojo syncs from `dist.project.json`, so Studio gets the processed code, while `default.project.json` still maps your files for luau-lsp, `rbxtsc` and Darklua's sourcemap. `rogen serve dist` writes `dist.project.json` and serves it. It writes only that file, so `default.project.json` is as fresh as your last `rogen write`; see [The project file is as fresh as its last write](/docs/v2/core-concepts/output#the-project-file-is-as-fresh-as-its-last-write).

### Run the Pipeline

`init` prints the commands to run side by side, with `--watch` already in the Darklua one. Rogen doesn't run Darklua or the compiler, so a task runner such as `concurrently` can start them all with one command.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>

    ```
      darklua process src dist --watch
      rogen serve dist
    ```

    With several source paths, `init` prints one Darklua command each (`darklua process lib dist/lib --watch`).

    ```bash
    rogen sourcemap --watch -o sourcemap.json
    ```

## Data Files

Darklua turns `.txt`, `.json`, `.toml`, `.yaml` and `.yml` files into Lua modules (`src/Note.txt` becomes `dist/Note.lua`) and drops `.csv` files. Rogen still points at `dist/Note.txt`, so the instance goes missing, and Rogen warns:

```
dist.project.json - warning: 1 data file was turned into a Lua module under "dist" (src/Note.txt: expected "dist/Note.txt", found "dist/Note.lua"). (output.dataFileConverted)
```

Either require the module (`require(script.Parent.Note)` returns the string), or copy the data files into `dist` after Darklua runs.

## Darklua at Release Only

If Darklua should process your code only for a release, serve the source while you work and give the processed code to a `release.rogen.json`, a complete file that also sets the compiled path:

```json title="release.rogen.json"
{
	"name": "Game",
	"sourcePaths": ["src"],
	"routes": { "Server": "ServerScriptService", "*": "ReplicatedStorage/Shared" },
	"compiledPath": "dist"
}
```

`rogen serve` serves `default.project.json`, which reads `src`. A release runs Darklua, then builds the place from the other project file:

```bash
darklua process src dist
rogen build release -o game.rbxl
```

## Darklua with Places

A repository with [several places](/docs/v2/setups/places) gives each place its own dist config: `game.dist.rogen.json` beside `game.rogen.json` for Luau, with one `.darklua.json` at the root, or `projects/game/dist.rogen.json` and its own `.darklua.json` for a place in `projects/`, since Darklua reads its config from the folder it runs in. Common code is compiled once per place, into the place's own compiled path, which repeats the layout of its source paths (`dist/common` and `dist/game` in Luau):

```json title="game.dist.rogen.json"
{
	"name": "game",
	"sourcePaths": ["src/common", "src/game"],
	"routes": { "Server": "ServerScriptService", "*": "ReplicatedStorage/Shared" },
	"compiledPath": "dist"
}
```

So a place has two `darklua process` commands, one for the common folder and one for its own source. `init --places --darklua` prints them:

```
Run each in its own terminal:
  darklua process src/common dist/common --watch
  darklua process src/game dist/game --watch
  rogen serve game.dist.rogen.json
```

In roblox-ts they run from the place's folder, as `cd projects/game && darklua process out dist --watch`.

A Luau place added later copies `game.dist.rogen.json` (and `game.release.rogen.json`) to `lobby.dist.rogen.json`, with `name` and the source path `src/game` changed as in its own config, and needs only `darklua process src/lobby dist/lobby --watch`, since the common code is processed already. A roblox-ts place copies its folder, `dist.rogen.json`, `release.rogen.json` and `.darklua.json` included (see [roblox-ts with Places](/docs/v2/setups/places#roblox-ts-with-places)).

Another place is a second terminal set with its own `--port`.
