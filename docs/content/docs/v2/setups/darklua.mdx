[Darklua](https://github.com/seaofvoices/darklua) is a **processor**: it rewrites your code into a folder of its own before Rojo syncs it. That folder is the **sync directory**. Rogen detects Darklua when it finds a `.darklua.json` or `.darklua.json5` file in the project root, and `init` asks about it.

<Callout type="info" title="Only Rojo syncs from the sync directory">
	Rogen reads your source folders to decide where each file goes. It never reads the sync directory: it only points Rojo's paths there.
</Callout>

<Steps>

<Step>
### Define the Sync Directory

Assume the Darklua configuration takes files from `src` and outputs files to `dist`. With roblox-ts, Darklua reads the compiled `out` folder instead.

</Step>

<Step>
### Create the Config

Run `rogen init` and answer that Darklua processes your code. The setup differs by language:

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    `init` writes **two** configs. `default.rogen.json` holds the tree, with paths into `src`, and `sync.rogen.json` extends it and adds the sync directory:

    ```json title="default.rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"rootDirs": ["src"],
    	"routes": {
    		"Server": "ServerScriptService",
    		"Client": "StarterPlayer/StarterPlayerScripts",
    		"Shared": "ReplicatedStorage/Shared",
    		"*": "ReplicatedStorage/Shared"
    	}
    }
    ```

    ```json title="sync.rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"extends": "./default.rogen.json",
    	"syncDir": "dist"
    }
    ```

    The two configs are one tree rendered twice. `default.project.json` points into `src`. `sync.project.json` points into `dist` and is the file for `rojo serve`.

    The source-rooted config is the default because luau-lsp generates its sourcemap from `default.project.json` without any settings, and Darklua's `convert_require` rule reads that same `sourcemap.json`. Your editor maps instances to the files you edit, and Darklua rewrites requires against your source, with nothing configured. It's also the parent, because a child can add a field but never remove one.

  </Tab>
  <Tab value="roblox-ts">
    `init` writes **one** config. `rbxtsc` compiles `src` into `out`, and Darklua processes `out` into the sync directory:

    ```json title="default.rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"rootDirs": ["src"],
    	"routes": {
    		"server": "ServerScriptService",
    		"client": "StarterPlayer/StarterPlayerScripts",
    		"shared": "ReplicatedStorage/shared",
    		"*": "ReplicatedStorage/shared"
    	},
    	"template": "template.project.json",
    	"syncDir": "dist"
    }
    ```

    roblox-ts has its own types, so nothing needs a source-rooted project and a second config isn't needed.
  </Tab>
</Tabs>

</Step>

<Step>
### Run the Pipeline

`init` prints the commands to run. Run the processors and Rogen simultaneously.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```
    Have Darklua process your code into the sync dir:
      darklua process src dist
    ```

    With several root directories, each one lands at its own path under `dist` (`darklua process lib dist/lib`), and `init` prints one command per directory.

    ```bash
    darklua process src dist --watch
    ```

    Watch both configs, so the project file for Darklua stays current too:

    ```bash
    rogen watch default sync
    ```

    Darklua reads `sourcemap.json`, which luau-lsp keeps current from `default.project.json` while your editor is open. Without luau-lsp, keep it current yourself:

    ```bash
    rojo sourcemap default.project.json --output sourcemap.json --watch
    ```

    Then serve the synced project:

    ```bash
    rojo serve sync.project.json
    ```

    <Callout type="warn">
    	A bare `rojo serve` picks up `default.project.json` and syncs your unprocessed source. Always name `sync.project.json`.
    </Callout>
  </Tab>
  <Tab value="roblox-ts">
    ```
    Have Darklua process your code into the sync dir:
      darklua process out dist
    ```

    ```bash
    rbxtsc -w
    darklua process out dist --watch
    rogen watch
    ```

    Then start Rojo with `rojo serve`.
  </Tab>
</Tabs>

</Step>

</Steps>

<Callout type="info">
	`rogen build` and `rogen watch` print one line naming any `*.rogen.json` they weren't asked to build, so forgetting the synced config in a Darklua setup doesn't go unnoticed.
</Callout>

## Data Files

Darklua turns data files into Lua modules. `darklua process src dist` writes `src/Note.txt` as `dist/Note.lua`, and does the same for `.json`, `.toml`, `.yaml` and `.yml` (a `.model.json` becomes `Model.model.lua`). It has no option to copy them unchanged, and it leaves `.csv` files out.

Rogen builds the path it expects from the source file, so a `Note.txt` points at `dist/Note.txt`, which Darklua never wrote. Rojo finds nothing there, so the instance is missing, or it syncs a `ModuleScript` where a folder collapses. Rogen doesn't rewrite the path to what exists, because a build never depends on what the sync dir holds. It warns instead, once per build (and once per config load in `watch`, when Darklua may not have run):

```
warning: 1 data file was turned into a Lua module under "dist" (src/Note.txt: expected "dist/Note.txt", found "dist/Note.lua").
```

Either accept the conversion and require the module (`require(script.Parent.Note)` returns the string), or copy the data files into the sync dir after Darklua runs, so Rogen finds them where it expects.
