[Darklua](https://github.com/seaofvoices/darklua) is a **processor**: it rewrites your code into a folder of its own, called the **sync directory**, and Rojo syncs from there. If there's a `.darklua.json` or `.darklua.json5` in the project root, `init` notices and asks about it.

<Callout type="info" title="Only Rojo syncs from the sync directory">
	Rogen reads your source folders to decide where each file goes. It never reads the sync directory; it only points Rojo's paths at it.
</Callout>

<Steps>

<Step>
### Define the Sync Directory

This guide assumes Darklua reads from `src` and writes to `dist`. With roblox-ts, Darklua reads the compiled `out` folder instead.

</Step>

<Step>
### Create the Config

Run `rogen init` and say yes when it asks whether Darklua processes your code. What it writes next depends on the language:

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    `init` writes **two** configs. `default.rogen.json` holds the tree, with paths into `src`, and `sync.rogen.json` extends it with the sync directory:

    ```json title="default.rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"rootDirs": ["src"],
    	"routes": {
    		"Server": "ServerScriptService",
    		"Client": "StarterPlayer/StarterPlayerScripts",
    		"Shared": "ReplicatedStorage/Shared",
    		"*": "ReplicatedStorage/Shared"
    	}
    }
    ```

    ```json title="sync.rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"extends": "./default.rogen.json",
    	"syncDir": "dist"
    }
    ```

    That's one tree rendered twice: `default.project.json` points into `src`, and `sync.project.json` points into `dist`. The second one is what you serve with Rojo.

    The source-facing config is the default because luau-lsp builds its sourcemap from `default.project.json` out of the box, and Darklua's `convert_require` rule reads that same `sourcemap.json`. That way your editor maps instances to the files you actually edit, and Darklua rewrites requires against your source, with nothing extra to configure. It's also the parent, because a child config can add a field but can't remove one.

  </Tab>
  <Tab value="roblox-ts">
    `init` writes **one** config. `rbxtsc` compiles `src` into `out`, and Darklua processes `out` into the sync directory:

    ```json title="default.rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"rootDirs": ["src"],
    	"routes": {
    		"server": "ServerScriptService",
    		"client": "StarterPlayer/StarterPlayerScripts",
    		"shared": "ReplicatedStorage/shared",
    		"*": "ReplicatedStorage/shared"
    	},
    	"template": "template.project.json",
    	"syncDir": "dist"
    }
    ```

    roblox-ts has its own types, so nothing needs a project file pointing at your source, and one config is enough.
  </Tab>
</Tabs>

</Step>

<Step>
### Run the Pipeline

`init` prints the commands you need; run them side by side.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```
    Have Darklua process your code into the sync dir:
      darklua process src dist
    ```

    With several root directories, each one gets its own path under `dist` (`darklua process lib dist/lib`), and `init` prints a command for each of them.

    ```bash
    darklua process src dist --watch
    ```

    Watch both configs, so Darklua's project file stays current too:

    ```bash
    rogen watch default sync
    ```

    Darklua reads `sourcemap.json`, which luau-lsp keeps up to date from `default.project.json` while your editor is open. If you don't use luau-lsp, keep it updated yourself:

    ```bash
    rojo sourcemap default.project.json --output sourcemap.json --watch
    ```

    Then serve the synced project:

    ```bash
    rojo serve sync.project.json
    ```

    <Callout type="warn">
    	A bare `rojo serve` picks up `default.project.json` and syncs your unprocessed source. Always pass `sync.project.json`.
    </Callout>
  </Tab>
  <Tab value="roblox-ts">
    ```
    Have Darklua process your code into the sync dir:
      darklua process out dist
    ```

    ```bash
    rbxtsc -w
    darklua process out dist --watch
    rogen watch
    ```

    Then start Rojo with `rojo serve`.
  </Tab>
</Tabs>

</Step>

</Steps>

<Callout type="info">
	`rogen build` and `rogen watch` mention any `*.rogen.json` you didn't ask them to build, so you'll notice if you forget the sync config.
</Callout>

## Data Files

Darklua turns data files into Lua modules. `darklua process src dist` writes `src/Note.txt` as `dist/Note.lua`, and does the same for `.json`, `.toml`, `.yaml` and `.yml`. It drops `.csv` files entirely, and there's no option to copy any of them unchanged.

Rogen expects `Note.txt` at `dist/Note.txt`, where Darklua never wrote it, so Rojo finds nothing and the instance goes missing (or, where a folder collapses, it syncs a `ModuleScript`). Rogen won't rewrite the path to match what's on disk, because a build never depends on what's in the sync directory. Instead it warns you, once per build:

```
default.rogen.json - warning: 1 data file was turned into a Lua module under "dist" (src/Note.txt: expected "dist/Note.txt", found "dist/Note.lua").
```

You have two ways out: require the module (`require(script.Parent.Note)` returns the string), or copy the data files into the sync directory after Darklua runs.
