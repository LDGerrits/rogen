[Darklua](https://github.com/seaofvoices/darklua) rewrites your code into a folder of its own, the **sync path**, and Rojo syncs from there. Rogen still reads your source to decide where files go; a [project](/docs/v2/configuration#projects) points Rojo's paths at the sync path.

Two files matter here. `default.project.json` keeps pointing at your source, which is what luau-lsp builds `sourcemap.json` from and what Darklua's `convert_require` reads. A `dist` project points at the sync path, which is what Studio syncs. `rogen serve` serves the one `serveProject` names, so you never serve unprocessed code by accident.

<Steps>

<Step>
### Define the Sync Path

This guide assumes Darklua reads `src` and writes `dist`. With roblox-ts, it reads the compiled `out` folder instead.

</Step>

<Step>
### Create the Config

Run `rogen init`. It spots your `.darklua.json` and asks whether Darklua processes your code. With `--darklua` and no `.darklua.json`, it writes one, pins Darklua with your toolchain manager, and lists the sync path in the `.gitignore` it creates. It never edits a `.gitignore` that exists: if that one doesn't list the sync path, `init` tells you the line to add.

To add Darklua to a project you already set up, run `rogen init --darklua`: on a project that has a `rogen.json` it adds the `dist` project, `serveProject`, `.darklua.json` and Darklua's pin, keeps your comments, and lists what it changed. `rogen init --no-darklua` takes the `dist` project off again while it is still what `init` writes. Darklua needs one source of code, so it can't start together with `--places`.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    `init` writes one `rogen.json`, with a `dist` project that has `"syncPath": "dist"` and is the one `rogen serve` serves:

    ```json title="rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"sourcePaths": ["src"],
    	"routes": {
    		"Server": "ServerScriptService",
    		"Client": "StarterPlayer/StarterPlayerScripts",
    		"Shared": "ReplicatedStorage/Shared",
    		"*": "ReplicatedStorage/Shared"
    	},
    	"serveProject": "dist",
    	"projects": {
    		"dist": { "syncPath": "dist" }
    	}
    }
    ```
  </Tab>
  <Tab value="roblox-ts">
    `init` writes one `rogen.json`. `rbxtsc` compiles `src` into `out`, which `default.project.json` points at, and Darklua processes `out` into the sync path of the `dist` project:

    ```json title="rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"tree": {
    		"$className": "DataModel",
    		"ReplicatedStorage": {
    			"rbxts_include": {
    				"$path": { "optional": "include" },
    				"node_modules": {
    					"$className": "Folder",
    					"@rbxts": { "$path": { "optional": "node_modules/@rbxts" } }
    				}
    			}
    		}
    	},
    	"sourcePaths": ["src"],
    	"routes": {
    		"server": "ServerScriptService",
    		"client": "StarterPlayer/StarterPlayerScripts",
    		"shared": "ReplicatedStorage/shared",
    		"*": "ReplicatedStorage/shared"
    	},
    	"syncPath": "out",
    	"serveProject": "dist",
    	"projects": {
    		"dist": { "syncPath": "dist" }
    	}
    }
    ```
  </Tab>
</Tabs>

Rojo syncs from `dist.project.json`, so Studio gets the processed code, while `default.project.json` still maps your files for luau-lsp, `rbxtsc` and Darklua's sourcemap.

</Step>

<Step>
### Run the Pipeline

`init` prints the commands to run side by side, with `--watch` already in the Darklua one. Rogen doesn't run Darklua or the compiler, so a task runner such as `concurrently` can start them all with one command.

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    ```
    Run each in its own terminal:
      darklua process src dist --watch
      rogen serve
    ```

    With several source paths, `init` prints one Darklua command each (`darklua process lib dist/lib --watch`).

    luau-lsp keeps `sourcemap.json` current while your editor is open, so `init` leaves the next line out when your editor settings name luau-lsp. Without it, run:

    ```bash
    rogen sourcemap --watch -o sourcemap.json
    ```
  </Tab>

    ```
    Run each in its own terminal:
      rbxtsc -w
      darklua process out dist --watch
      rogen serve
    ```

    ```bash

    darklua process out dist --watch
    rogen serve
    ```

## Data Files

Darklua turns `.txt`, `.json`, `.toml`, `.yaml` and `.yml` files into Lua modules (`src/Note.txt` becomes `dist/Note.lua`) and drops `.csv` files. Rogen still points at `dist/Note.txt`, so the instance goes missing, and Rogen warns:

```
rogen.json - warning: 1 data file was turned into a Lua module under "dist" (src/Note.txt: expected "dist/Note.txt", found "dist/Note.lua"). (output.dataFileConverted)
```

Either require the module (`require(script.Parent.Note)` returns the string), or copy the data files into `dist` after Darklua runs.

## Darklua at Release Only

If Darklua should process your code only for a release, serve the source while you work and give the processed code to a `release` project:

```json title="rogen.json"
{
	"sourcePaths": ["src"],
	"routes": { "Server": "ServerScriptService", "*": "ReplicatedStorage/Shared" },
	"projects": {
		"release": { "syncPath": "dist" }
	}
}
```

`rogen serve` serves `default.project.json`, which reads `src`. A release runs Darklua, then builds the place from the other project file:

```bash
darklua process src dist
rogen build release -o game.rbxl
```
