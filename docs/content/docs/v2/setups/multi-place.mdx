A **place** is one Roblox place in a repo that builds several. Each place is a config that `extends` a shared one and adds a folder of its own to the root directories, so every place shares the core code.

<Steps>

<Step>
### Structure the Repository

Keep shared code in `src`, and each place's own code in `places/<name>`.

<Step>
### Add the Place

If you're starting fresh, run `rogen init` and pick **Several places that share code**. That's the default if there are already folders in `places/`. It asks the usual questions for the shared config, then the place names, and writes one config per place.

To add a place later, run `rogen init` again in a terminal and pick **A place**. It only asks for the place's name and folder (`places/lobby` by default), and takes the language, Darklua, routes and packages from the existing project. Without a terminal, or with `--no-input`, `rogen init lobby` takes those defaults and adds the place without asking. That's how a script or a coding agent adds one:

```bash
rogen init                    # in a terminal, then pick A place
rogen init lobby --no-input   # without asking
```

A place folder can't overlap the shared root directories, and `init` never edits an existing file. What it writes depends on the toolchain:

<Tabs items={["Luau", "roblox-ts"]} groupId="language" persist>
  <Tab value="Luau">
    One config:

    ```json title="lobby.rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"extends": "./default.rogen.json",
    	"rootDirs": ["src", "places/lobby"]
    }
    ```

    Rogen reads both root directories and merges them into one tree. If two files land on the same instance, the directory listed last wins, so a place can override shared code.
  </Tab>
  <Tab value="roblox-ts">
    One config and one tsconfig. A place's root directories have a different common root than `src` on its own, so its compiled files land at a different path and need their own `outDir`:

    ```json title="lobby.rogen.json"
    {
    	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
    	"extends": "./default.rogen.json",
    	"rootDirs": ["src", "places/lobby"],
    	"syncDir": "out/lobby"
    }
    ```

    ```json title="tsconfig.lobby.json"
    {
    	"extends": "./tsconfig.json",
    	"compilerOptions": {
    		"rootDir": null,
    		"rootDirs": ["src", "places/lobby"],
    		"outDir": "out/lobby"
    	},
    	"include": ["src", "places/lobby"]
    }
    ```

    `init` never edits `tsconfig.json` itself. If it has no `include`, its own build would pick up `places/lobby` too, so `init` tells you to add `"include": ["src"]`.
  </Tab>
</Tabs>

</Step>

The project file is named after the config: `lobby.rogen.json` writes `lobby.project.json`. `rogen list` shows every config the repo can build.

## With Darklua

Each place needs a project file that points at its source, for Darklua, **and** one that points at the processed output, for Studio. So a place is two configs: `lobby` extends `default` and adds the place's root directory, and `lobby-sync` extends `lobby` and adds a sync directory.

```json title="lobby.rogen.json"
{
	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
	"extends": "./default.rogen.json",
	"rootDirs": ["src", "places/lobby"]
}
```

```json title="lobby-sync.rogen.json"
{
	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
	"extends": "./lobby.rogen.json",
	"syncDir": "dist/lobby"
}
```

The common root of `src` and `places/lobby` is the repo root, so the synced paths are `dist/lobby/src/…` and `dist/lobby/places/lobby/…`. Run Darklua once per root directory to match, keep the place's sourcemap current for `convert_require`, and serve the synced project:

```bash
darklua process src dist/lobby/src
darklua process places/lobby dist/lobby/places/lobby
rogen watch lobby lobby-sync
rojo sourcemap lobby.project.json --output sourcemap.json --watch
rojo serve lobby-sync.project.json
```

luau-lsp regenerates `sourcemap.json` from `default.project.json`, which only has the shared code, and would overwrite the place's version. While you work on a place, point luau-lsp at it with `"luau-lsp.sourcemap.rojoProjectFile": "lobby.project.json"`, or turn off `luau-lsp.sourcemap.autogenerate`.

One merged source config for all places wouldn't work. Darklua rewrites requires against the sourcemap, so the sourcemap has to be the place's own tree, and places that override each other's files would collapse into one.

<Callout type="info">
	Shared `routes`, `variants` and `template` live in the config every place extends, so each place only says what's different.
</Callout>
