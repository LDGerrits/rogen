---
title: Using Syncback
description: Bring changes made in Studio back into your source files
---

`rogen syncback` writes the changes in a place file saved from Studio back into your source files. It needs Rojo 7.7.0 or newer.

## Run Syncback

In Studio, save the place with **File > Save to File As** as `game.rbxlx`, then preview:

```
$ rogen syncback --input game.rbxlx --dry-run
Writing src/Greeter/Shared/Greeting.luau
Writing src/Quest/Shared/QuestTypes.luau
Writing src/Greeter/Server/Welcome.luau
Writing src/Quest/Server/Main.server.luau
Removing src/Greeter/Client
Syncback would change 5 files (4 to write, 1 to remove).
```

Read the list before you write. Syncback also removes the files of instances the place no longer holds, so a place saved from an old copy undoes newer edits. When it looks right, run it again without `--dry-run`, adding `-y` in CI.

## Where Changes Go

A changed instance goes back to its own file, and a new one goes where routing would put it, styled like the files around it: in their routing folder, with their `@` or under their marker. A folder renamed in Studio keeps its layout, as its folder on disk is renamed with what it holds, data files in their own form and new children named like their siblings, as long as every side it makes was renamed alike. Before it writes anything, syncback asks routing itself where each new file would land, so an instance whose name routing would read as a route, such as `Save@Server`, `^Hud` or `(Group)`, is left out with a warning; rename it in Studio. An instance named `.` or `..`, or with a `/` or `\` in its name, which Rojo would write somewhere else than the instance is, stops syncback before it writes or removes anything; rename it in Studio. Under a [`compiledPath`](/docs/v2/config), syncback leaves the compiled code alone and warns about each change for you to copy into the source.
