title: Testing
description: Run your specs in Roblox with jest-roblox-cli, from a project that builds them in and a release project that leaves them out.
---

import { Steps, Step } from "fumadocs-ui/components/steps";
import { Callout } from "fumadocs-ui/components/callout";

[jest-roblox-cli](https://github.com/christopher-buss/jest-roblox-cli) builds a place with Rojo, runs your Jest specs inside Roblox and prints the results. Rogen's part is the project files it builds the place from: one with the specs in it, and a release one that must not have them.

The two differ by a `globIgnorePaths` entry, which is what a [project](/docs/v2/configuration#projects) is for. This page is for the [Luau setup](/docs/v2/setups/luau), where the project file points at your source.

<Steps>

<Step>
### Build the Specs In, and Leave Them Out of Release

The description is what you work on and test, so it keeps the specs. A `release` project is the same description with the specs ignored:

```json title="rogen.json"
{
	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared",
		"*": "ReplicatedStorage/Shared"
	},
	"projects": {
		"release": { "globIgnorePaths": ["**/*.spec.luau"] }
	}
}
```

`rogen init` writes this when it finds a test runner. `rogen build` writes `default.project.json` with the specs and `release.project.json` without them. A `globIgnorePaths` in a project replaces the list of the description, so state every glob the release should ignore.

</Step>

<Step>
### Keep Test-only Settings Out of Release

A game you ship should not have `LoadStringEnabled`, which Jest needs. Put it in the description's `tree` and turn it off in `release`:

```json title="rogen.json"
{
	"tree": {
		"$className": "DataModel",
		"ServerScriptService": { "$properties": { "LoadStringEnabled": true } }
	},
	"projects": {
		"release": {
			"globIgnorePaths": ["**/*.spec.luau"],
			"tree": { "ServerScriptService": { "$properties": { "LoadStringEnabled": false } } }
		}
	}
}
```

To leave out anything else that is only for development, such as a `DevPackages` mount, ignore its folder in `release`: `"globIgnorePaths": ["DevPackages/**", "**/*.spec.luau"]` drops the mount from `release.project.json`.

</Step>

<Step>
### Run Them

Build, then point jest-roblox at the project file with the specs. `default.project.json` is the one it looks for when it isn't told otherwise:

```bash
rogen build
jest-roblox
```

Build the release place from the other file:

```bash
rogen build release
rojo build release.project.json -o game.rbxl
```

</Step>

</Steps>

<Callout type="info">
	Run `rogen check` in CI, so a spec that lands nowhere is
	found before the run. jest-roblox's own exit code then says whether the tests
	passed.
</Callout>
