---
title: Testing
description: Run your specs in Roblox with jest-roblox-cli, from a project that builds them in and leaves them out of production.
---

import { Steps, Step } from "fumadocs-ui/components/steps";
import { Callout } from "fumadocs-ui/components/callout";

[jest-roblox-cli](https://github.com/christopher-buss/jest-roblox-cli) builds a place with Rojo, runs your Jest specs inside Roblox and prints the results. Rogen's part is the project file it builds the place from: one with the specs in it, which a production build must not have.

The specs and the production build differ by a `globIgnorePaths` entry, and the project that has the specs lives in a folder of its own. This page is for the [Luau setup](/docs/v2/setups/luau), where the project file points at your source.

<Steps>

<Step>
### Leave the Specs Out of Production

Ignore the specs in the `rogen.json` at the root, so `rogen serve` and a release build leave them out:

```json title="rogen.json"
{
	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared",
		"*": "ReplicatedStorage/Shared"
	},
	"globIgnorePaths": ["**/*.spec.luau"]
}
```

Anything else that is only for development, such as a `DevPackages` mount, goes in the `tree` of the test project below.

</Step>

<Step>
### Add a Project for the Tests

Put it in a folder of its own, so the `rogen.json` at the root stays what `rogen serve` and `rogen build` read. `test/rogen.json` reads the same source and builds the specs, since it ignores nothing, and sets `LoadStringEnabled`, which Jest needs and a game you ship should not have:

```json title="test/rogen.json"
{
	"$schema": "https://ldgerrits.github.io/rogen/schema/2/rogen.json",
	"name": "GameTests",
	"tree": {
		"$className": "DataModel",
		"ServerScriptService": { "$properties": { "LoadStringEnabled": true } }
	},
	"sourcePaths": ["../src"],
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared",
		"*": "ReplicatedStorage/Shared"
	}
}
```

A config doesn't inherit from another, so the test project states its own `tree` and `routes`; copy them from the root `rogen.json` and keep them in step. Paths in a config are relative to its folder, so the source path reaches back with `..`. With the default `src` instead, the build would warn that the source path does not exist ([`scan.missingSourcePath`](/docs/v2/diagnostics#scan-missingsourcepath)), and the place would hold no specs.

</Step>

<Step>
### Run Them

Build the test project, then point jest-roblox at its project file:

```bash
rogen build test
jest-roblox --rojoProject test/default.project.json
```

Its paths reach back into `../src`, so the specs are the files you edit. A plain `rogen build` still writes only the root `default.project.json`, with no specs, and jest-roblox looks for that one first when it isn't told otherwise, so pass `--rojoProject`, or set `rojoProject` in its config.

</Step>

</Steps>

<Callout type="info">
	Add `--deny-warnings` to `rogen build test` in CI, so a spec that lands
	nowhere is found before the run. jest-roblox's own exit code then says
	whether the tests passed.
</Callout>
