title: Testing
description: Run your specs in Roblox with jest-roblox-cli, from a project that builds them in and a release project that leaves them out.
---

import { Steps, Step } from "fumadocs-ui/components/steps";
import { Callout } from "fumadocs-ui/components/callout";

[jest-roblox-cli](https://github.com/christopher-buss/jest-roblox-cli) builds a place with Rojo, runs your Jest specs inside Roblox and prints the results. Rogen's part is the project files it builds the place from: one with the specs in it, and a release one that must not have them.

The two differ by a `globIgnorePaths` entry, so each is its own config file: `default.rogen.json` and `release.rogen.json`. This page is for the [Luau setup](/docs/v2/setups/luau), where the project file points at your source.

<Steps>

<Step>
### Build the Specs In, and Leave Them Out of Release

`default.rogen.json` is what you work on and test, so it keeps the specs. `release.rogen.json` is a complete copy of it with the specs ignored. It repeats `name`, `routes` and `tree`, since no file reads another:

```json title="default.rogen.json"
{
	"name": "Game",
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared"
	},
	"tree": { "$className": "DataModel" }
}
```

```json title="release.rogen.json"
{
	"name": "Game",
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared"
	},
	"tree": { "$className": "DataModel" },
	"globIgnorePaths": ["**/*.spec.luau"]
}
```

`rogen init` writes `release.rogen.json` when it finds a test runner. `rogen write` writes `default.project.json` with the specs and `release.project.json` without them; `rogen write release` writes only the second. When you change a route, change it in both files.

</Step>

<Step>
### Keep Test-only Settings Out of Release

A game you ship should not have `LoadStringEnabled`, which Jest needs. Put it in the `tree` of `default.rogen.json` and turn it off in the `tree` of `release.rogen.json`:

```json title="default.rogen.json"
{
	"tree": {
		"$className": "DataModel",
		"ServerScriptService": { "$properties": { "LoadStringEnabled": true } }
	}
}
```

```json title="release.rogen.json"
{
	"tree": {
		"$className": "DataModel",
		"ServerScriptService": { "$properties": { "LoadStringEnabled": false } }
	}
}
```

(Both files also hold the keys of the first step.) To leave out anything else that is only for development, such as a `DevPackages` mount, ignore its folder in `release.rogen.json`: `"globIgnorePaths": ["DevPackages/**", "**/*.spec.luau"]` drops the mount from `release.project.json`.

</Step>

<Step>
### Run Them

Build, then point jest-roblox at the project file with the specs. `default.project.json` is the one it looks for when it isn't told otherwise, and `rogen write` is what keeps it fresh:

```bash
rogen write
jest-roblox
```

Build the release place from the other config:

```bash
rogen build release -o game.rbxl
```

</Step>

</Steps>

<Callout type="info">
	Run `rogen check` in CI, so a spec that lands nowhere is
	found before the run. jest-roblox's own exit code then says whether the tests
	passed.
</Callout>
