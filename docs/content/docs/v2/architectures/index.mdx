[Core Concepts](/docs/v2/core-concepts/routing) explains how Rogen reads a tree. These pages are about which tree to write: layouts that work well for Roblox games, where they come from, and what they cost.

## Two Axes

You can split a Roblox codebase by **where code runs** (server, client, both) or by **what it's about** (inventory, combat, trading). Without Rogen, Rojo forces the first split onto your top-level folders. Every layout here flips that: features (or layers, then features) at the top, with `Server/`, `Client/` and `Shared/` inside.

## Comparison

| | [Feature folders](/docs/v2/architectures/feature-folders) | [Layered](/docs/v2/architectures/layered) | [ECS by feature](/docs/v2/architectures/ecs) |
|---|---|---|---|
| **Top level** | One folder per feature | `base`, `platform`, `core`, `features`, `app` | One folder per feature |
| **Inside it** | `Server/`, `Client/`, `Shared/` | Features, each with `Server/`, `Client/`, `Shared/` | Components in `Shared/`, systems per side |
| **Dependency rule** | Features stay independent | Layers only require layers below | Systems read components, not each other |
| **Extra config** | None | Optional invisible layer folders | None |
| **Costs** | Shared code needs a home | More folders, a decision per module | A new model to learn |

## Pick This If…

- **Feature folders** if you're starting out or moving away from `server/client/shared`. It's the smallest change, and the other two build on it.
- **Layered** once utilities, infrastructure and gameplay start to blur together and you want a rule for what may require what.
- **ECS by feature** if you use Jecs or Matter, or have lots of entities that share behavior.

They mix well, too: a layered codebase has feature folders inside it, and ECS can live in `features/`.

## Enforcing the Rules

Every rule on these pages is a rule about paths: `platform` doesn't require `features`, features don't require each other, `Shared` doesn't require `Server`. Because the layer, feature and side are in every path, a linter can check each rule by comparing two paths. With `client/Controllers/InventoryController`, you couldn't even write "inventory doesn't require trading" down.

Rogen doesn't read your `require` calls, so checking them is up to your tools. Roblox catches a client requiring server code, but a shared module that does so only fails once a client loads it, and a feature poking at another's internals works fine until someone changes them.

### roblox-ts

ESLint's [`import/no-restricted-paths`](https://github.com/import-js/eslint-plugin-import/blob/main/docs/rules/no-restricted-paths.md) checks imports against folders. This config enforces the [layered](/docs/v2/architectures/layered) rules, using one zone per feature to stop sideways imports:

```js title="eslint.config.js"
import { readdirSync } from "node:fs";
import importPlugin from "eslint-plugin-import";

const features = readdirSync("src/features");

export default [
	{
		files: ["src/**/*.ts"],
		plugins: { import: importPlugin },
		settings: { "import/resolver": { typescript: true } },
		rules: {
			"import/no-restricted-paths": ["error", {
				zones: [
					// Layers only import the layers below them.
					{ target: "./src/base", from: ["./src/platform", "./src/core", "./src/features", "./src/app"] },
					{ target: "./src/platform", from: ["./src/core", "./src/features", "./src/app"] },
					{ target: "./src/core", from: ["./src/features", "./src/app"] },
					{ target: "./src/features", from: "./src/app" },
					// Features don't import each other.
					...features.map((name) => ({
						target: `./src/features/${name}`,
						from: "./src/features",
						except: [`./${name}`],
					})),
					// Shared code runs on both sides.
					{ target: "./src/**/shared/**", from: ["./src/**/server/**", "./src/**/client/**"] },
					{ target: "./src/**/server/**", from: "./src/**/client/**" },
					{ target: "./src/**/client/**", from: "./src/**/server/**" },
				],
			}],
		},
	},
];
```

The resolver setting needs `eslint-import-resolver-typescript`. For [feature folders](/docs/v2/architectures/feature-folders), the side zones work unchanged. Features in that layout are allowed to import the helper features that hold shared code, so give each feature a zone whose `except` lists the helpers it may use.

### Luau

[Lute](https://lute.luau.org/cli/lint/)'s linter runs rules written in Luau, on the same parser Luau and Roblox use. A Luau `require` names an instance rather than a file, so the rule below reads the sourcemap from `rojo sourcemap` to learn where each file lands, follows each `require` to the instance it names, and compares the two:

- **Sides:** server and client code require their own side and shared code. Shared code requires only shared code.
- **Features:** a feature doesn't require another, except the helper features in `sharedFeatures`.
- **Missing instances:** a `require` of something no file provides, such as a module that was renamed, is an error too.

The rule follows `game`, `script`, `.Parent`, `:GetService`, `:WaitForChild`, `:FindFirstChild`, `["Name"]` and locals holding any of those. It skips what it can't resolve without running the code, such as `script.Parent[name]`, and string requires, such as [Darklua](/docs/v2/setups/darklua)'s path requires.

`featureRoots` lists the instances whose children are features. For [feature folders](/docs/v2/architectures/feature-folders), they're the targets of your routes:

```luau title=".config.luau"
return {
	lute = {
		lint = {
			rulepaths = { "lints" },
			ruleconfigs = {
				require_boundaries = {
					options = {
						sourcemap = "sourcemap.json",
						featureRoots = {
							"ServerScriptService",
							"StarterPlayer.StarterPlayerScripts",
							"ReplicatedStorage.Shared",
						},
						sharedFeatures = { "Util" },
					},
				},
			},
		},
	},
}
```

```luau title="lints/require_boundaries.luau"
local fs = require("@std/fs")
local json = require("@std/json")
local path = require("@std/path")
local query = require("@std/syntax/query")
local syntax = require("@std/syntax")
local utils = require("@std/syntax/utils")

type Side = "server" | "client" | "shared"
type InstancePath = { string }
type Sourcemap = { byFile: { [string]: InstancePath }, instances: { [string]: boolean } }
type Scope = { script: InstancePath, values: { [any]: any }, seen: { [any]: boolean } }

local name = "require_boundaries"

local SIDES: { [string]: Side } = {
	ServerScriptService = "server",
	ServerStorage = "server",
	StarterPlayer = "client",
	StarterGui = "client",
	ReplicatedFirst = "client",
	ReplicatedStorage = "shared",
	Workspace = "shared",
}

local MAY_REQUIRE: { [Side]: { [Side]: boolean } } = {
	server = { server = true, shared = true },
	client = { client = true, shared = true },
	shared = { shared = true },
}

local sourcemaps: { [string]: Sourcemap } = {}

local function loadSourcemap(file: string): Sourcemap
	local absolute = path.format(path.resolve(file))
	if sourcemaps[absolute] then
		return sourcemaps[absolute]
	end
	local result: Sourcemap = { byFile = {}, instances = {} }
	local function walk(node: any, at: InstancePath)
		result.instances[table.concat(at, ".")] = true
		for _, filePath in node.filePaths or {} do
			result.byFile[path.format(path.resolve(path.dirname(absolute), filePath))] = at
		end
		for _, child in node.children or {} do
			local childAt = table.clone(at)
			table.insert(childAt, child.name)
			walk(child, childAt)
		end
	end
	walk(json.deserialize(fs.readFileToString(absolute)), {})
	sourcemaps[absolute] = result
	return result
end

-- The instance path an expression names, or nil when it isn't static.
local function resolve(expr: any, scope: Scope): InstancePath?
	if expr.tag == "group" then
		return resolve(expr.expression, scope)
	elseif expr.tag == "global" then
		if expr.name.text == "game" then
			return {}
		elseif expr.name.text == "script" then
			return table.clone(scope.script)
		end
	elseif expr.tag == "local" then
		local value = scope.values[expr["local"]]
		if value and not scope.seen[value] then
			scope.seen[value] = true
			return resolve(value, scope)
		end
	elseif expr.tag == "indexname" and expr.accessor.text == "." then
		local parent = resolve(expr.expression, scope)
		if parent and expr.index.text == "Parent" then
			return if #parent > 0 then { table.unpack(parent, 1, #parent - 1) } else nil
		elseif parent then
			table.insert(parent, expr.index.text)
			return parent
		end
	elseif expr.tag == "index" and expr.index.tag == "string" then
		local parent = resolve(expr.expression, scope)
		if parent then
			table.insert(parent, expr.index.token.text)
			return parent
		end
	elseif expr.tag == "call" and expr.self then
		local argument = expr.arguments[1]
		local child = argument and argument.node.tag == "string" and argument.node.token.text
		local receiver = child and resolve(expr.func.expression, scope)
		local method = expr.func.index.text
		if receiver and method == "GetService" and #receiver == 0 then
			return { child }
		elseif receiver and (method == "WaitForChild" or method == "FindFirstChild") then
			table.insert(receiver, child)
			return receiver
		end
	end
	return nil
end

-- The side and feature of an instance, where the feature is the child of the deepest feature root.
local function locate(at: InstancePath, featureRoots: { string }): (Side?, string?)
	local joined = table.concat(at, ".")
	local deepest = 0
	for _, root in featureRoots do
		local depth = #string.split(root, ".")
		if depth > deepest and string.sub(joined, 1, #root + 1) == root .. "." then
			deepest = depth
		end
	end
	return SIDES[at[1]], if deepest > 0 then at[deepest + 1] else nil
end

local function lint(ast: syntax.AstStatBlock, sourcepath: path.Path?, context: any)
	local options = context.options
	local sourcemap = loadSourcemap(options.sourcemap or "sourcemap.json")
	local script = sourcepath and sourcemap.byFile[path.format(path.resolve(sourcepath))]
	if script == nil then
		return {}
	end
	local featureRoots = options.featureRoots or {}
	local helpers = {}
	for _, feature in options.sharedFeatures or {} do
		helpers[feature] = true
	end
	local fromSide, fromFeature = locate(script, featureRoots)

	local values = {}
	query.findAllFromRoot(ast, utils.isStatLocal):forEach(function(stat: any)
		if #stat.variables == 1 and #stat.values == 1 then
			values[stat.variables[1].node] = stat.values[1].node
		end
	end)

	local violations = {}
	query.findAllFromRoot(ast, utils.isRequireCall):forEach(function(call: any)
		local argument = call.arguments[1]
		local target = argument and resolve(argument.node, { script = script, values = values, seen = {} })
		if target == nil then
			return
		end
		local targetName = table.concat(target, ".")
		local toSide, toFeature = locate(target, featureRoots)
		local message
		if not sourcemap.instances[targetName] then
			message = `{targetName} is not in the sourcemap`
		elseif fromSide and toSide and not MAY_REQUIRE[fromSide][toSide] then
			message = `{fromSide} code requires {toSide} code: {targetName}`
		elseif fromFeature and toFeature and fromFeature ~= toFeature and not helpers[toFeature] then
			message = `feature {fromFeature} requires feature {toFeature}: {targetName}`
		end
		if message then
			table.insert(violations, {
				lintname = name,
				location = call.location,
				message = message,
				severity = "error",
				sourcepath = sourcepath,
			})
		end
	end)
	return violations
end

return table.freeze({ name = name, lint = lint })
```

Build and write the sourcemap first, so it matches the tree. In CI, a crossed boundary fails the job:

```bash
rogen write
rojo sourcemap default.project.json --output sourcemap.json
lute lint --no-default-lints src
```

In a [layered](/docs/v2/architectures/layered) codebase with visible layers, the feature roots are one level down, such as `ServerScriptService.features`. The rule doesn't check the order of the layers, so write that rule down in your `AGENTS.md` and hold the line in review.

### Why It Pays Off

- **A smaller blast radius.** A change inside `features/Shop` can only break the shop.
- **Safe deletes.** Nothing outside a feature requires it, so removing it can't break anything else.
- **Parallel work.** Crossed boundaries fail in CI, not in review weeks later.
- **Agents stay inside the lines.** They can run the linter and fix what they crossed. See [Working with agents](/docs/v2/agents).
- **The architecture holds up.** Rules in people's heads erode one shortcut at a time; rules in a lint config don't.

<Callout type="info" title="About the examples">
	The trees use the routes `rogen init` writes for Luau. In a roblox-ts project, the routing folders are lowercase (`server/`, `client/`, `shared/`) and the files end in `.ts`. Client modules go to `StarterPlayerScripts` because that's where `init` sends them; point the `Client` route at a folder in `ReplicatedStorage` if you'd rather keep them there.
</Callout>
