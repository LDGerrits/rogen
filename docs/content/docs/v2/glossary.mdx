## The Pipeline

- **Source path**: A folder Rogen scans and watches for code, listed in `sourcePaths`. With several, their feature folders merge into one tree, and the later one wins a clash. See [Project Layout](/docs/v2/core-concepts/project-layout#several-source-paths).

- **Common root**: The deepest folder that contains every source path. Rogen works it out; you never write it in the config. See [Sync Path](/docs/v2/core-concepts/output#sync-path).

- **Linked directory**: A symlink or Windows junction inside a source path, read as the directory it points to. See [Project Layout](/docs/v2/core-concepts/project-layout#linked-directories).

- **Feature folder**: A folder inside a source path that holds everything for one gameplay feature, whichever service each file ends up in. See [Routing](/docs/v2/core-concepts/routing#routing-folders).

- **Sync path**: The folder Rojo syncs from, set as `syncPath`: your compiler's output. See [Output and Sync](/docs/v2/core-concepts/output#sync-path).

- **Tree**: The instance tree in `rogen.json`, as in any Rojo project file, that Rogen merges its generated nodes into. See [Configuration](/docs/v2/configuration#tree).

- **Project**: The Rojo project file Rogen writes, `default.project.json`, beside the `rogen.json` it comes from. Rogen owns it. See [Output and Sync](/docs/v2/core-concepts/output#output).

- **Build**: One complete run that turns the source paths into a project. See [CLI](/docs/v2/cli#build-project).

- **Watch**: A long-running build that rewrites its output when files change, and reloads when a config changes. See [CLI](/docs/v2/cli#watch-project).

- **Toolchain**: The language (Luau or roblox-ts), an optional processor and the package manager a project uses. `init` detects it once. See [CLI](/docs/v2/cli#init).

- **Processor**: A tool such as Darklua that rewrites your code into a folder of its own before Rojo syncs it. See the [Darklua guide](/docs/v2/setups/darklua).

## Routing

- **Service**: A top-level Roblox container that code can go in, such as `ServerScriptService`. See [Routing](/docs/v2/core-concepts/routing#targets).

- **Route**: An entry in `routes` that sends files to a target. Its name is the **route key**. See [Routing](/docs/v2/core-concepts/routing).

- **Governing route**: The one route that decides where a file goes: the first one Rogen meets, walking down from the source path. Every route after it is ignored. See [Routing](/docs/v2/core-concepts/routing#the-governing-route).

- **Target**: The path a route places files at. Its first segment is a service. See [Routing](/docs/v2/core-concepts/routing#targets).

- **Fallback route**: The `*` route, for files no other route matched. See [Routing](/docs/v2/core-concepts/routing#files-that-match-no-route).

- **Routing folder**: A folder named after a route key, like `Server/` or `@server/`. When it governs, it disappears from the generated tree. Below another route, it's an ordinary folder. See [Routing](/docs/v2/core-concepts/routing#routing-folders).

- **Suffix**: The end of a name that routes it. Routes use `@` (`Save@server.luau`, `Matchmaking@server/`), and Rojo's `.server` and `.client` route too when a key of that name exists. See [Routing](/docs/v2/core-concepts/routing#the--sign).

- **Declared key**: A route key. It is recognized as a folder, a marker file or a suffix. See [Routing](/docs/v2/core-concepts/routing).

- **Marker file**: An empty file named after a declared key with its `@`, like `@server`, which applies it to its folder and everything below. See [Routing](/docs/v2/core-concepts/routing#marker-files).

- **Metadata file**: Rojo's `*.meta.json`, which sets a class, properties or attributes. See [Project Layout](/docs/v2/core-concepts/project-layout#metadata-files).

- **Invisible folder**: A folder written as `(name)`, left out of the generated tree. See [Project Layout](/docs/v2/core-concepts/project-layout#invisible-folders).
- **Hoisted name**: A file or folder name that starts with `^`, which lands directly at its route's target, dropping every folder in between. See [Routing](/docs/v2/core-concepts/routing#hoisted-names).

- **Init folder**: A folder with an `init` or `index` script, which Rojo treats as one instance. See [Project Layout](/docs/v2/core-concepts/project-layout#init-folders).

## Filtering

- **Ignored**: Left out of the project because the file matches a `globIgnorePaths` glob. See [Project Layout](/docs/v2/core-concepts/project-layout#leaving-out-files).

- **Mounted**: Left out of the scan because a `tree` `$path` points at it, inside a source path. Rojo reads it as it is, and Rogen neither routes it nor warns about it. See [Configuration](/docs/v2/configuration#tree).

- **Displaced**: Left out of the project because the `tree` defines the file's node, or gives one of its folders a `$path`. See [Configuration](/docs/v2/configuration#tree).

## Configuration

- **Config**: A folder's `rogen.json`: a Rojo project file plus `sourcePaths`, `routes` and `syncPath`. See [Configuration](/docs/v2/configuration).

- **Legacy config**: A config written for Rogen 1, which v2 doesn't read. A `rogen.json` with v1's keys is an error that links to the [migration page](/docs/v2/migrating-from-v1).
