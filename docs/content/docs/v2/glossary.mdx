## The Pipeline

- **Root directory**: A directory Rogen scans and watches for code, listed in `rootDirs`. With several, their feature folders merge into one tree, and the later one wins a clash. See [Project Layout](/docs/v2/core-concepts/project-layout#several-root-directories).

- **Common root**: The deepest folder that contains every root directory. Rogen works it out; you never write it in the config. See [Sync Directory](/docs/v2/core-concepts/output#sync-directory).

- **Linked directory**: A symlink or Windows junction inside a root directory, read as the directory it points to. See [Project Layout](/docs/v2/core-concepts/project-layout#linked-directories).

- **Feature folder**: A folder inside a root directory that holds everything for one gameplay feature, whichever service each file ends up in. See [Routing](/docs/v2/core-concepts/routing#routing-folders).

- **Sync directory**: The folder Rojo syncs from, set as `syncDir`: your compiler's output. See [Output and Sync](/docs/v2/core-concepts/output#sync-directory).

- **Template**: The Rojo project file that Rogen merges its generated tree into, set as `template`. See [Output and Sync](/docs/v2/core-concepts/output#template).

- **Output**: The Rojo project file a config writes, set as `outFile`. Rogen owns it. See [Output and Sync](/docs/v2/core-concepts/output#output).

- **Build**: One complete run that turns the root directories into an output for one config. See [CLI](/docs/v2/cli#build-name).

- **Rendering**: The tree written out as a project file, with its `$path`s rooted at one folder. See [Output and Sync](/docs/v2/core-concepts/output#one-tree-two-renderings).

- **Watch**: A long-running build that rewrites its output when files change, and reloads when a config changes. See [CLI](/docs/v2/cli#watch-name).

- **Toolchain**: The language (Luau or roblox-ts), an optional processor and the package manager a project uses. `init` detects it once. See [CLI](/docs/v2/cli#init-name).

- **Processor**: A tool such as Darklua that rewrites your code into a folder of its own before Rojo syncs it. See the [Darklua guide](/docs/v2/setups/darklua).

- **Place**: One Roblox place in a repo that builds several, written as a config that extends a shared one. See the [multi-place guide](/docs/v2/setups/multi-place).

## Routing

- **Service**: A top-level Roblox container that code can go in, such as `ServerScriptService`. See [Routing](/docs/v2/core-concepts/routing#targets).

- **Route**: An entry in `routes` that sends files to a target. Its name is the **route key**. See [Routing](/docs/v2/core-concepts/routing).

- **Governing route**: The one route that decides where a file goes: the first one Rogen meets, walking down from the root directory. Every route after it is ignored. See [Routing](/docs/v2/core-concepts/routing#the-governing-route).

- **Target**: The path a route places files at. Its first segment is a service. See [Routing](/docs/v2/core-concepts/routing#targets).

- **Fallback route**: The `*` route, for files no other route matched. See [Routing](/docs/v2/core-concepts/routing#files-that-match-no-route).

- **Routing folder**: A folder named after a route key, like `Server/` or `@server/`. When it governs, it disappears from the generated tree. Below another route, it's an ordinary folder. See [Routing](/docs/v2/core-concepts/routing#routing-folders).

- **Suffix**: The end of a name that routes it or marks a variant. Routes use `@` (`Save@server.luau`, `Matchmaking@server/`), variants use a dot (`Analytics.mock.luau`), and Rojo's `.server` and `.client` route too when a key of that name exists. See [Routing](/docs/v2/core-concepts/routing#the--sign).

- **Declared key**: A route key, a variant or a mode. All three are recognized as a folder, a marker file or a suffix. See [Variants](/docs/v2/core-concepts/variants#marking-files).

- **Marker file**: An empty file named after a declared key with its sign, `@server` for a route and `.mock` for a variant, which applies it to its folder and everything below. See [Routing](/docs/v2/core-concepts/routing#marker-files).

- **Metadata file**: Rojo's `*.meta.json`, which sets a class, properties or attributes. See [Project Layout](/docs/v2/core-concepts/project-layout#metadata-files).

- **Invisible folder**: A folder written as `(name)`, left out of the generated tree. See [Project Layout](/docs/v2/core-concepts/project-layout#invisible-folders).
- **Hoisted name**: A file or folder name that starts with `^`, which lands directly at its route's target, dropping every folder in between. See [Routing](/docs/v2/core-concepts/routing#hoisted-names).

- **Init folder**: A folder with an `init` or `index` script, which Rojo treats as one instance. See [Project Layout](/docs/v2/core-concepts/project-layout#init-folders).

## Variants and Filtering

- **Variant**: A name declared in `variants` that marks another version of a file, kept right next to it. See [Variants](/docs/v2/core-concepts/variants).

- **Active variant**: A variant that's on for the current build. Its suffix is stripped, and its file replaces the plain one. See [Variants](/docs/v2/core-concepts/variants#declaring-variants).

- **Dormant variant**: A declared variant that's off for the current build. See [Variants](/docs/v2/core-concepts/variants#declaring-variants).

- **Variant folder**: A folder named after a declared variant. It never appears in the tree. See [Variants](/docs/v2/core-concepts/variants#variant-folders).

- **Mode**: A named environment declared in `modes`, such as `dev` or `prod`, of which exactly one is active per build. It marks files like a variant does and can switch variants and add excludes, but never changes where files go. See [Modes](/docs/v2/core-concepts/modes).

- **Active mode**: The mode the build runs in, picked by `--mode`, the config's `mode` field, or the first one declared. See [Modes](/docs/v2/core-concepts/modes#picking-the-mode).

- **Pruned**: Left out of the output because the file belongs to a dormant variant or to a mode that isn't active. See [Variants](/docs/v2/core-concepts/variants#declaring-variants).

- **Excluded**: Left out of the output because the file, or the template `$path` that mounts it, matches an `exclude` glob. See [Project Layout](/docs/v2/core-concepts/project-layout#excluding-files).

- **Mounted**: Left out of the scan because a template `$path` points at it, inside a root directory. Rojo reads it as it is, and Rogen neither routes it nor warns about it. See [Output and Sync](/docs/v2/core-concepts/output#template).

- **Displaced**: Left out of the output because the template defines the file's node, or gives one of its folders a `$path`. See [Output and Sync](/docs/v2/core-concepts/output#template).

## Configuration

- **Config**: A `<name>.rogen.json` file. One config is one tree and one output. See [Configuration](/docs/v2/configuration).

- **Legacy config**: A config written for Rogen 1, which v2 doesn't read. A `.rogen.json` that fails to load and has v1's keys gets a hint that links to the [migration page](/docs/v2/migrating-from-v1).

- **Override**: A CLI flag that replaces a config value for a single run. See [CLI](/docs/v2/cli#options).
