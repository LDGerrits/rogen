Rogen writes the project file, and `rogen serve` starts [Rojo](https://rojo.space) on it. The syncing, and every setting on this page, belongs to Rojo's Studio plugin: Rogen doesn't change the plugin. What follows is how Rojo 7.7 behaves; the plugin is Rojo's to change, so look in its settings page when a name differs. Install the plugin that matches your Rojo with `rogen plugin install`, which has the Rojo your project pins do it.

## Connect Without Clicking

Rojo's plugin can connect on its own, with **Auto Reconnect**. It is off by default, so turn it on in the plugin's settings page, once. It connects when a place opens, only for a place you connected before, to the host and port you used for that place last time. After a lost connection it doesn't try again until a place opens.

**Start `rogen serve` before you open the place.** Rojo looks for a server only as the place opens, and reminds you to connect, about every 30 seconds, when it finds one later.

<Callout type="warn">
	Rojo remembers a place by its place ID, and doesn't remember an unsaved local
	file or one of Roblox's starter templates (Baseplate, Flat Terrain and the
	like), so Auto Reconnect has nothing to go by for them. It also forgets a
	place it hasn't synced in about five months. Publish the place, or save it
	to Roblox, then connect once by hand.
</Callout>

Rojo also checks the **name of the project** against the one it synced last: a place reconnects only to a server that serves a project of the same name. That name is `name` in the config, which Rogen writes to the project file. Without one, Rojo names a `default.project.json` after its folder, and every other project file needs a `name`. Give the project a name, and keep it.

### The Confirmation Dialog

Rojo's plugin asks to confirm the first changes of each project in a session. Its **Confirmation Behavior** setting changes when:

- **Initial**, the default: once per project per session.
- **Unlisted PlaceId**: only when the place isn't in the project's `servePlaceIds`, which is the next section. A place you listed connects without asking.
- **Large Changes**: only when a patch changes at least as many instances as the **Confirmation Threshold** setting, 5 by default.
- **Never** and **Always**.

## Place IDs

A config can say which places the server is for, with `servePlaceIds`, as a Rojo project file does:

```json title="default.rogen.json"
{
	"name": "Game",
	"servePlaceIds": [1818],
	"rogen": { "routes": { "*": "ReplicatedStorage" } }
}
```

Rojo refuses to connect from any other place, and says which IDs it expects. `blockedPlaceIds` does the opposite, and names places that may never connect. Rogen writes both to the project file as they are. They are ordinary Rojo keys in every config file, so a `dist.rogen.json` repeats them.

<Callout type="warn">
	A place that was never saved to Roblox has the place ID `0`, which no list
	holds, so a listed project refuses it. Add the IDs to the config once the places are
	published.
</Callout>

### Several places

Each [place](/docs/v2/setups/places) is served by naming it, and a second place at once is a second terminal with `--port`. Studio remembers a port per place, so a Studio opened on the wrong place can end up on another place's port and sync that place's code. Give each place its own `servePlaceIds` in its `default.rogen.json`, and Rojo refuses the connection from any other place, with an error that names `servePlaceIds`:

```json title="places/lobby/default.rogen.json"
{
	"name": "Lobby",
	"servePort": 34872,
	"servePlaceIds": [1818],
	"rogen": {
		"sourcePaths": ["../shared/src", "src"],
		"routes": { "*": "ReplicatedStorage" }
	}
}
```

Rogen writes no port and picks none: set `servePort` yourself, or pass `--port` to the second terminal.

## The Port

`rogen serve` starts the server on the `servePort` of the config, else on 34872. A second `rogen serve` at the same time needs `--port` or its own `servePort`, as a second `rojo serve` does. In Studio, connect to that port. Rojo remembers the port for a place after the first connect, so Auto Reconnect takes it back to the same one. See [`serve`](/docs/v2/cli#serve) for how Rogen picks the Rojo and the port.

## Serve With Argon

`rogen serve` only starts Rojo. [Argon](https://github.com/argon-rbx/argon) reads the Rojo project files Rogen writes, so run `rogen write --watch` to keep the project file current, and serve it with Argon, from its VS Code extension or with `argon serve` beside it. Argon's plugin and its settings are then Argon's own. A project file with [`syncRules`](/docs/v2/configuration#sync-rules) is Rojo's alone, since Argon rejects it.
