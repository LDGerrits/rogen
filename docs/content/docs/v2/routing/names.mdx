---
title: Routing by Name
description: Route a file or folder without moving it into a routing folder
---

When a feature is too small for routing folders, route by name instead.

## The `@` Suffix

`@` and a route key at the end of a file or folder name route it, and come off the name. A file keeps its class, so `TradeService@Server.luau` stays a ModuleScript:

<RouteFigure
	disk={`
  src/
    Trade/
      Admin@Server/
        Ban.luau
      TradeService@Server.luau
      TradeTypes@Shared.luau
      TradeUi@Client.luau
`}
	studio={`
  ReplicatedStorage
    Shared/
      Trade/
        TradeTypes
  ServerScriptService
    Trade/
      Admin/
        Ban
      TradeService
  StarterPlayer
    StarterPlayerScripts
      Trade/
        TradeUi
`}
/>

## Marker Files

An empty file named `@Server` routes the folder it's in, and the folder keeps its name:

<RouteFigure
	disk={`
  src/
    Anticheat/
      @Server
      Check.luau
      Report.luau
`}
	studio={`
  ServerScriptService
    Anticheat/
      Check
      Report
`}
/>

## Rojo's Script Suffixes

When your config has a `Server` or `Client` key, Rojo's `.server` and `.client` suffixes route a script as well as set its class, so `Main.server.luau` goes to the server. A sync rule's `suffix` routes another language's scripts the same way, such as `.server.lang`.

## Init Scripts

A route in an init script's name places only the script, not the folder around it; to move the whole folder, route the folder itself. That lets each side have its own init script:

<RouteFigure
	disk={`
  src/
    Shop/
      init@Server.luau
      init@Client.luau
      ShopService@Server.luau
      ShopUi@Client.luau
`}
	studio={`
  ServerScriptService
    Shop
      ShopService
  StarterPlayer
    StarterPlayerScripts
      Shop
        ShopUi
`}
/>

A plain `init.luau` routes the same way: it is its folder only where its own route puts it, which is `*` unless something routes it. On every other side the folder's files sit in a plain folder of the same name, so the init script reaches a server-only child by its full path, as `ServerScriptService.Shop.ShopService`, rather than through `script`.

## Patterns

A route key with a wildcard routes files by their name, so a project that names files by their role, such as `ShopController.luau`, needs no `@` on each one:

```json title="default.rogen.json"
{
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared",
		"*Controller.*": "StarterPlayer/StarterPlayerScripts",
		"*Service.*": "ServerScriptService",
		"*": "ReplicatedStorage/Shared"
	}
}
```

<RouteFigure
	disk={`
  src/
    Shop/
      ShopController.luau
      ShopService.luau
      Prices.luau
      Shared/
        PriceService.luau
`}
	studio={`
  ReplicatedStorage
    Shared/
      Shop/
        PriceService
        Prices
  ServerScriptService
    Shop/
      ShopService
  StarterPlayer
    StarterPlayerScripts
      Shop/
        ShopController
`}
/>

A pattern routes a file by its name, and keeps the whole name, so `ShopController.luau` stays `ShopController`. It takes only a file that no folder, `@` or marker routes, which is why `PriceService` stays in `Shared/`, and it never matches a folder or an init script. When several patterns match, the longer one wins, so `*.story.tsx` beats `*.tsx`. Patterns use Rojo's glob syntax for one name (`*`, `?`, `[Ss]`, `{a,b}`) and match letter case exactly.
