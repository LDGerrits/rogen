---
title: The Tree
description: Mount packages and the other things that folder names can't place
---

The `tree` in your config is a Rojo project tree. Rogen adds your routed files to it and writes the result to `default.project.json`. Folder names place only the code in your source paths, so everything else goes in the `tree`: packages, the place's map, and anything a Rojo tree can hold, such as a service's `$properties`.

## Packages

Mount a package folder with `$path` where your code requires it from, as in `require(ReplicatedStorage.Packages.Promise)`. Wally installs into `Packages`:

```json title="default.rogen.json"
{
	"routes": {
		"Server": "ServerScriptService",
		"Shared": "ReplicatedStorage/Shared"
	},
	"tree": {
		"$className": "DataModel",
		"ReplicatedStorage": {
			"Packages": { "$path": "Packages" }
		}
	}
}
```

`rogen init` mounts the package folders it finds, so install your packages before you run it. Wally makes `ServerPackages` only once you add a server dependency, so mount it in ServerScriptService then. A mounted folder that's missing stops `rogen serve` and `rogen build` with Rojo's error, rather than leaving your requires to fail in Studio. In a roblox-ts project, init mounts `node_modules/@rbxts`, as [Using roblox-ts](/docs/v2/roblox-ts) shows.

## The Place

`rogen init` puts the starting map, a baseplate and Rojo's lighting, in a `place` folder and mounts it, unless you pass `--no-sample`. The folder sits outside the source paths, so Rogen doesn't route it:

```json title="default.rogen.json"
{
	"tree": {
		"$className": "DataModel",
		"Lighting": { "$path": "place/Lighting" },
		"SoundService": { "$path": "place/SoundService" },
		"Workspace": { "$path": "place/Workspace" }
	}
}
```
