---
title: How Routing Works
description: Name a folder or file after a route, and Rogen puts it where the route points
---

Your config's `routes` name the places your code can go in the game:

```json title="default.rogen.json"
{
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared",
		"*": "ReplicatedStorage/Shared"
	}
}
```

A route's name in a file's path sends the file there. A `Server/` folder sends everything inside it, and `@Client` at the end of a name sends one file:

<RouteFigure
	disk={`
  src/
    Shop/
      Server/
        ShopService.luau
      Shared/
        Prices.luau
      ShopUi@Client.luau
`}
	studio={`
  ReplicatedStorage
    Shared/
      Shop/
        Prices
  ServerScriptService
    Shop/
      ShopService
  StarterPlayer
    StarterPlayerScripts
      Shop/
        ShopUi
`}
/>

The name is spelled exactly as the key. A folder or `@` that misses it by its case or, for an `@`, a typo, as `server/`, `Save@server.luau` or `Save@Sever.luau` under a `Server` route, would send server code to `*`, so Rogen stops until you fix it. Only Rojo's own `.server` and `.client`, which it reads in lower case, route a key of that name in any case. Everything else in the path stays, so `Shop` shows up under each service. [Routing Folders](/docs/v2/routing/folders) and [Routing by Name](/docs/v2/routing/names) show each way to route in full, and [Skipping Folders](/docs/v2/routing/skipping-folders) how to leave a folder out.

## Files Without a Route

The `*` route takes every file that no other route matches, so `src/Shop/Prices.luau` lands in `ReplicatedStorage/Shared/Shop`. A [pattern route](/docs/v2/routing/names#patterns) such as `*.tsx` takes a file by its name before `*` does. `rogen init` writes it. Without `*`, Rogen leaves such a file out and warns about it, so a server file that forgets its route never reaches clients. That suits a project where every file names its side.

## The Outermost Route Wins

A route inside another route is an ordinary folder. Server code under `Shared/` ships to every client, and Rogen warns about it:

<RouteFigure
	disk={`
  src/
    Shared/
      Server/
        Datastore.luau
`}
	studio={`
  ReplicatedStorage
    Shared/
      Server/
        Datastore
`}
/>

## When Rogen Stops

Rogen stops the write where a name can only have meant a route and misses it, since the file would land where you didn't send it. That covers a folder, `@` or marker file that misses a key by its case or a typo, and Rojo's `.server` or `.client` where Rojo doesn't read it, as `Main.Server.luau` or `Config.server.json`. It also stops when two files would make one instance and the build would lose one. A name that may be an ordinary name stays one, so a `Servers/` folder or a `Button.story.luau` beside a `Story` route routes nothing and Rogen says nothing about it. Where Rogen only guesses, it warns and writes: for a file that nearly matches a pattern, a file no route takes, or server code that the route above it ships to clients. Each error names the rename that fixes it, and the [diagnostics](/docs/v2/diagnostics) page explains each code.

## Check Where a File Lands

`rogen where` prints where a file lands in the game, and the require that reaches it:

```
$ rogen where src/Shop/Server/ShopService.luau
src/Shop/Server/ShopService.luau -> ServerScriptService/Shop/ShopService · route Server (folder)
  require(game:GetService("ServerScriptService").Shop.ShopService)
```
