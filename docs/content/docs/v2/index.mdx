A bad folder structure slows you down. You spend your time remembering where the related pieces live, and then hunting for them.

## The Problem: Technical Grouping

Most Roblox codebases group files by what kind of code they are, not what they're about: `Controllers`, `Services` and `Utils`, under `server`, `client` and `shared`. Rojo maps folders straight onto instances, so Roblox tooling nudges you toward that runtime split. The result is that one feature is scattered across the tree, and changing the **Inventory** system means hunting through three folders for its pieces.

David Parnas called this a mistake back in 1972. He argued that modules should hide design decisions, not follow the order in which the program runs:

> Since, in most cases, design decisions transcend time of execution, modules will not correspond to steps in the processing.
>
> — D. L. Parnas, [_On the Criteria To Be Used in Decomposing Systems into Modules_](https://wstomv.win.tue.nl/edu/2ip30/references/criteria_for_modularization.pdf) (1972)

On Roblox, _where code runs_ is one of those steps. A feature has server, client and shared code, so the feature should be the module, and where each piece runs becomes a detail inside it.

## The Solution: Package by Feature

Put all the code for one feature in a single **feature folder**, named after what it does in your game. Rogen reads your folder and file names and writes a Rojo **project file** that puts every script in the **service** where it runs. Rojo or Argon then syncs it into Studio as usual.

Your [config](/docs/v2/configuration) maps each kind of folder to a service:

```json title="default.rogen.json"
{
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared",
		"*": "ReplicatedStorage/Shared"
	}
}
```

<Callout type="info">
	**The result:** your repository stays organized by feature, and Studio still
	gets every script in the right place.
</Callout>

Feature folders are a good place to start, but [Architectures](/docs/v2/architectures) covers other layouts that work well with Rogen, like layers and ECS.
