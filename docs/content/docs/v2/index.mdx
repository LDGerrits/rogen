Rogen is a command-line tool that writes your Rojo project file for you. Rojo still syncs and builds your game, and nothing of Rogen ends up in it. To see why that helps, this page cleans up a typical Roblox project, one step at a time.

## A Typical Roblox Project

Here is a game with an inventory, a shop and combat. Its project file mounts `src/server` into ServerScriptService, `src/client` into StarterPlayerScripts and `src/shared` into a `Shared` folder in ReplicatedStorage. Inside those three folders, the code is sorted by type:

        ShopConfig.luau

      types/
        CombatTypes.luau
        InventoryTypes.luau
        ShopTypes.luau
      utils/
        DamageUtils.luau
        InventoryUtils.luau

/>

Now find everything that makes up the inventory. It's spread over seven folders, and the shop's and combat's files sit beside it in every one. To follow how the inventory works, you jump all over `src`. To remove it, you hunt down each of its files, and `ItemConfig` is easy to miss because its name doesn't mention the inventory.

This is already much easier to work with. The inventory's files no longer sit between the shop's, and `ItemConfig` is in the inventory's folder, where you'd look for it. A new feature gets a folder on each side instead of a file in every type folder. The project file doesn't even change, because Rojo still mounts the same three folders.

## Three Inventory Folders

Look at the inventory again, though. It still has a folder in `client`, one in `server` and one in `shared`. A change to the inventory often touches all three, so you still jump between them to follow it.

The next step is a single `src/Inventory` folder with the three sides inside it. Rojo can mount `src/Inventory/Server` into ServerScriptService, but every such folder needs its own entry in `default.project.json`. For three features, that's nine:

```json title="default.project.json"
{
	"name": "my-game",
	"tree": {
		"$className": "DataModel",
		"ServerScriptService": {
			"Combat": { "$path": "src/Combat/Server" },
			"Inventory": { "$path": "src/Inventory/Server" },
			"Shop": { "$path": "src/Shop/Server" }
		},
		"StarterPlayer": {
			"StarterPlayerScripts": {
				"Combat": { "$path": "src/Combat/Client" },
				"Inventory": { "$path": "src/Inventory/Client" },
				"Shop": { "$path": "src/Shop/Client" }
			}
		},
		"ReplicatedStorage": {
			"Shared": {
				"$className": "Folder",
				"Combat": { "$path": "src/Combat/Shared" },
				"Inventory": { "$path": "src/Inventory/Shared" },
				"Shop": { "$path": "src/Shop/Shared" }
			}
		}
	}
}
```

Every feature you add, rename or remove means editing this file by hand, and a folder you forget to list never reaches the game. That upkeep is why projects sorted by feature usually keep the three side folders.

In Studio, the game is the same as when you sorted by feature, so your requires don't change. On disk, everything about the inventory is in `src/Inventory`. You read it in one place, and you remove it by deleting one folder. Keeping a feature's code together like this is called colocation.

## How Rogen Does It

Your config, `default.rogen.json`, is a Rojo project file with [`routes`](/docs/v2/config) added. Each route names a folder and where its files go:

```json title="default.rogen.json"
{
	"name": "my-game",
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared"
	},
	"tree": {
		"$className": "DataModel"
	}
}
```

From it, Rogen writes `default.project.json` with the same nine entries you would have written by hand, and adds new ones as you add features. `rogen serve` writes the project file, runs `rojo serve`, and keeps the file up to date while you work. `rogen build` writes it and runs `rojo build`. Both take Rojo's flags.

A feature with a single server file can skip the folder: name the file `CombatService@Server.luau`. [How Routing Works](/docs/v2/core-concepts/routing) shows both ways.

In short, Rogen is a superset of Rojo that generates Rojo project files from your file system. To try it on an existing Rojo project, [install Rogen](/docs/v2/installation) and run `rogen init`. It turns your `default.project.json` into a `default.rogen.json` and leaves your files where they are.
