Rogen is a command-line tool that writes your Rojo project file for you. You run `rogen serve` where you ran `rojo serve`, and Rojo still syncs your game into Studio. Nothing of Rogen ends up in the game. What changes is how you can organize your code: by feature, with its server and client code in one folder.

## Organized by Type

Rojo maps each folder you list in the project file to one service in the game. A typical project lists three: `src/server` for ServerScriptService, `src/client` for StarterPlayerScripts and `src/shared` for ReplicatedStorage. Inside them, the code is often sorted again by type, into folders such as `services`, `controllers` and `utils`:

<RouteFigure
	disk={`
  src/
    server/
      services/
        InventoryService.luau
        ShopService.luau
    client/
      controllers/
        InventoryController.luau
        ShopController.luau
      ui/
        InventoryWindow.luau
        ShopWindow.luau
    shared/
      types/
        InventoryTypes.luau
        ShopTypes.luau
      utils/
        InventoryUtils.luau
        ShopUtils.luau
        TableUtils.luau
`}
/>

The inventory is spread over five folders, and the shop's files sit beside it in each one. To change how the inventory works, you jump between files far apart in the tree. To delete it, you hunt down each of its files, and its helpers in `utils` tend to stay behind.

## Feature Folders on Each Side

Sorting by feature helps, because a feature's files usually change together. Rojo can mount `src/Inventory/Server` into ServerScriptService, but only with its own entry in the project file. Every feature needs an entry for each side, and you keep them in sync by hand as features come and go. So most games settle for a feature folder on each side:

<RouteFigure
	disk={`
  src/
    server/
      Inventory/
        InventoryService.luau
      Shop/
        ShopService.luau
    client/
      Inventory/
        InventoryController.luau
        InventoryWindow.luau
      Shop/
        ShopController.luau
        ShopWindow.luau
    shared/
      Inventory/
        InventoryTypes.luau
        InventoryUtils.luau
      Shop/
        ShopTypes.luau
        ShopUtils.luau
      Utils/
        TableUtils.luau
`}
/>

The inventory now has a folder on each side, three in all, far apart in the tree. Deleting the feature still takes three deletes.

## One Folder per Feature

With Rogen, the feature is one folder. A `Server`, `Client` or `Shared` folder inside it says where its files go:

<RouteFigure
	disk={`
  src/
    Inventory/
      Server/
        InventoryService.luau
      Client/
        InventoryController.luau
        InventoryWindow.luau
      Shared/
        InventoryTypes.luau
        InventoryUtils.luau
`}
	studio={`
  ReplicatedStorage
    Shared/
      Inventory/
        InventoryTypes
        InventoryUtils
  ServerScriptService
    Inventory/
      InventoryService
  StarterPlayer
    StarterPlayerScripts
      Inventory/
        InventoryController
        InventoryWindow
`}
/>

Each file still runs where it did, and everything about the inventory is in `src/Inventory`. You read it in one place, and you delete it by deleting one folder. Keeping a feature's code together like this is called colocation.

A feature with a single server file can skip the folder and name the file `InventoryService@Server.luau`. [How Routing Works](/docs/v2/core-concepts/routing) shows both ways. In Studio the files still sit in different services, so code requires them by their path in the game. `rogen where` prints that path and the `require` line for any file.

## Rogen Writes the Project File

Rogen is a superset of Rojo that generates Rojo project files from your file system. Your config, `default.rogen.json`, is a Rojo project file with [`routes`](/docs/v2/config) added. Each route names a folder and the service it goes to. Rogen finds every file whose path names a route, and writes `default.project.json` with the entries you would otherwise write by hand. This is the part it writes for the inventory's server code:

```json title="default.project.json"
"ServerScriptService": {
	"$className": "ServerScriptService",
	"Inventory": {
		"$path": { "optional": "src/Inventory/Server" }
	}
}
```

Rogen doesn't build or sync your game itself. `rogen serve` writes `default.project.json`, runs `rojo serve`, and writes the project file again when your files change. `rogen build` writes it and runs `rojo build`. Both take Rojo's flags. To start from an existing Rojo project, run `rogen init` in it. It turns your `default.project.json` into a `default.rogen.json` and keeps your tree.
