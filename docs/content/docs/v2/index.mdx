Rogen is a command-line tool that writes your Rojo project file for you, while Rojo still syncs and builds your game. Here is why that helps.

## A Typical Roblox Project

This game has an inventory and a shop. Its project file mounts `src/server` into ServerScriptService, `src/client` into StarterPlayerScripts and `src/shared` into a `Shared` folder in ReplicatedStorage. Inside them, code is sorted by type:

        InventoryTypes.luau
        ShopTypes.luau

The inventory is spread over six folders, mixed in with the shop, so changing or removing it means hunting through all of them.

## Feature Folders in Rojo

Sorting each side by feature helps, but the inventory still has three folders, one each in `client`, `server` and `shared`. A single `src/inventory` folder is better, and Rojo can do it if you give every side of every feature its own entry in `default.project.json`:

```json title="default.project.json"
{
  "name": "my-game",
  "tree": {
    "$className": "DataModel",
    "ServerScriptService": {
      "inventory": { "$path": "src/inventory/server" },
      "shop": { "$path": "src/shop/server" }
    },
    "StarterPlayer": {
      "StarterPlayerScripts": {
        "inventory": { "$path": "src/inventory/client" },
        "shop": { "$path": "src/shop/client" }
      }
    },
    "ReplicatedStorage": {
      "Shared": {
        "$className": "Folder",
        "inventory": { "$path": "src/inventory/shared" },
        "shop": { "$path": "src/shop/shared" }
      }
    }
  }
}
```

Every feature you add, rename or remove means editing this file by hand, and a folder you forget never reaches the game.

## One Folder per Feature

Rogen writes those entries for you when you put each feature in one folder, with `client`, `server` and `shared` folders inside:

	disk={`

    inventory/
      client/
        InventoryController.luau
        InventoryWindow.luau
      server/
        InventoryService.luau
        InventoryStore.luau
      shared/
        InventoryTypes.luau
        ItemConfig.luau
    shop/
      client/
        ShopController.luau
        ShopWindow.luau
      server/
        ShopService.luau
      shared/
        ShopConfig.luau
        ShopTypes.luau
`}
	studio={`
  ReplicatedStorage
    shared/
      inventory/
        InventoryTypes
        ItemConfig
      shop/
        ShopConfig
        ShopTypes
  ServerScriptService
    inventory/
      InventoryService
      InventoryStore
    shop/
      ShopService
  StarterPlayer
    StarterPlayerScripts
      inventory/
        InventoryController
        InventoryWindow
      shop/
        ShopController
        ShopWindow
`}
/>

Studio gets the same tree as the hand-written project file, while everything about the inventory sits in `src/inventory` and you remove it by deleting one folder.

## How Rogen Does It

You write `default.rogen.json`, a Rojo project file with [`routes`](/docs/v2/config) added, where each route names a folder and where its files go. Rogen adds the routed files to the [`tree`](/docs/v2/routing/tree), which holds what folder names can't place, such as your packages:

```json title="default.rogen.json"
{
  "name": "my-game",
  "routes": {
    "server": "ServerScriptService",
    "client": "StarterPlayer/StarterPlayerScripts",
    "shared": "ReplicatedStorage/Shared"
  },
  "tree": { "$className": "DataModel" }
}
```

`rogen serve` and `rogen build` write `default.project.json` from it, then run `rojo serve` and `rojo build` with Rojo's flags. To try it on an existing project, [install Rogen](/docs/v2/installation) and run `rogen init`.
