Rogen is a superset of Rojo that generates Rojo project files from your file system. It lets you keep all the code for a feature in one folder, even when part of it runs on the server and part of it on the client.

## Organized by Type

Many Roblox games sort their code by type. A Rojo project maps `src/server` to ServerScriptService, `src/client` to StarterPlayerScripts and `src/shared` to ReplicatedStorage, and inside those folders the code is sorted again, into folders such as `services`, `controllers` and `types`:

<RouteFigure
	disk={`
  src/
    server/
      services/
        InventoryService.luau
        ShopService.luau
    client/
      controllers/
        InventoryController.luau
        ShopController.luau
    shared/
      types/
        InventoryTypes.luau
        ShopTypes.luau
`}
/>

The inventory is spread over three folders, and each of those folders also holds a piece of every other feature. To change how the inventory works, you edit files far apart in the tree. To delete it, you hunt down every file that belongs to it. The more features a game has, the longer each of those folders gets.

## Organized by Feature

Organizing by feature is much better. A feature's files change together, so they belong together, and a folder named `Inventory` tells you what is in it. But a Rojo project still splits the code by where it runs, so the best you can do is a feature folder on each side:

<RouteFigure
	disk={`
  src/
    server/
      Inventory/
        InventoryService.luau
      Shop/
        ShopService.luau
    client/
      Inventory/
        InventoryController.luau
      Shop/
        ShopController.luau
    shared/
      Inventory/
        InventoryTypes.luau
      Shop/
        ShopTypes.luau
`}
/>

Each folder now holds one feature, but each feature still lives in three folders. The server half of the inventory sits far from its client half, and deleting the feature still means deleting it three times.

## One Feature, One Folder

Rogen removes the split. The feature is one folder, and a `Server`, `Client` or `Shared` folder inside it says where its code goes:

<RouteFigure
	disk={`
  src/
    Inventory/
      Server/
        InventoryService.luau
      Client/
        InventoryController.luau
      Shared/
        InventoryTypes.luau
`}
	studio={`
  ReplicatedStorage
    Shared/
      Inventory/
        InventoryTypes
  ServerScriptService
    Inventory/
      InventoryService
  StarterPlayer
    StarterPlayerScripts
      Inventory/
        InventoryController
`}
/>

Rogen reads those folder names and writes `default.project.json`, which mounts each file in the right service. In Studio, the game looks as it did before. On disk, everything about the inventory is in `src/Inventory`, so you read it in one place and delete it by deleting one folder.

Keeping all of a feature's code together like this is called colocation. With Rojo alone, the split between server and client code stood in the way.

## Rojo Still Runs Your Game

Rogen doesn't build or sync your game itself. It writes the project file, and then Rojo does what it always did. `rogen serve` writes `default.project.json`, runs `rojo serve`, and writes the file again when you add or move a file. `rogen build` writes it and runs `rojo build`. Both take Rojo's flags. A project without a Rogen config works as it does with Rojo.

## The Config

A Rogen config is a Rojo project file with `routes` added. The `tree` is the base: put in it what your folder names can't say, such as your packages, and Rogen adds every routed file to it.

```json title="default.rogen.json"
{
	"name": "my-game",
	"routes": {
		"Server": "ServerScriptService",
		"Client": "StarterPlayer/StarterPlayerScripts",
		"Shared": "ReplicatedStorage/Shared",
		"*": "ReplicatedStorage/Shared"
	},
	"tree": {
		"$className": "DataModel",
		"ReplicatedStorage": {
			"Packages": { "$path": "Packages" }
		}
	}
}
```

Each route names a folder and where its files go. The `*` route takes every file that no other route matches. The routes are yours to change: add `"Gui": "StarterGui"`, and a `Gui` folder sends its files to StarterGui.
