Rogen is a superset of Rojo that generates Rojo project files from your file system. You keep each feature's code in one folder, and Rogen puts every file in the service where it runs.

## Why Rogen?

Rojo puts a folder where the project file mounts it, so most Roblox codebases are split by where code runs. One feature ends up in three places, and changing it means opening all of them:

<RouteFigure
	disk={`
  src/
    client/
      Controllers/
        InventoryController.luau
    server/
      Services/
        InventoryService.luau
    shared/
      Types/
        InventoryTypes.luau
`}
/>

With Rogen, the feature is the folder, and where each file runs is a detail inside it. Rogen writes the project file that puts each piece in its service:

<RouteFigure
	disk={`
  src/
    Inventory/
      Client/
        InventoryController.luau
      Server/
        InventoryService.luau
      Shared/
        InventoryTypes.luau
`}
	studio={`
  ReplicatedStorage
    Shared/
      Inventory/
        InventoryTypes
  ServerScriptService
    Inventory/
      InventoryService
  StarterPlayer
    StarterPlayerScripts
      Inventory/
        InventoryController
`}
/>

David Parnas made the same case in 1972: a module should hide a design decision, not follow the order the program runs in ([_On the Criteria To Be Used in Decomposing Systems into Modules_](https://wstomv.win.tue.nl/edu/2ip30/references/criteria_for_modularization.pdf)).

## It's Still Rojo

Rojo still serves, builds and syncs your game. `rogen serve` and `rogen build` take Rojo's flags, and a project without a Rogen config works as it did. [Commands](/docs/v2/commands) lists them all.
