title: Architectures
description: Folder layouts that work well with Rogen
---

Rogen puts each file where its route sends it, so the layout of your folders is yours to choose. Two layouts work well with it.

## Feature Folders

Give each feature one folder, with a routing folder inside for each side it runs on. The [Introduction](/docs/v2) shows how `src/Inventory` holds everything about the inventory, and [Routing Folders](/docs/v2/core-concepts/routing/folders) how it reaches the game.

Features talk to each other through what they put in `Shared/`, and a feature's `Server/` and `Client/` code is its own. To delete a feature, delete its folder.

## Layers

A larger codebase puts feature folders inside layers, and each layer requires only the layers below it:

<RouteFigure
	disk={`
  src/
    base/
      Shared/
        Signal.luau
    platform/
      Data/
        Server/
          PlayerData.luau
    features/
      Inventory/
        Client/
          InventoryController.luau
        Server/
          InventoryService.luau
`}
	studio={`
  ReplicatedStorage
    Shared/
      base/
        Signal
  ServerScriptService
    platform/
      Data/
        PlayerData
    features/
      Inventory/
        InventoryService
  StarterPlayer
    StarterPlayerScripts
      features/
        Inventory/
          InventoryController
`}
/>

`base` holds helpers that depend on nothing else, `platform` the services every feature uses, such as player data, and `features` the game itself. A feature requires `platform` and `base`, never another feature, and `platform` never requires a feature.

A layer folder stays in the game path, so a require names it, as in `ReplicatedStorage.Shared.base.Signal`. To leave the layers out of the game, make them [invisible folders](/docs/v2/core-concepts/routing/skipping-folders#invisible-folders), such as `(features)/`.

Rogen routes files, so it doesn't check that a require stays within these rules. [Linting](/docs/v2/linting) shows a lint rule that does.
