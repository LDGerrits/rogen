# Configs

A folder's config is `default.rogen.json` (or `default.rogen.jsonc`), parsed as JSONC. It is a Rojo project file with one extra key, `rogen`, holding Rogen's three keys: `sourcePaths` (default `["src"]` when `routes` exist), `routes` and `compiledPath`. Rojo's keys (`name`, `tree`, `servePort`, `servePlaceIds`, `emitLegacyScripts`, `globIgnorePaths` and the rest) stay at the top level and pass through to the project file Rogen writes beside the config, `default.project.json`. A top-level key that is neither Rojo's nor `rogen`, and an unknown key inside `rogen`, is an error. `X.rogen.json` writes `X.project.json`, so a second output (`dist`, `release`) is a second complete file that repeats `name`, `routes` and `tree`. Every path is relative to its file, and no file reads another.

A command given no argument reads the default of the current folder and looks nowhere else, as `rojo` does. A folder argument means its default, a path means that file, and a bare name `X` means `X.rogen.json` here. With no config, a `default.project.json` is read as a config whose output is itself: Rogen runs its commands on a plain Rojo project and writes nothing to it. A command writes only the project file of the config it names, so `default.project.json` is as fresh as its last `rogen build`: build again after adding a feature folder, and after a clone before the editor or a compiler needs it. `rogen list` shows the files of a folder and how each differs from `default`.

- `tree` is the instance tree Rogen merges its generated nodes into, as in any Rojo project file. It holds what names can't express: the DataModel name, package mounts and `$properties`. The tree wins a clash. A `$path` into a source path is Rojo's: Rogen skips that folder, so mount vendored code there to sync it as it is. With `routes`, the tree's root must be a DataModel; without them any root is valid and the file is written as it is.
- Without `routes`, nothing is routed and no source path is scanned, and `sourcePaths` is an error. Rogen warns when `src` holds files the tree doesn't mount.
- Several `sourcePaths` merge into one tree, and the later one wins a clash. Paths are relative to the folder of the config.
- `globIgnorePaths` lists globs, relative to the folder, that Rojo ignores and Rogen keeps out of routing, such as `**/*.spec.luau`. A mount of `tree` whose folder or file a glob names, or covers with `/**` (`DevPackages/**`), is left out of the project file; a glob that ignores only some of its files leaves the mount.
- `compiledPath` is the compiler's output (`out` for roblox-ts, `dist` for Darklua), where emitted `$path`s point. It repeats the layout of the source paths under their common folder, so `["../shared/src", "src"]` in `places/lobby` with `out` reads `out/shared/src` and `out/lobby/src`; `rogen list` prints the layout. It may not overlap a source path.
- A place has its own complete config: its own `name`, `sourcePaths` in full and `routes`. In Luau it is a `lobby.rogen.json` at the root (`["src/common", "src/lobby"]`), in roblox-ts a folder of `projects/` with a `default.rogen.json` (`["../common/src", "src"]`). Shared code is a plain folder, with no config. A place is served by naming it, as `rogen serve lobby` or `rogen serve projects/lobby`; `servePort`, `servePlaceIds`, `blockedPlaceIds`, `placeId` and `gameId` are ordinary keys in every file, and Rogen writes no port. A second place served at once takes `--port`. A bare command at a root that holds only places is Rojo's "not found" error.
- `syncRules` is Rojo's list of rules that turn a file name into an instance, tried before Rojo's own. Rogen reads files by it and writes it to each project file, moved with the files it takes.
- `extends`, `projects`, `serveProject`, `placePaths`, `syncPath`, `template`, `outFile` and `exclude` are errors that name what replaces them.

The project file carries `name` only when the config sets one; Rojo names the project after its folder otherwise. A file other than `default` must set `name`, since Rojo can't read its project file without one.

Ownership:

- `rogen build` overwrites the project file of the config it builds: put changes in the `.rogen.json`. `*.project.json` is gitignored by `init`; `!name.project.json` keeps one.
- The `compiledPath` is compiler output: edit the sources in the source paths.
