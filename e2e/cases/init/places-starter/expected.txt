README.md:
# project
Generated by [Rogen](https://rogen-roblox.vercel.app/).

## What's here
`src/common` holds the code every place shares, here the `Greeter` feature: one folder for the code that belongs together. `src/lobby` holds the code of the lobby place alone.

A place is a `<place>.rogen.json` at the root: `lobby.rogen.json` lists the source paths `src/common` and `src/lobby`, and Rogen writes `lobby.project.json` from it.

The tree in `lobby.rogen.json` holds Rojo's sample Baseplate and the Lighting and SoundService settings, as `$properties` and a `Baseplate` node, and Rogen routes nothing in it.

The folders inside a feature decide where its code runs: `Server` goes to ServerScriptService, `Client` to StarterPlayerScripts and `Shared` to ReplicatedStorage/Shared. To see where a file lands, and how to require it, use:

```bash
rogen where src/common/Greeter/Shared/Greeting.luau
```

`rogen check` and `rogen where` find the place a path belongs to, and a file in `src/common` belongs to every place. `rogen check` with no path checks every place. `rogen where lobby` lists the files of one place.

## Getting Started
To serve the lobby place and connect to it from Roblox Studio, use:

```bash
rogen serve lobby
```

To build the lobby place from scratch, use:

```bash
rogen build lobby -o "project.rbxlx"
```

## Changing the project
Edit `lobby.rogen.json`, not `lobby.project.json`, which `rogen write` replaces. After you add a feature folder, run `rogen write lobby` so the editor's `lobby.project.json` follows. The `routes` in each config say where each folder's code goes, and a folder to place as it is, such as `Packages`, is mounted in the `tree` of each.

## Adding a place
Copy `lobby.rogen.json` to `match.rogen.json`, change its `name` to `match` and its source path `src/lobby` to `src/match`, and make the `src/match` folder. Give the copy its own `name` and source path, since Rogen errors while two configs match, and `lobby.release.rogen.json`, if there is one, needs the same copy. A second place is served from a second terminal, with its own `--port`:

```bash
rogen serve match --port <port>
```

## Editor
A sourcemap describes one place, so luau-lsp knows one place at a time: the one in `.vscode/settings.json`. It runs

```bash
rogen sourcemap lobby --watch -o sourcemap.json
```

to keep `sourcemap.json` current as files come and go. To switch place, change `lobby` to the name of another in that setting.

To check every place exactly at once, for an agent or CI, check each place against its own sourcemap:

```bash
rogen sourcemap lobby -o sourcemap.json && luau-lsp analyze --definitions=@roblox=<types.d.luau> --sourcemap=sourcemap.json src/common src/lobby
```

For more help, check out [the Rogen documentation](https://rogen-roblox.vercel.app/).
