$ rogen help build
exit 0
stdout:
  rogen-build
  Writes the project file of default.rogen.json here, or of the config you name, beside it
  (dist.rogen.json writes dist.project.json), then builds a place, model or plugin from it with Rojo,
  as 'rojo build' does: -o or -p is required. To write the project file only, run 'rogen write'.
  
  USAGE:
      rogen build [OPTIONS] [PROJECT]
  
  ARGS:
      <PROJECT>    A folder, a .rogen.json file, a *.project.json path, or the name of a file here. A
                   name such as dist stands for dist.rogen.json. The default.rogen.json of the working
                   directory, or its default.project.json, when none is given.
  
  OPTIONS:
          --color <COLOR>      Whether to colour the output. [default: auto] [possible values: auto,
                               always, never]
      -h, --help               Print help.
          --json               Print one JSON document instead of text.
      -o, --output <OUTPUT>    Build the project into this place or model file with Rojo (.rbxl,
                               .rbxlx, .rbxm or .rbxmx). This or -p is required.
      -p, --plugin <PLUGIN>    Build the project into Roblox's plugins folder with Rojo, under this
                               file name. This or -o is required.
      -q, --quiet              Only print errors.
      -v, --verbose            Print debug output; -vv, trace output. (repeatable)
      -V, --version            Print the version.
          --watch              Keep going: write the project file again whenever names or configs
                               change. Build with Rojo after each write, and again after an edit
                               inside a file under the source paths. Press Ctrl+C to stop; --json
                               prints one JSON object per line.
  
  EXIT CODES:
      0    done (warnings included)
      1    the project has a problem: an error, or Rojo failing
      2    the command line is wrong, or a terminal is needed and there is none
  
  EXAMPLES:
      rogen build -o game.rbxl
      rogen build places/lobby -o lobby.rbxl
      rogen build -p Tool.rbxm
      rogen build -o game.rbxl --watch
      rogen build -o game.rbxl --json

$ rogen help init
exit 0
stdout:
  rogen-init
  Writes a starting default.rogen.json, detecting the workspace and asking in a terminal. With a
  folder, starts a project there, as 'rojo init' does. It starts projects and never changes a config
  that exists: where one is, it fails and writes nothing. To change a config, edit the .rogen.json and
  run 'rogen check'.
  
  USAGE:
      rogen init [OPTIONS] [PATH]
  
  ARGS:
      <PATH>    The folder to start the project in, made when it is not there.
  
  OPTIONS:
          --[no-]agent-hook                Whether to add the hook that reports Rogen warnings to the
                                           coding agents found. Not added when not given.
          --[no-]agent-rules               Whether to add Rogen's rules for coding agents to the agent
                                           file. Added when not given.
          --color <COLOR>                  Whether to colour the output. [default: auto] [possible
                                           values: auto, always, never]
          --compiled-path <PATH>           With Darklua: the folder it writes into, and Rojo syncs
                                           from.
          --[no-]darklua                   Whether Darklua processes your code before Rojo syncs it.
                                           Found from a Darklua config when not given.
      -n, --dry-run                        Plan without writing: print the files and choices, then
                                           stop.
      -h, --help                           Print help.
          --json                           Print one JSON document instead of text.
          --kind <KIND>                    What a new project is, as Rojo's init names it: a place
                                           (the default), a model or a plugin. A model or a plugin
                                           starts with Rojo's template of that kind and no routes.
                                           [possible values: place, model, plugin]
          --language <ID>                  The language: luau or roblox-ts. Detected from the folder
                                           when not given. For roblox-ts in a folder with no code,
                                           package.json or tsconfig.json, init first runs 'npm create
                                           roblox-ts', which needs npm and the network.
      -y, --non-interactive                Write the defaults without asking. A run without a
                                           terminal, or under a coding agent or CI, does so anyway.
                                           --json implies it. A flag below answers its question either
                                           way.
          --package <PATH>                 A package folder to mount as it is; repeat for several, or
                                           none for no mounts. The installed ones when not given.
                                           (repeatable)
          --[no-]places                    Whether a new project is several places. Luau: the code
                                           they share in src/common, a first place in src/game, a
                                           game.rogen.json at the root for it, and editor settings for
                                           luau-lsp; more places by copying that file. roblox-ts: the
                                           code they share in projects/common and a first place in
                                           projects/game with its own default.rogen.json and
                                           tsconfig.json, more by copying that folder. One place when
                                           not given, or several where a projects folder exists for
                                           roblox-ts.
          --project-file <PROJECT_FILE>    What to do with a default.project.json already here: lift
                                           its tree, or start a new one. Lifting writes the tree into
                                           default.rogen.json, and is the default. [possible values:
                                           lift, new]
      -q, --quiet                          Only print errors.
          --route <ID>                     A route to start with; repeat for several, or none. The
                                           routes are server, client, shared, replicatedFirst,
                                           serverStorage and starterGui. The first three when not
                                           given. When a lifted project file mounts a folder of that
                                           name, the name stands for the route derived from it, which
                                           `Took the defaults` and `--json` write as mount:server.
                                           (repeatable)
          --[no-]sample                    Whether a new place starts with the Greeter sample. It is
                                           three hello-world scripts in src/Greeter, Rojo's Baseplate
                                           and lighting in place, which the tree mounts, and a README.
                                           Written when not given, in a folder with no code.
                                           --no-sample leaves src empty and writes no place.
          --skip-git                       Leave git out of a new project: write no .gitignore and run
                                           no git init. Otherwise a .gitignore is written where none
                                           is, and git init runs where no work tree holds the folder.
          --source-path <PATH>             A folder with your scripts, relative to here; repeat for
                                           several. src when not given, or where the code is.
                                           (repeatable)
          --unmatched <UNMATCHED>          Where files that match no route go: nowhere (the default)
                                           or into the shared route. Left out, each file is warned
                                           about, naming the routing folders to move it into; in the
                                           shared route it goes in as a "*" route. A lifted project
                                           file that mounted a whole source path keeps "*", which
                                           places what that node held. [possible values: leave,
                                           shared]
      -v, --verbose                        Print debug output; -vv, trace output. (repeatable)
      -V, --version                        Print the version.
  
  EXIT CODES:
      0    done (warnings included)
      1    the project has a problem: an error, or Rojo failing
      2    the command line is wrong, or a terminal is needed and there is none
  
  EXAMPLES:
      rogen init
      rogen init --non-interactive
      rogen init game

$ rogen help where
exit 0
stdout:
  rogen-where
  Prints where each file lands in the game, and why, with its warnings.
  
  USAGE:
      rogen where [OPTIONS] [PATH]...
  
  ARGS:
      <PATH>...    A file, a directory, a Studio instance path, or '-' for text on stdin. A directory
                   gives the files in it, and a file that doesn't exist yet is placed as if it did. A
                   :line or :line:col after a file is ignored.
                   - Instance: a path as Studio prints it (ServerScriptService.Inventory.Save:12)
                     gives the files behind it.
                   - '-': reads text on stdin and prints it with each Studio instance path
                     (Service.Feature.Name:12 or Script 'Service.Feature.Name', Line 12) written as
                     file:line; an instance that several files place stays as it is, and is listed on
                     stderr.
                   - Config: the default config of the nearest folder at or above the path; with none,
                     every .rogen.json at or above it whose source paths cover it. A .rogen.json, or a
                     config named as build reads it (game for game.rogen.json), lists every file of
                     that config.
                   - Several configs: each answer names its config file, and so does config in the
                     JSON.
                   - Skipped: a path Rogen leaves out gets a note on stderr, and is listed under
                     skipped in the JSON document.
                   - No path: every file of every config of the working directory. An instance or '-':
                     its default config.
  
  OPTIONS:
          --color <COLOR>    Whether to colour the output. [default: auto] [possible values: auto,
                             always, never]
      -h, --help             Print help.
          --json             Print one JSON document instead of text.
      -q, --quiet            Only print errors.
      -v, --verbose          Print debug output; -vv, trace output. (repeatable)
      -V, --version          Print the version.
  
  EXIT CODES:
      0    every path answered, one that no file places included
      1    the config has errors
      2    the command line is wrong, or a terminal is needed and there is none
  
  EXAMPLES:
      rogen where src/Inventory/Server/Save.luau
      rogen where ServerScriptService.Inventory.Save:12
      rogen where src --json
      pbpaste | rogen where -
